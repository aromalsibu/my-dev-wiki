    break & continue

    1. Overview

    Definition

    break and continue are jump statements that alter the normal flow of loops and switch statements. They are the primary tools for early termination and iteration skipping within repetitive code.

    // break — exits the loop immediately
for (let i = 0; i < 10; i++) {
    if (i === 3) break;
    console.log(i); // 0, 1, 2
}

// continue — skips to the next iteration
for (let i = 0; i < 10; i++) {
    if (i === 3) continue;
    console.log(i); // 0, 1, 2, 4, 5, 6, 7, 8, 9
}

    Both statements can optionally accept a label to target an outer loop or block:

    outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (j === 1) continue outer; // skip to next i
        if (i === 2) break outer;    // exit both loops
        console.log(i, j);
    }
}

    break terminates the current loop or switch statement and transfers control to the statement following it. continue terminates the current iteration and resumes the loop with the next iteration — in a while or do...while loop, it jumps back to the condition; in a for loop, it jumps to the update expression; in a for...in, for...of, or for await...of loop, it jumps to the next iteration.

    Purpose

    break and continue exist to solve the early exit problem: loops often need to stop before their natural termination condition, or skip processing for specific elements. Without these statements, every early exit would require a flag variable — a boolean that is checked on every iteration, cluttering the loop and slowing execution.

    // Without break — flag variable
let found = false;
for (const item of items) {
    if (!found) {
        if (item.id === targetId) {
            found = true;
            result = item;
        }
    }
}

// With break — direct and clear
for (const item of items) {
    if (item.id === targetId) {
        result = item;
        break;
    }
}

    They serve as the loop control layer of the language:

    • break — exit a loop or switch entirely.
    • continue — skip the rest of the current iteration.
    • Labels — target outer loops from nested ones.

    Where It Fits

    Control Flow
├── Conditionals          ✅ done
├── Loops                 ✅ done
├── break & continue      ← you are here
├── Labels
├── Exceptions
└── Error Handling

    break and continue sit directly after Loops because they only make sense inside loops — they are the tools that modify loop execution from within. The next concept, Labels, extends their power to nested loops.

    2. Why It Exists

    The Problem

    Loops execute until their condition fails. But real programs often need to stop early:

    • Found the item you were searching for — no need to continue.
    • Detected an error — abort the loop.
    • Encountered a null value — skip this iteration.
    • Reached a sufficient result — stop processing.

    Without break and continue, every early exit requires a flag variable that is tested on every iteration — verbose, error-prone, and slower because the loop continues running even after the useful work is done.

    Previous Limitations

    Era Limitation
    No break Loops could only exit via condition failure
    No continue Skipping required nested if blocks around the entire body
    No labels Nested loop exits required flag variables
    forEach limitation forEach cannot break or continue — a major gap

    Why break and continue Were Introduced

    break was part of the original JavaScript (1995). It solved the need for early loop termination and switch case termination. continue was also in the original language, providing a way to skip iterations without wrapping the body in conditionals.

    Labels were added to extend break and continue to nested loops — allowing a break inside an inner loop to exit an outer loop directly, without flag variables.

    Why forEach Cannot Break

    Array.prototype.forEach was introduced in ES5 as a functional iteration method. It calls a callback for each element — but the callback cannot break or continue the outer loop because it is a function, not a loop body. break and continue are loop statements, not function statements. This is a fundamental design limitation of forEach, and the primary reason for...of is preferred when early termination is needed.

    3. Syntax / Basic Usage

    break — Unlabeled

    break;

    Exits the innermost loop or switch statement.

    // In a for loop
for (let i = 0; i < 10; i++) {
    if (i === 3) break;
    console.log(i); // 0, 1, 2
}

// In a while loop
let i = 0;
while (i < 10) {
    if (i === 3) break;
    console.log(i); // 0, 1, 2
    i++;
}

// In a switch
switch (value) {
    case 1:
        console.log("one");
        break;
    case 2:
        console.log("two");
        break;
}

    break — Labeled

    break label;

    Exits the statement identified by label. The break statement must be nested within the labeled statement.

    outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (i === 1 && j === 1) break outer;
        console.log(i, j);
    }
}
// 0 0
// 0 1
// 0 2
// 1 0

    continue — Unlabeled

    continue;

    Skips the rest of the current iteration and proceeds to the next.

    for (let i = 0; i < 5; i++) {
    if (i === 2) continue;
    console.log(i); // 0, 1, 3, 4
}

    continue — Labeled

    continue label;

    Continues the loop identified by label. The continue statement must be nested within the labeled loop, and the label must refer to a looping statement (not a plain block).

    outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (j === 1) continue outer;
        console.log(i, j);
    }
}
// 0 0
// 1 0
// 2 0

    Labeled Blocks with break

    Labels can be attached to any statement, not just loops. break can exit a labeled block:

    outerBlock: {
    innerBlock: {
        console.log("1");
        break outerBlock; // exits both blocks
        console.log("never runs");
    }
    console.log("never runs");
}

    continue Cannot Target Blocks

    continue can only target looping statements. It cannot be used with a plain block label:

    block: {
    continue block; // ❌ SyntaxError
}

    Loop-Specific Behavior of continue

    The behavior of continue depends on the loop type:

    Loop continue Jumps To
    while The condition
    do...while The condition
    for The update expression
    for...in Next property key
    for...of Next value
    for await...of Next async value

    4. Mental Model

    The "Emergency Exit" Mental Model

    Think of break and continue as doors in a building:

    • break — the emergency exit. You leave the building immediately, abandoning whatever you were doing. No more iterations. No more code in the loop. You are outside.
    • continue — the skip button. You finish the current room and move directly to the next one. The building continues operating. You just didn't finish this particular room.
    Loop body:
┌─────────────────────────────────┐
│                                 │
│  [statement]                    │
│  [statement]                    │
│  ─── continue ───▶ next iteration
│                                 │
│  [statement]                    │
│  [statement]                    │
│  ─── break ───▶ exit loop       │
│                                 │
│  [statement]                    │
│                                 │
└─────────────────────────────────┘

    The "Flag Variable Replacement" Mental Model

    Before break and continue, loops used flag variables:

    Without break:                    With break:
┌─────────────────────┐          ┌─────────────────────┐
│ let found = false;  │          │ for (const x of xs) │
│ for (const x of xs) │          │   if (match(x)) {   │
│   if (!found) {     │          │     result = x;     │
│     if (match(x)) { │          │     break;          │
│       found = true; │          │   }                 │
│       result = x;   │          │ }                   │
│     }               │          │                     │
│   }                 │          │ Clean. Direct.      │
│ }                   │          │                     │
│                     │          │                     │
│ Every iteration     │          │ Exits immediately.  │
│ checks `!found`.    │          │                     │
└─────────────────────┘          └─────────────────────┘

    break and continue eliminate the flag variable — simpler code, faster execution.

    The "Nested Loop Problem" Mental Model

    In nested loops, unlabeled break and continue only affect the innermost loop:

    outer: for (i) {
    inner: for (j) {
        break;        → exits inner only
        continue;     → continues inner only
    }
}

    To affect an outer loop, you need a label:

    outer: for (i) {
    inner: for (j) {
        break outer;     → exits both
        continue outer;  → continues outer
    }
}

    Labels are the bridge between inner and outer loops.

    The "forEach Trap" Mental Model

    for...of:                          forEach:
┌─────────────────────┐           ┌─────────────────────┐
│ for (const x of xs)│           │ xs.forEach(x => {   │
│   if (skip(x))     │           │   if (skip(x)) {    │
│     continue;      │           │     // can't continue│
│   if (stop(x))     │           │   }                 │
│     break;         │           │   if (stop(x)) {    │
│   process(x);      │           │     // can't break  │
│ }                  │           │   }                 │
│                    │           │   process(x);       │
│ ✅ break/continue  │           │ });                 │
│                    │           │                     │
│                    │           │ ❌ No break/continue│
└─────────────────────┘           └─────────────────────┘

    This is why for...of is preferred when early termination is needed.

    5. Core Concepts

    Concept 1: break Terminates, continue Skips

    Statement Effect
    break Exits the loop or switch immediately
    continue Skips the rest of the current iteration; proceeds to the next

    Concept 2: Both Work in All Loop Types

    break and continue work in:

    • for
    • while
    • do...while
    • for...in
    • for...of
    • for await...of

    Concept 3: break Also Works in switch

    break is the standard way to prevent fall-through in switch cases:

    switch (x) {
    case 1:
        console.log("one");
        break; // prevents fall-through to case 2
    case 2:
        console.log("two");
        break;
}

    Concept 4: Labels Target Outer Statements

    A label is an identifier prefixed to a statement:

    label: statement;

    break label exits the labeled statement. continue label continues the labeled loop.

    Concept 5: Label Scope

    A label is available only within the labeled statement. It cannot be referenced from outside:

    outer: for (let i = 0; i < 3; i++) {
    // `outer` is available here
}
// `outer` is NOT available here

    Concept 6: continue Requires a Loop

    continue label requires the label to be attached to a looping statement:

    // ❌ SyntaxError — block is not a loop
block: {
    continue block;
}

// ✅ Valid — label is on a loop
loop: for (let i = 0; i < 3; i++) {
    continue loop;
}

    Concept 7: break Works with Any Labeled Statement

    break label can target any labeled statement — including blocks:

    outerBlock: {
    console.log("1");
    break outerBlock;
    console.log("never runs");
}

    Concept 8: Nested Labels

    A statement can have multiple labels:

    outer: inner: for (let i = 0; i < 3; i++) {
    break outer; // both labels are equivalent
}

    All labels on the same statement are functionally equivalent.

    Concept 9: break and continue Cannot Be Used at Top Level

    A break or continue statement — with or without a label — cannot be used at the top level of a script, module, function body, or static initialization block, even if the function is contained within a loop.

    // ❌ SyntaxError
break;

// ❌ SyntaxError
continue;

function f() {
    break; // ❌ SyntaxError
}

    Concept 10: forEach Cannot Use break or continue

    Array.prototype.forEach takes a callback function. break and continue are loop statements — they cannot appear inside a callback because the callback is not a loop body.

    [1, 2, 3].forEach(x => {
    if (x === 2) break; // ❌ SyntaxError
});

    Solution: Use for...of when early termination is needed.

    Concept 11: Iterator Protocol Cleanup

    When break exits a for...of loop early, JavaScript calls the iterator's return() method to perform cleanup — this is called IteratorClose. This is how generators clean up resources when a loop exits early.

    function* gen() {
    try {
        yield 1;
        yield 2;
        yield 3;
    } finally {
        console.log("cleanup");
    }
}

for (const x of gen()) {
    if (x === 2) break; // triggers finally → "cleanup"
}

    Concept 12: break in switch Inside a Loop

    When a switch is inside a loop, break inside the switch exits the switch, not the loop:

    for (const x of items) {
    switch (x) {
        case 1:
            console.log("one");
            break; // exits switch, not loop
        case 2:
            return; // exits function
    }
    // continues loop after switch
}

    To exit the loop from inside the switch, use a label:

    loop: for (const x of items) {
    switch (x) {
        case 1:
            break loop; // exits the loop
    }
}

    Concept 13: continue in switch Inside a Loop

    continue inside a switch inside a loop continues the loop — not the switch:

    for (const x of items) {
    switch (x) {
        case 1:
            continue; // skips to next loop iteration
    }
}

    Concept 14: Labels and break vs. continue Semantics

    outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (j === 1) continue outer; // skip to next i
        if (i === 2) break outer;    // exit outer loop
        console.log(i, j);
    }
}
    • continue outer — skips the rest of the inner loop and the rest of the current outer iteration, then proceeds to the next outer iteration.
    • break outer — exits the outer loop entirely.

    Concept 15: break and continue in try/finally

    break and continue inside a try block still execute the finally block:

    for (let i = 0; i < 5; i++) {
    try {
        if (i === 2) break;
        if (i === 1) continue;
        console.log(i);
    } finally {
        console.log("finally", i);
    }
}

    Output:

    0
finally 0
finally 1
finally 2

    Concept 16: ESLint Rules for break and continue

    Rule Purpose
    no-unsafe-finally Disallow break/continue in finally blocks
    no-unreachable Flag code after break/continue
    no-extra-label Flag unnecessary labels
    no-labels Disallow labels entirely
    no-continue Disallow continue
    no-restricted-syntax Restrict break/continue patterns

    The no-unsafe-finally rule is particularly important — using break or continue in a finally block overwrites control flow from try and catch, which is considered unexpected behavior.

    Concept 17: break and continue Are Performance-Neutral

    break and continue compile to conditional jumps in bytecode — the same primitive used by if and loop conditions. They do not add overhead; they remove overhead by exiting loops early.

    Concept 18: ES2026 and Loop Control

    ES2026 does not introduce new break or continue syntax. However, it adds features that reduce the need for manual loop control:

    • Array.fromAsync — collects async iterables without manual for await...of loops.
    • Iterator Helpers (ES2025) — .take(n) replaces break after n iterations.
    • Iterator.concat() — sequences iterators without nested loops.

    6. How It Works

    Step-by-Step: break Execution

    1.  `break` statement is encountered.
    │
    ▼
2.  If unlabeled:
    │   - Find the innermost enclosing loop or switch.
    │   - Exit that statement.
    │
    ▼
3.  If labeled:
    │   - Find the statement with the matching label.
    │   - Verify `break` is nested within it.
    │   - Exit that statement.
    │
    ▼
4.  If the loop is a for...of or for await...of:
    │   - Call iterator.return() for cleanup (IteratorClose).
    │
    ▼
5.  Resume execution after the terminated statement.

    Step-by-Step: continue Execution

    1.  `continue` statement is encountered.
    │
    ▼
2.  If unlabeled:
    │   - Find the innermost enclosing loop.
    │   - Skip to the next iteration.
    │
    ▼
3.  If labeled:
    │   - Find the loop with the matching label.
    │   - Verify `continue` is nested within it.
    │   - Skip to the next iteration of that loop.
    │
    ▼
4.  Jump target depends on loop type:
    │   - while / do...while → condition
    │   - for → update expression
    │   - for...in / for...of / for await...of → next iteration
    │
    ▼
5.  Continue executing the loop.

    Step-by-Step: Labeled break in Nested Loops

    1.  outer: for (i) { ... inner: for (j) { ... break outer; ... } }
    │
    ▼
2.  `break outer` is encountered inside inner loop.
    │
    ▼
3.  Engine searches for label `outer`.
    │
    ▼
4.  Finds `outer` attached to the outer for loop.
    │
    ▼
5.  Exits the outer loop entirely.
    │
    ▼
6.  Resumes after the outer loop.

    Step-by-Step: IteratorClose on break

    1.  for (const x of generator) { if (x === 2) break; }
    │
    ▼
2.  `break` exits the loop.
    │
    ▼
3.  Engine calls iterator.return().
    │
    ▼
4.  Generator's finally block executes.
    │
    ▼
5.  Resource cleanup completes.
    │
    ▼
6.  Execution resumes after the loop.

    7. Internal Architecture / Under the Hood

    Bytecode Compilation

    V8 compiles break and continue into unconditional jumps in Ignition bytecode:

    for loop:
  initialization
loop_start:
  condition
  jump-if-false → loop_end
  body
  if (condition) → jump loop_start  // continue
  jump loop_end                    // break
  update
  jump loop_start
loop_end:

    Both statements are single-jump instructions — they do not add runtime overhead.

    Completion Records

    In the ECMAScript spec, break and continue produce Completion Records:

    break → { [[Type]]: break, [[Target]]: label }
continue → { [[Type]]: continue, [[Target]]: label }

    These records propagate up through the loop's evaluation until the loop handles them.

    LoopContinues Abstract Operation

    The spec defines LoopContinues(completion, labelSet) — an abstract operation that determines whether a loop should continue based on a completion record. This is the mechanism behind break and continue in for...of and for await...of loops.

    IteratorClose on break

    When break exits a for...of loop, the spec's IteratorClose abstract operation is invoked. It calls the iterator's return() method if present, ensuring generators and other iterables clean up resources.

    Labels in the Parser

    Labels are resolved during parsing. The parser maintains a label set — a stack of active labels. When a break or continue with a label is encountered, the parser verifies:

    1. The label exists in the current scope.
    2. The label is attached to an appropriate statement (loop for continue, any statement for break).
    3. The break/continue is nested within the labeled statement.

    If any check fails, a syntax error is thrown.

    finally Interaction

    break and continue inside a try block trigger the finally block before completing:

    try {
    break;  // finally runs first, then break completes
} finally {
    cleanup();
}

    This is why ESLint's no-unsafe-finally rule warns against break/continue in finally — they overwrite pending control flow from try/catch.

    Performance in the JIT

    The JIT compilers (Sparkplug, Maglev, TurboFan) treat break and continue as branch instructions. They are optimized as part of the loop's control flow graph. There is no performance penalty for using them.

    8. Lifecycle / Workflow

    break Execution Lifecycle

    Encountered → Find target → Exit statement → (IteratorClose) → Resume after

    continue Execution Lifecycle

    Encountered → Find target loop → Skip to next iteration → Resume loop

    Labeled break Lifecycle

    Encountered → Resolve label → Verify nesting → Exit labeled statement → Resume after

    Development Workflow

    Write loop → Add break/continue → Lint (ESLint) → Run → Debug

    ESLint rules like no-unreachable and no-unsafe-finally catch common break/continue mistakes.

    Loop Control Decision Workflow

    Need to exit loop early?
    │
    ├── Yes → Use break
    │
    └── No → Need to skip current iteration?
              │
              ├── Yes → Use continue
              │
              └── No → Normal loop

    9. Practical Examples

    Example 1: Basic break

    const items = [1, 2, 3, 4, 5];
const target = 3;

for (const item of items) {
    if (item === target) {
        console.log("Found:", item);
        break;
    }
    console.log("Checking:", item);
}
// Checking: 1
// Checking: 2
// Found: 3

    Breakdown:

    • Loop exits as soon as item === 3.
    • Remaining elements (4, 5) are not processed.

    Example 2: Basic continue

    for (let i = 0; i < 10; i++) {
    if (i % 2 === 0) continue; // skip even numbers
    console.log(i); // 1, 3, 5, 7, 9
}

    Breakdown:

    • continue skips the rest of the iteration for even numbers.
    • Only odd numbers are printed.

    Example 3: break in switch

    switch (day) {
        case "sat":
        case "sun":
            return "weekend";
        case "mon":
        case "tue":
        case "wed":
        case "thu":
        case "fri":
            return "weekday";
        default:
            return "invalid";
    }
}

    Breakdown:

    • return exits the function — break is not needed.
    • In non-returning switch, break prevents fall-through.

    Example 4: Labeled break in Nested Loops

    for (let j = 0; j < 3; j++) {
        if (i === 1 && j === 1) break outer;
        console.log(i, j);
    }
}
// 0 0
// 0 1
// 0 2
// 1 0

    Breakdown:

    • break outer exits both loops.
    • Without the label, only the inner loop would exit.

    Example 5: Labeled continue in Nested Loops

    outer: for (let i = 0; i < 3; i++) {

        console.log(i, j);

}
// 0 0
// 1 0
// 2 0

    Breakdown:

    • continue outer skips to the next outer iteration.
    • The inner loop is abandoned for the current outer iteration.

    Example 6: break in a for...of with Iterator Cleanup

    function* gen() {
    try {
        yield 1;
        yield 2;
        yield 3;
    } finally {
        console.log("cleanup");
    }
}

for (const x of gen()) {
    if (x === 2) break;
    console.log(x); // 1
}
// cleanup (from finally)

    Breakdown:

    • break triggers IteratorClose, which runs the generator's finally block.
    • Resource cleanup is guaranteed.

    Example 7: break in switch Inside a Loop

    for (const x of [1, 2, 3]) {
    switch (x) {
        case 1:
            console.log("one");

        case 2:
            console.log("two");

    Breakdown:

    • break exits the switch, not the loop.
    • To exit the loop, use a label.

    Example 8: break in try/finally

    for (let i = 0; i < 5; i++) {
    try {
        if (i === 2) break;
        console.log("try", i);
    } finally {
        console.log("finally", i);
    }
}

    Output:

    try 0
finally 0
try 1
finally 1
finally 2

    Breakdown:

    • break triggers finally before exiting.
    • The finally block runs for iteration i = 2.

    Example 9: continue with for...of

    const users = [
    { name: "Ada", active: true },
    { name: "Grace", active: false },
    { name: "Alan", active: true },
];

for (const user of users) {
    if (!user.active) continue;

}
// Active: Ada
// Active: Alan

    Scenario Statement
    Stop searching after finding target break
    Exit loop on error break
    Skip invalid elements continue
    Exit nested loops break label
    Skip outer loop iteration continue label
    Prevent switch fall-through break
    Exit a labeled block break label
    Process only valid items continue
    Early return from search break + return

    11. Best Practices

    1. Use break for early termination. Why: eliminates flag variables and speeds up loops.
    2. Use continue to skip iterations. Why: flattens nested conditionals.
    3. Use labels sparingly. Why: labels can make code harder to follow; prefer extracting functions.
    4. Prefer for...of over forEach when you need break or continue. Why: forEach cannot break.
    5. Document intentional switch fall-through. Why: missing break is usually a bug.
    6. Always include break in switch cases unless fall-through is intentional. Why: prevents accidental fall-through.
    7. Never use break or continue in finally blocks. Why: overwrites control flow from try/catch (ESLint no-unsafe-finally).
    8. Use return instead of break when the loop is the last statement in a function. Why: simpler control flow.
    9. Keep labels close to their usage. Why: distant labels are hard to trace.
    10. Avoid deeply nested loops with labels. Why: consider extracting the inner loop into a function.
    11. Use break in switch inside loops carefully. Why: break exits the switch, not the loop — use a label to exit the loop.
    12. Use IteratorClose awareness with generators. Why: break triggers cleanup in for...of.
    13. Enable ESLint no-unreachable. Why: flags code after break/continue.
    14. Prefer some() or find() over loops with break. Why: more declarative and expressive.
    15. Test edge cases: first iteration, last iteration, no match. Why: break/continue bugs often hide at boundaries.

    12. Common Mistakes

    ❌ Mistake: Using break in forEach

    [1, 2, 3].forEach(x => {
    if (x === 2) break; // ❌ SyntaxError
});

    ✅ Correct:

    for (const x of [1, 2, 3]) {
    if (x === 2) break;
    console.log(x);
}

    ❌ Mistake: Forgetting break in switch

    switch (x) {
    case 1:
        console.log("one");
    case 2:
        console.log("two"); // runs for x === 1 too!
}

    ✅ Correct:

    switch (x) {
    case 1:
        console.log("one");
        break;
    case 2:
        console.log("two");
        break;
}

    ❌ Mistake: break in switch Inside a Loop

    for (const x of items) {
    switch (x) {
        case 1:
            break; // exits switch, not loop
    }
    // continues looping
}

    ✅ Correct:

    loop: for (const x of items) {
    switch (x) {
        case 1:
            break loop; // exits the loop
    }
}

    ❌ Mistake: continue Targeting a Block

    block: {
    continue block; // ❌ SyntaxError
}

    ✅ Correct: continue requires a loop label.

    ❌ Mistake: break at Top Level

    break; // ❌ SyntaxError

    ✅ Correct: break must be inside a loop or switch.

    ❌ Mistake: Unreachable Code After break

    for (let i = 0; i < 3; i++) {
    break;
    console.log(i); // unreachable
}

    ✅ Correct: Remove unreachable code.

    ❌ Mistake: break in finally

    try {
    // ...
} finally {
    break; // ❌ no-unsafe-finally
}

    ✅ Correct: Never use break/continue in finally.

    ❌ Mistake: Overusing Labels

    outer: for (...) {
    inner: for (...) {
        loop: for (...) {
            if (x) continue outer;
        }
    }
}

    ✅ Correct: Extract inner loops into functions.

    ❌ Mistake: Confusing break and continue

    for (let i = 0; i < 5; i++) {
    if (i === 2) break; // exits loop, not skip
    console.log(i); // 0, 1
}

    ✅ Correct: Use continue to skip, break to exit.

    ❌ Mistake: Assuming break Works in map/filter

    [1, 2, 3].map(x => {
    if (x === 2) break; // ❌ SyntaxError
    return x * 2;
});

    ✅ Correct: Use for...of when early exit is needed.

    13. Performance Considerations

    • break and continue are free — they compile to jumps with no runtime overhead.
    • Early exit saves work — break skips remaining iterations.
    • continue skips work — avoids processing unwanted elements.
    • Flag variables are slower — they require a check on every iteration.
    • Labeled break is as fast as unlabeled — resolved at parse time.
    • IteratorClose adds overhead — but only on early exit from for...of.
    • finally blocks add overhead — break inside try triggers finally before exiting.

    Performance Tips

    1. Use break to exit loops as soon as possible.
    2. Use continue to skip expensive processing for unwanted elements.
    3. Prefer for...of with break over forEach with flags.
    4. Avoid break inside try/finally in hot loops — the finally overhead adds up.
    5. Labels are free — do not avoid them for performance reasons.

    14. Security Considerations

    Infinite Loop Prevention

    break is the primary mechanism for exiting intentional infinite loops:

    while (true) {
    const input = getInput();
    if (input === "quit") break;
    process(input);
}

    Without break, this loop would run forever.

    Iterator Cleanup and Resource Leaks

    break from a for...of loop triggers IteratorClose, which calls the iterator's return() method. This prevents resource leaks in generators, file handles, and database connections.

    break in finally — Security Risk

    Using break or continue in a finally block can overwrite control flow from try and catch, leading to unexpected behavior that may have security implications. ESLint's no-unsafe-finally rule flags this.

    Loop Bound Enforcement

    break can enforce maximum iteration limits, preventing denial-of-service (DoS) via unbounded loops:

    let count = 0;
for (const item of untrustedInput) {
    if (++count > MAX_ITERATIONS) break;
    process(item);
}

    15. Debugging Tips

    • console.log before break/continue — verify when they trigger.
    • debugger; — pause inside the loop body.
    • ESLint no-unreachable — flags code after break/continue.
    • ESLint no-unsafe-finally — flags break/continue in finally.
    • ESLint no-extra-label — flags unnecessary labels.
    • Chrome DevTools Sources panel — set breakpoints on break/continue.
    • Loop iteration counter — add a counter to verify loop exits correctly.
    • Label verification — check that labels are attached to the correct statement.

    16. When to Use

    Statement When to Use
    break Exit loop early — found target, error, or sufficient result
    continue Skip current iteration — invalid item, filter condition
    break label Exit nested loops
    continue label Skip outer loop iteration
    break in switch Prevent fall-through
    break label in switch inside loop Exit the loop from the switch

    17. When Not to Use

    • forEach — cannot use break/continue; use for...of.
    • finally blocks — avoid break/continue; use no-unsafe-finally.
    • Top-level code — syntax error outside loops.
    • Simple transformations — use .map(), .filter(), .find() instead.
    • When some() or find() works — more declarative.
    • Labels when functions would be clearer — extract the inner loop.
    • Unnecessary break in switch with return — return is cleaner.

    • break and continue were in the original JavaScript (1995).
    • break works in switch — it is not limited to loops.
    • continue only works in loops — it cannot target a block.
    • Labels are the only "goto" in JavaScript — JavaScript has no goto statement.
    • break from a for...of loop triggers IteratorClose — generators clean up resources.
    • break in a finally block is flagged by ESLint — it overwrites control flow.
    • forEach cannot break — this is a fundamental limitation.
    • break inside a switch inside a loop exits the switch — not the loop.
    • Labels can be attached to any statement — not just loops.
    • Multiple labels on one statement are equivalent — outer: inner: for....
    • break and continue compile to jumps — no runtime overhead.
    • continue in a for loop jumps to the update expression — not the condition.
    • continue in a while loop jumps to the condition.
    • break and continue cannot be used at top level — syntax error.
    • LoopContinues is the spec abstract operation behind loop control.
    • ES2026 does not add new break/continue syntax — they remain as they were.
