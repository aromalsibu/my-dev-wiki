    Rest Parameters

    1. Overview

    Definition

    A rest parameter is a special parameter syntax that allows a function to accept an indefinite number of arguments and collect them into a real array. It is denoted by three dots (...) followed by an identifier, placed as the last parameter in a function's signature.

    function sum(...numbers) {
    return numbers.reduce((total, n) => total + n, 0);
}

sum(1, 2, 3);       // 6
sum(1, 2, 3, 4, 5); // 15

    The rest parameter collects all remaining arguments — those not already bound to named parameters — into a standard JavaScript Array. Unlike the legacy arguments object, the rest parameter is a true array instance, meaning all array methods (map, filter, reduce, sort, forEach, pop, etc.) can be applied directly to it without conversion.

    Rest parameters work identically in function declarations, function expressions, and arrow functions — they are fully supported across all function forms.

    Purpose

    Rest parameters exist to solve the variadic function problem: functions that need to accept an arbitrary number of arguments. Before ES2015, this required the arguments object — an array-like object that lacked array methods, was unavailable in arrow functions, and had confusing aliasing behavior in non-strict mode.

    Rest parameters serve as the modern variadic input mechanism of the language:

    • Variadic utilities — functions like sum, average, log, and format that accept any number of values.
    • Framework APIs — React hooks, Vue composition functions, and middleware that accept variable arguments.
    • Event aggregation — collecting callbacks, listeners, or handlers.
    • Argument forwarding — passing through arguments to other functions.

    2. Why It Exists

    The Problem

    JavaScript functions have no arity checking — you can call any function with any number of arguments. The language needed a way to capture those extra arguments in a useful form. Before ES2015, the only option was the arguments object.

    The arguments object had serious limitations:

    // ❌ arguments is not a real array
function sum() {
    return arguments.reduce((a, b) => a + b, 0); // TypeError!
}

// ❌ arguments is not available in arrow functions
const sum = () => arguments; // ReferenceError

// ❌ arguments aliases parameters in non-strict mode
function f(a) {
    arguments[0] = 99;
    console.log(a); // 99 — unexpected!
}

    The arguments object is an array-like object — it has a length property and indexed elements, but it does not have map, filter, reduce, forEach, or any other Array.prototype methods. To use array methods, you had to convert it:

    // The old way — verbose conversion
function sum() {
    const args = Array.prototype.slice.call(arguments);
    return args.reduce((a, b) => a + b, 0);
}

    Previous Limitations

    Era Limitation
    Pre-ES2015 No rest parameters — arguments was the only option
    arguments not an array Required Array.prototype.slice.call() conversion
    arguments unavailable in arrows Arrow functions could not capture variadic args
    arguments aliasing Non-strict functions had mapped arguments — confusing
    No destructuring Could not extract specific positions from variadic args
    Performance overhead Converting arguments to an array was costly

    Why Rest Parameters Were Introduced

    Rest parameters were introduced in ES2015 (ES6) as part of a broader language overhaul. They solved the arguments problem by:

    1. Creating a real array — all array methods work directly.
    2. Working in arrow functions — unlike arguments.
    3. Eliminating aliasing — the rest parameter is always a copy, never mapped to named parameters.
    4. Supporting destructuring — you can extract specific positions from the collected array.
    5. Improving performance — creating an array is faster than the arguments object machinery.

    The design was deliberately restrictive: only one rest parameter per function, it must be last, it cannot have a default value, and trailing commas are not allowed. These restrictions keep the syntax unambiguous and the semantics predictable.

    Why Rest Parameters Still Matter in 2026

    In 2026, rest parameters are Baseline Widely available — supported across all modern browsers since July 2015 (though implementation rolled out through 2016). They are the preferred modern approach for variadic functions, having replaced the arguments object in virtually all new code.

    ES2026 does not introduce new rest parameter syntax — the feature set is mature. However, the ES2026 spec continues to define rest parameters in Section 15.1 (Parameter Lists), specifically through the IsSimpleParameterList and ExpectedArgumentCount static semantics.

    3. Syntax / Basic Usage

    Basic Syntax

    function name(param0, ...restParam) {
    // restParam is an array of remaining arguments
}

    The rest parameter is three dots followed by an identifier, placed as the last parameter in the signature.

    Minimal Rest Parameter

    function collect(...items) {
    return items;
}

collect();           // []
collect(1);          // [1]
collect(1, 2, 3);    // [1, 2, 3]

    Rest with Leading Named Parameters

    function log(level, ...messages) {
    console.log(`[${level}]`, ...messages);
}

log("INFO", "Server started", "Port 3000");
// [INFO] Server started Port 3000

    The first argument binds to level; all remaining arguments bind to messages.

    Rest in Arrow Functions

    const sum = (...numbers) => numbers.reduce((a, b) => a + b, 0);
const log = (level, ...messages) => console.log(level, ...messages);

    Rest parameters work identically in arrow functions — no arguments workaround needed.

    Rest in Function Expressions

    const multiply = function(factor, ...values) {
    return values.map(v => v * factor);
};

multiply(2, 1, 2, 3); // [2, 4, 6]

    Rest with No Arguments

    function empty(...args) {
    return args.length;
}

empty(); // 0

    The rest parameter is an empty array when no arguments are provided — never undefined.

    Destructured Rest Parameters

    function firstTwo(...[first, second]) {
    return { first, second };
}

firstTwo(1, 2, 3); // { first: 1, second: 2 }
firstTwo(1);       // { first: 1, second: undefined }

    Rest parameters can be destructured to extract specific positions from the collected array.

    Rest with Spread (Forwarding)

    function forward(...args) {
    return otherFunction(...args); // spread back out
}

    Rest and spread are complementary — rest collects, spread distributes.

    Async Function with Rest

    async function fetchAll(...urls) {
    const responses = await Promise.all(urls.map(url => fetch(url)));
    return responses;
}

    Generator Function with Rest

    function* yieldAll(...values) {
    yield* values;
}

    Syntax Restrictions

    // ❌ Rest parameter must be last
function bad(...rest, last) {}

// ❌ Only one rest parameter allowed
function bad(...a, ...b) {}

// ❌ No trailing comma after rest
function bad(...rest,) {}

// ❌ Rest parameter cannot have a default value
function bad(...rest = []) {}

    4. Mental Model

    The "Collector" Mental Model

    Think of a rest parameter as a collector — it gathers all remaining arguments into a container:

    Function call: sum(1, 2, 3, 4, 5)
                       │
                       ▼
              ┌─────────────────┐
              │  ...numbers     │
              │                 │
              │  [1, 2, 3, 4, 5]│  ← Real array
              └─────────────────┘

    The rest parameter is the destination for arguments that do not have a named parameter.

    The "Rest vs. Spread" Mental Model

    Rest and spread use the same syntax (...) but do opposite things:

    Rest (collect):                     Spread (distribute):
┌─────────────────────┐            ┌─────────────────────┐
│  ...args            │            │  ...arr             │
│                     │            │                     │
│  Gathers multiple   │            │  Spreads one        │
│  values into ONE    │            │  collection into    │
│  array              │            │  MULTIPLE values    │
│                     │            │                     │
│  Function params    │            │  Function calls,    │
│                     │            │  array literals,    │
│                     │            │  object literals    │
└─────────────────────┘            └─────────────────────┘

    Rest is about receiving; spread is about sending.

    The "Arguments Object vs. Rest Parameter" Mental Model

    ┌─────────────────────────────────────────────────────┐
│              arguments Object                        │
│                                                     │
│  ┌─────────────────────┐  ┌─────────────────────┐  │
│  │ Array-like          │  │ Real Array          │  │
│  │                     │  │                     │  │
│  │ • Has length        │  │ • Has length        │  │
│  │ • Has indices       │  │ • Has indices       │  │
│  │ • ❌ No map/filter  │  │ • ✅ All array       │  │
│  │ • ❌ No forEach     │  │   methods           │  │
│  │ • ❌ Not in arrows  │  │ • ✅ In arrows      │  │
│  │ • ⚠️ Aliases in    │  │ • ✅ Never aliased  │  │
│  │   non-strict mode   │  │                     │  │
│  └─────────────────────┘  └─────────────────────┘  │
└─────────────────────────────────────────────────────┘

    The "Last Parameter Rule" Mental Model

    The rest parameter must be last because it collects everything that remains:

    function f(a, b, ...rest) {}

Call: f(1, 2, 3, 4, 5)

     a = 1
     b = 2
     rest = [3, 4, 5]  ← everything after a and b

    There is no room for another parameter after rest — it has consumed all remaining arguments.

    5. Core Concepts

    Concept 1: Rest Parameters Are Real Arrays

    Unlike the arguments object, rest parameters are true Array instances. All array methods work directly:

    function sortAndSum(...numbers) {
    return numbers.sort((a, b) => a - b).reduce((a, b) => a + b, 0);
}

    This eliminates the need for Array.prototype.slice.call(arguments) conversions.

    Concept 2: Rest Parameter Must Be Last

    function f(...rest, last) {} // ❌ SyntaxError

    The rest parameter collects remaining arguments — it cannot be followed by another parameter.

    Concept 3: Only One Rest Parameter Per Function

    function f(...a, ...b) {} // ❌ SyntaxError

    There can be only one rest parameter per function signature.

    Concept 4: No Trailing Comma After Rest

    function f(...rest,) {} // ❌ SyntaxError

    The rest parameter cannot be followed by a trailing comma.

    Concept 5: Rest Parameters Cannot Have Default Values

    function f(...rest = []) {} // ❌ SyntaxError

    Rest parameters cannot have default values. They are always arrays (empty if no arguments).

    Concept 6: Rest Parameters Work in Arrow Functions

    const sum = (...numbers) => numbers.reduce((a, b) => a + b, 0);

    Unlike arguments, rest parameters are fully available in arrow functions.

    Concept 7: Rest Parameters Can Be Destructured

    function f(...[a, b, c]) {
    return a + b + c;
}

f(1, 2, 3); // 6
f(1, 2, 3, 4); // 6 — fourth argument ignored
f(1); // NaN — b and c are undefined

    Destructuring allows extracting specific positions from the collected array.

    Concept 8: Rest Parameters and Function length

    The length property of a function does not count the rest parameter:

    function f(a, b, ...rest) {}
console.log(f.length); // 2 — rest is not counted

    This is defined by the spec's ExpectedArgumentCount static semantics.

    Concept 9: Rest Parameters and arguments

    When a function has a rest parameter, the arguments object is not mapped to the parameters:

    function f(a, ...rest) {
    arguments[0] = 99;
    console.log(a); // unchanged — arguments is unmapped
}

    Per ES2026 §10.2.11 / §10.4.4.6 / §10.4.4.7, functions with rest parameters create unmapped arguments objects.

    Concept 10: Rest Parameters Are Not Counted in Function.length

    function f(a, b, c, ...rest) {}
f.length; // 3

    Only parameters before the rest parameter are counted.

    Concept 11: Rest Parameters Replace arguments for Variadic Functions

    // Old way
function sum() {
    return Array.prototype.slice.call(arguments)
        .reduce((a, b) => a + b, 0);
}

// Modern way
function sum(...numbers) {
    return numbers.reduce((a, b) => a + b, 0);
}

    ESLint's prefer-rest-params rule enforces this preference.

    Concept 12: Rest Parameters and Spread Are Complementary

    function forward(...args) {
    return target(...args);
}

    Rest collects arguments into an array; spread distributes them back out.

    Concept 13: Rest Parameters in Class Methods

    class Calculator {
    add(...numbers) {
        return numbers.reduce((a, b) => a + b, 0);
    }
}

    Rest parameters work in class methods, including constructors.

    Concept 14: Rest Parameters in Object Methods

    const obj = {
    sum(...numbers) {
        return numbers.reduce((a, b) => a + b, 0);
    },
};

    Concept 15: ES2026 Spec — IsSimpleParameterList

    Per ES2026 §15.1.3, a parameter list is simple if it contains only simple identifiers. A parameter list with a rest parameter is not simple. This distinction affects:

    • Whether the arguments object is mapped or unmapped.
    • Whether "use strict" can be applied inside the function.

    Concept 16: Performance — Rest Parameters Are Faster Than arguments

    Benchmarks show that using ...args is significantly faster than Array.prototype.slice.call(arguments). One test showed:

    Running this under node took ~480ms for the old arguments version and about ~110ms for the new ...args version. Running with --trace-gc produced 1010 vs 95 reported scavenges.

    The performance difference comes from V8's ability to avoid allocating the arguments object when rest parameters are used.

    Concept 17: ESLint Rules for Rest Parameters

    Rule Purpose
    prefer-rest-params Prefer rest over arguments
    no-useless-rename Disallow redundant renaming in destructuring

    Concept 18: Rest Parameters in Modern Frameworks

    // React hook
function useLogger(...messages) {
    useEffect(() => console.log(...messages), messages);
}

// Express middleware
app.use((req, res, ...next) => { /* ... */ });

    Rest parameters are widely used in React, Vue, Express, and most modern npm packages.

    6. How It Works

    Step-by-Step: Rest Parameter Binding

    1.  Function is called with arguments.
    │
    ▼
2.  New execution context is created.
    │
    ▼
3.  Named parameters before the rest are bound first.
    │
    ▼
4.  All remaining arguments are collected into a new Array.
    │
    ▼
5.  The rest parameter is bound to that array.
    │
    ▼
6.  Function body executes.

    Step-by-Step: Rest Parameter with Destructuring

    1.  Function is called with arguments.
    │
    ▼
2.  All arguments are collected into an array.
    │
    ▼
3.  Destructuring pattern is applied to the array.
    │
    ▼
4.  Each extracted value is bound to a local variable.
    │
    ▼
5.  Remaining values are discarded (if not captured).

    Step-by-Step: Rest vs. arguments

    Rest:                                arguments:
1.  Function called.                 1.  Function called.
2.  Remaining args → new Array.      2.  arguments object created.
3.  Array has all methods.           3.  Array-like, no array methods.
4.  Available in arrows.             4.  Not available in arrows.
5.  Never mapped.                    5.  Mapped in non-strict simple lists.

    Step-by-Step: Performance Optimization in V8

    1.  Function with rest parameter is called.
    │
    ▼
2.  V8 checks if the rest array is actually needed.
    │
    ▼
3.  If the function just forwards to another function (spread),
    │   V8 can avoid allocating the array entirely.
    │
    ▼
4.  The JSCallForwardVarargs operator passes parameters directly.
    │
    ▼
5.  No allocation, no deconstruction — maximum performance.

    V8's TurboFan compiler includes an optimization to avoid allocating rest parameters when they are immediately spread into another call. This is implemented via the JSCallForwardVarargs operator.

    7. Internal Architecture / Under the Hood

    The Spec's Treatment of Rest Parameters

    The ECMAScript specification covers rest parameters in Section 15.1 (Parameter Lists). Key subclauses:

    Clause Title
    15.1.1 Static Semantics: Early Errors
    15.1.2 Static Semantics: ContainsExpression
    15.1.3 Static Semantics: IsSimpleParameterList
    15.1.4 Static Semantics: HasInitializer
    15.1.5 Static Semantics: ExpectedArgumentCount
    15.1.6 Runtime Semantics: IteratorBindingInitialization

    IsSimpleParameterList (ES2026 §15.1.3)

    A parameter list is simple if it contains only simple identifiers. It is not simple if it contains:

    • Default parameters
    • Rest parameters
    • Destructured parameters

    Functions with non-simple parameter lists create unmapped arguments objects.

    ExpectedArgumentCount (ES2026 §15.1.5)

    This static semantic determines the function's length property — the number of parameters before the first default or rest parameter.

    function f(a, b, c = 1, ...rest) {}
f.length; // 2 — a and b

    Mapped vs. Unmapped arguments (ES2026 §10.2.11 / §10.4.4.6 / §10.4.4.7)

    • Mapped — arguments[i] and parameter i are aliases. Only in non-strict functions with simple parameter lists.
    • Unmapped — arguments[i] is a copy. Functions with rest parameters create unmapped objects.

    IteratorBindingInitialization

    For destructured rest parameters, the engine uses IteratorBindingInitialization — an abstract operation that iterates over the pattern and binds each extracted value.

    Memory Layout

    Function Execution Context:
┌─────────────────────────────────────┐
│  Parameter Environment              │
│                                     │
│  a: 1         ← named parameter     │
│  b: 2         ← named parameter     │
│  rest: [3, 4, 5]  ← real Array      │
│                                     │
│  arguments: [1, 2, 3, 4, 5]         │
│    (unmapped — because of rest)     │
└─────────────────────────────────────┘

    V8 Optimization: JSCallForwardVarargs

    V8's TurboFan compiler has a special optimization for the pattern:

    function forward(...args) {
    return target(...args);
}

    Instead of allocating an array for args and then spreading it back out, V8 uses the JSCallForwardVarargs operator to pass the incoming parameters directly. This avoids both allocation and deconstruction.

    Performance in the JIT

    • Rest parameter binding — allocates a new array; fast but not free.
    • Forwarding optimization — V8 can eliminate the allocation entirely for spread calls.
    • Rest is faster than arguments — benchmarks show ~4x improvement and 10x fewer GC scavenges.

    11. Best Practices

    1. Prefer rest parameters over arguments. Why: real arrays, arrow function compatible, faster.
    2. Place the rest parameter last. Why: it collects all remaining arguments — required by syntax.
    3. Use destructuring with rest for specific positions. Why: cleaner than index access.
    4. Name rest parameters meaningfully. Why: numbers beats args when the type is known.
    5. Use rest parameters for variadic utilities. Why: natural fit for functions with unknown arity.
    6. Use spread to forward rest parameters. Why: rest and spread are complementary.
    7. Enable ESLint prefer-rest-params. Why: enforces rest over arguments.
    8. Avoid arguments in new code. Why: legacy, limited, and slower.
    9. Keep rest parameters as the only variadic mechanism. Why: consistency and readability.
    10. Use TypeScript's ...args: T[] for type safety. Why: ensures type correctness.
    11. Do not use rest parameters for fixed-arity functions. Why: named parameters are clearer.
    12. Understand Function.length behavior. Why: rest parameters are not counted.
    13. Use rest with async functions for batch operations. Why: Promise.all + rest is a powerful pattern.
    14. Consider performance in hot paths. Why: rest parameter allocation is fast but not free.
    15. Document variadic functions clearly. Why: callers need to know the expected argument shape.

    12. Common Mistakes

    ❌ Mistake: Rest Parameter Not Last

    function f(...rest, last) {} // ❌ SyntaxError

    ✅ Correct:

    function f(first, ...rest) {}

    ❌ Mistake: Multiple Rest Parameters

    function f(...a, ...b) {} // ❌ SyntaxError

    ✅ Correct: Only one rest parameter.

    ❌ Mistake: Trailing Comma After Rest

    function f(...rest,) {} // ❌ SyntaxError

    ✅ Correct:

    function f(...rest) {}

    ❌ Mistake: Default Value on Rest Parameter

    function f(...rest = []) {} // ❌ SyntaxError

    ✅ Correct:

    function f(...rest) {} // rest is always an array

    ❌ Mistake: Using arguments Instead of Rest

    function sum() {
    return arguments.reduce((a, b) => a + b, 0); // ❌ TypeError
}

    ✅ Correct:

    function sum(...numbers) {
    return numbers.reduce((a, b) => a + b, 0);
}

    ❌ Mistake: Expecting arguments to Be Mapped with Rest

    function f(a, ...rest) {
    arguments[0] = 99;
    console.log(a); // unchanged — unmapped
}

    ✅ Correct: Understand that rest parameters create unmapped arguments.

    ❌ Mistake: Using Rest for Fixed-Arity Functions

    function add(...numbers) { // ❌ less clear than (a, b)

}

    ✅ Correct:

    function add(a, b) {
    return a + b;
}

    ❌ Mistake: Forgetting Rest Is an Array

    function f(...rest) {

    // return rest.length; // ✅ also correct
}

    ❌ Mistake: Using ... in Object Setters

    const obj = {
    set value(...args) {} // ❌ SyntaxError — rest not allowed in setters
};

    ✅ Correct: Use a regular method instead.

    ❌ Mistake: Assuming Rest Works Everywhere

    // ❌ Rest parameters cannot be used in object literal setters

    set x(...args) {}
};

    ✅ Correct: Use rest in functions, methods, and constructors — not in setters.

    13. Performance Considerations

    • Rest parameter allocation — creates a new array; fast but not free.
    • Forwarding optimization — V8 can eliminate allocation for spread-forwarding patterns.
    • Rest is faster than arguments — ~4x improvement and ~10x fewer GC scavenges in benchmarks.
    • Rest in hot loops — avoid creating variadic functions in loops.
    • Destructured rest — additional destructuring cost; minor.
    • Function.length — rest parameters are not counted; no performance impact.

    Performance Tips

    1. Use rest parameters instead of arguments — faster and cleaner.
    2. Use spread-forwarding patterns — V8 optimizes them.
    3. Avoid creating variadic functions in hot loops.
    4. Profile with --trace-opt / --trace-deopt if needed.

    14. Security Considerations

    Rest Parameters and arguments Obfuscation

    Rest parameters are an ordinary binding ... Do rest parameters and spread at call sites survive protection? Yes. Rest parameters still produced real arrays, spread at the call site still delivered the right values including a mixed spread of two arrays, and spreading a string or a Set into a call was unchanged.

    Rest parameters are not affected by obfuscation — they behave consistently in minified and obfuscated code.

    Prototype Pollution via Rest

    Rest parameters create plain arrays — they do not carry prototype pollution risk beyond what normal array operations introduce.

    Function Constructor and Rest Parameters

    The value must correspond to a valid JavaScript parameter (any of plain identifier, rest parameter, or destructured parameter, optionally with a default), or a list of such strings separated with commas.

    The Function constructor accepts rest parameters — but like all Function constructor usage, it is an injection sink and should never be used with untrusted input.

    Rest Parameters in CSP Contexts

    Rest parameters are compatible with strict Content Security Policy — they do not require eval or new Function.

    Argument Exhaustion

    A rest parameter can collect an unbounded number of arguments — a potential denial-of-service vector if input size is not limited.

    Defense: Limit input size at trust boundaries.

    • f.length — verify parameter count (rest not counted).

    Scenario Use Rest Parameter?
    Variadic utilities (sum, average, log) ✅ Yes
    Argument forwarding ✅ Yes
    Event emitter emit ✅ Yes
    React hooks ✅ Yes
    Express middleware ✅ Yes
    Batch async operations ✅ Yes
    Collecting callbacks ✅ Yes
    Fixed-arity functions ❌ No
    Configuration objects ⚠️ Prefer destructured parameters

    17. When Not to Use

    • Fixed-arity functions — named parameters are clearer.
    • Configuration objects — use destructured parameters.
    • Object literal setters — rest is not allowed.
    • When arguments is needed for all arguments — rare; use arguments (legacy).
    • In performance-critical loops — rest allocates an array per call.
    • When the function arity is known — named parameters document intent.

    19. Did You Know?

    • Rest parameters were introduced in ES2015 (ES6) — part of the same release as let/const, classes, and promises.
    • They are Baseline Widely available — supported across all browsers since July 2015.
    • Rest parameters are real arrays — unlike the arguments object.
    • They work in arrow functions — arguments does not.
    • Only one rest parameter per function — and it must be last.
    • Rest parameters cannot have defaults — they are always arrays.
    • Destructured rest parameters allow extracting specific positions.
    • Function.length does not count rest parameters — only parameters before the first default or rest.
    • V8 optimizes spread-forwarding patterns — no allocation when ...args is immediately spread.
    • Rest is ~4x faster than arguments — benchmarks show 480ms vs 110ms and 10x fewer GC scavenges.
    • ES2026 §15.1 defines rest parameters through IsSimpleParameterList and ExpectedArgumentCount.
    • Rest parameters create unmapped arguments — per ES2026 §10.2.11.
    • Rest parameters survive obfuscation — they still produce real arrays.
    • React hooks use rest parameters extensively — useEffect, useCallback, and custom hooks.

    20. Summary

    • A rest parameter (...args) collects remaining arguments into a real array.
    • It must be the last parameter and there can be only one per function.
    • No trailing comma, no default value — syntax restrictions.
    • Real array — all array methods work directly.
    • Works in arrow functions — unlike arguments.
    • Never mapped — unlike arguments in non-strict simple lists.
    • Destructurable — extract specific positions from the collected array.
    • Not counted in Function.length — ExpectedArgumentCount excludes it.
    • Faster than arguments — ~4x improvement in benchmarks.
    • V8 optimizes spread-forwarding — no allocation when immediately spread.
    • Replaces arguments in modern code — ESLint prefer-rest-params.
    • ES2026 §15.1 defines the spec behavior.
    • Use for variadic functions — sum, log, forward, emit.
    • Do not use for fixed arity — named parameters are clearer.
    • Rest parameters are the modern variadic input mechanism for JavaScript.
