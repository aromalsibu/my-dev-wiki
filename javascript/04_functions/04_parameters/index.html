    Parameters

    1. Overview

    Definition

    A parameter is a named variable declared in a function's definition that receives a value when the function is called. Parameters are the inputs to a function — the mechanism by which data flows from the caller into the function body. They are listed inside the parentheses of the function signature, separated by commas.

    function greet(name, greeting) {
    return `${greeting}, ${name}!`;
}

greet("Ada", "Hello"); // "Hello, Ada!"

    In JavaScript, parameters behave as local variables within the function body. All the usual variable rules apply: they are scoped to the function, they can be reassigned (unless declared in a context that forbids it), and they shadow outer variables with the same name.

    JavaScript provides three special parameter syntaxes beyond simple named parameters:

    // 1. Default parameters — fallback values
function greet(name = "world") { /* ... */ }

// 2. Rest parameters — collect remaining arguments into an array
function sum(...numbers) { /* ... */ }

// 3. Destructured parameters — extract values from objects/arrays
function createUser({ name, age }) { /* ... */ }

    Purpose

    Parameters exist to solve the data input problem: a function without parameters is a closed box that always does the same thing. Parameters make functions reusable and configurable — the same logic can operate on different data each time it is called.

    Parameters serve as the interface layer between a function and its callers:

    • Simple parameters — named inputs for straightforward functions.
    • Default parameters — optional inputs with fallback values.
    • Rest parameters — variadic inputs collected into an array.
    • Destructured parameters — structured inputs extracted from objects or arrays.

    Where It Fits

    Functions
├── Function Declarations       ✅ done
├── Function Expressions        ✅ done
├── Arrow Functions             ✅ done
├── Parameters                  ← you are here
├── Rest Parameters
├── Default Parameters
├── Closures
├── Higher-Order Functions
└── Pure Functions

    Parameters sit after Arrow Functions because all function forms share the same parameter syntax. Arrow functions support every parameter feature that regular functions do — with one restriction: parentheses are always required when using default, rest, or destructured parameters. The next concept, Rest Parameters, dives deep into the ... syntax.

    2. Why It Exists

    The Problem

    A function that cannot receive input must either:

    • Hardcode its values — making it useless for general use.
    • Reach outside its scope to access global variables — creating hidden dependencies and brittle code.
    // ❌ Hardcoded — always calculates the same thing
function calculateBill() {
    const total = 100 * 1.15; // hardcoded bill and tax rate
    return total;
}

// ❌ Reaches outside — depends on global variables
let bill = 100;
const taxRate = 0.15;
function calculateBill() {
    return bill * (1 + taxRate); // reads global state
}

    Parameters solve both problems by making the function's inputs explicit:

    // ✅ Parameters — explicit inputs, reusable
function calculateBill(billAmount, taxRate) {
    return billAmount * (1 + taxRate);
}

calculateBill(100, 0.15); // 115
calculateBill(200, 0.08); // 216

    The function now declares what it needs. Callers provide the data. The function is self-contained and testable.

    Previous Limitations

    Era Limitation
    Pre-ES2015 No default parameter values — required manual || checks
    No rest parameters Variadic functions required the arguments object
    No destructured parameters Extracting object properties required manual assignment
    arguments object limitations Not a real array; unavailable in arrow functions
    No parameter documentation Function signatures did not reveal optional parameters

    Why Special Parameter Syntaxes Were Introduced

    ES2015 (ES6) introduced three major parameter features:

    1. Default parameters — initialize parameters with fallback values when no argument or undefined is provided.
    2. Rest parameters — collect an indefinite number of arguments into a real array.
    3. Destructured parameters — extract values from objects and arrays directly in the parameter list.

    These features replaced the older workarounds:

    Old Workaround Modern Replacement
    param = param || default param = default
    arguments object ...rest parameter
    Manual property extraction { prop } destructuring

    Why Parameters Still Matter in 2026

    In 2026, parameter syntaxes are Baseline Widely available — supported across all modern browsers since 2016. ES2026 does not introduce new parameter syntax; the feature set is mature. However, the ES2026 spec clarifies the behavior of mapped arguments objects in non-strict mode: the binding exists only in non-strict functions with simple parameter lists, and the mapping behavior is controlled by the parameter-list shape.

    3. Syntax / Basic Usage

    Simple Parameters

    function add(a, b) {
    return a + b;
}

add(2, 3); // 5

    Simple parameters are named identifiers. They are the default form and require no special syntax.

    Default Parameters

    function greet(name = "world") {
    return `Hello, ${name}!`;
}

greet();            // "Hello, world!" — no argument provided
greet("Ada");       // "Hello, Ada!" — argument provided
greet(undefined);   // "Hello, world!" — undefined triggers default
greet(null);        // "Hello, null!" — null does NOT trigger default

    Default parameters are applied in exactly two situations: no parameter provided, or undefined explicitly provided. Passing null does not trigger the default.

    Default values can be any expression, including function calls:

    function createId(prefix = "user", timestamp = Date.now()) {
    return `${prefix}_${timestamp}`;
}

    Default parameters can reference earlier parameters:

    function createRange(start, end = start + 10) {
    return [start, end];
}

createRange(5);    // [5, 15]
createRange(5, 20); // [5, 20]

    Rest Parameters

    function sum(...numbers) {
    return numbers.reduce((total, n) => total + n, 0);
}

sum(1, 2, 3);       // 6
sum(1, 2, 3, 4, 5); // 15

    The rest parameter must be the last parameter and there can be only one per function. Trailing commas after the rest parameter are not allowed.

    Rest parameters work with leading named parameters:

    function log(level, ...messages) {
    console.log(`[${level}]`, ...messages);
}

log("INFO", "Server started", "Port 3000");
// [INFO] Server started Port 3000

    Rest parameters can be destructured:

    function ignoreFirst(...[, b, c]) {
    return b + c;
}

ignoreFirst(1, 2, 3); // 5

    Destructured Parameters

    Object destructuring:

    function createUser({ name, age, role = "viewer" }) {
    return { name, age, role };
}

createUser({ name: "Ada", age: 36 }); // { name: "Ada", age: 36, role: "viewer" }

    Array destructuring:

    function getFirstThree([first, second, third]) {
    return [first, second, third];
}

getFirstThree([1, 2, 3, 4, 5]); // [1, 2, 3]

    Renaming destructured properties:

    function display({ name: userName, age: userAge }) {
    return `${userName} is ${userAge}`;
}

display({ name: "Ada", age: 36 }); // "Ada is 36"

    Nested destructuring:

    function processOrder({ customer: { name }, items: [first, ...rest] }) {
    return { name, firstItem: first, otherCount: rest.length };
}

    Default Values with Destructuring

    function createConfig({ debug = false, timeout = 5000, retries = 3 } = {}) {
    return { debug, timeout, retries };
}

createConfig();                  // { debug: false, timeout: 5000, retries: 3 }
createConfig({ debug: true });  // { debug: true, timeout: 5000, retries: 3 }

    The = {} default is essential when destructuring — without it, calling the function with no arguments throws a TypeError because it tries to destructure undefined.

    arguments Object (Legacy)

    function legacy() {
    console.log(arguments); // [1, 2, 3] — array-like, not a real array
}

legacy(1, 2, 3);

    The arguments object is not a real array and is not available in arrow functions. Use rest parameters instead.

    Parameter length Property

    function f(a, b, c = 1, ...rest) {}
console.log(f.length); // 2 — parameters before the first default or rest

    The length property counts parameters before the first default or rest parameter.

│                                         │

│                  │      │               │

└─────────────────────────────────────────┘

    Parameters are the blanks; arguments are what you write in them.

    5. Core Concepts

    Concept 1: Parameters Are Local Bindings

    Parameters behave as local variables in the function body. They are scoped to the function and shadow any outer variables with the same name.

    const name = "outer";

function greet(name) {
    return `Hello, ${name}`; // shadows outer `name`
}

greet("Ada"); // "Hello, Ada"

    Concept 2: Arguments Are Passed by Value

    JavaScript always passes arguments by value — but for objects, the "value" is a reference to the object.

    function modify(obj) {
    obj.name = "changed"; // mutates the object
}

function reassign(obj) {
    obj = { name: "new" }; // reassigns local binding — no effect outside
}

const user = { name: "Ada" };
modify(user);    // user.name is now "changed"
reassign(user);  // user is still the same object

    Concept 3: Missing Arguments Are undefined

    JavaScript does no parameter checking. Missing arguments are undefined.

    function add(a, b) {
    return a + b;
}

add(1); // NaN — b is undefined

    Concept 4: Extra Arguments Are Ignored (Unless Rest)

    Extra arguments are ignored unless captured by a rest parameter or the arguments object.

    function f(a) { return a; }
f(1, 2, 3); // 1 — extra arguments ignored

    Concept 5: Default Parameters (ES2015)

    function greet(name = "world") { /* ... */ }

    Default parameters provide fallback values when no argument or undefined is passed.

    Concept 6: Rest Parameters (ES2015)

    function sum(...numbers) { /* ... */ }

    Rest parameters collect remaining arguments into a real array. They must be last and only one per function.

    Concept 7: Destructured Parameters (ES2015)

    function createUser({ name, age }) { /* ... */ }

    Destructured parameters extract values from objects or arrays directly in the function signature. They are especially common in React props, API handlers, and configuration objects.

    Concept 8: arguments Object vs. Rest Parameters

    Aspect arguments Rest Parameters
    Type Array-like Real array
    Methods ❌ No map, filter ✅ Full array methods
    Arrow functions ❌ Not available ✅ Available
    Count All arguments Remaining arguments
    Status Legacy Modern

    The arguments object is not a real array and lacks array methods. Rest parameters are real arrays and should be preferred.

    Concept 9: Parameter length Property

    The length property of a function counts parameters before the first default or rest parameter.

    function f(a, b, c = 1, ...rest) {}
console.log(f.length); // 2

    Concept 10: Default Parameters Can Reference Earlier Parameters

    function createRange(start, end = start + 10) {
    return [start, end];
}

    Default expressions are evaluated left to right, so earlier parameters are available.

    Concept 11: Destructuring Requires a Default Object

    function f({ a, b } = {}) { /* ... */ }

    Without = {}, calling f() throws TypeError: Cannot destructure property 'a' of 'undefined'.

    Concept 12: ES2026 Spec — Mapped arguments Objects

    Per ES2026 §10.2.11 / §10.4.4.6 / §10.4.4.7, the arguments object binding exists only in non-strict functions with simple parameter lists. The mapping behavior — whether arguments[0] stays in sync with the first parameter — is controlled by the parameter-list shape. Functions with default, rest, or destructured parameters create unmapped arguments objects.

    Concept 13: Arrow Functions and Parameters

    Arrow functions support all parameter syntaxes — default, rest, and destructured — but parentheses are always required when using them.

    const add = (a, b) => a + b;                    // simple
const greet = (name = "world") => `Hi, ${name}`; // default
const sum = (...nums) => nums.reduce((a, b) => a + b); // rest
const f = ({ a, b }) => a + b;                  // destructured

    Concept 14: TypeScript Parameter Features

    TypeScript adds type annotations, optional parameters (?), and readonly parameters:

    function greet(name: string, age?: number): string { /* ... */ }

    TypeScript also supports parameter properties in constructors — a shorthand for declaring and assigning class fields.

    Concept 15: Default Parameters vs. || Defaults

    Aspect || Default Default Parameter
    Triggers on Any falsy value Only undefined
    0 respected ❌ No ✅ Yes
    "" respected ❌ No ✅ Yes
    false respected ❌ No ✅ Yes
    Readability Lower Higher

    Concept 16: ESLint Rules for Parameters

    Rule Purpose
    default-param-last Enforce default parameters last
    no-dupe-args Disallow duplicate parameter names
    max-params Limit number of parameters
    prefer-rest-params Prefer rest over arguments

    Concept 17: Parameter Destructuring in React

    function UserCard({ name, avatar, role = "user" }) {
    return <div>{name} — {role}</div>;
}

    Destructured parameters are the standard pattern for React component props.

    Concept 18: Performance — Parameters Are Free

    Parameter binding is extremely fast — parameters are allocated on the stack or in registers. There is no meaningful performance difference between simple parameters, default parameters, or rest parameters in optimized code.

    6. How It Works

    Step-by-Step: Parameter Binding

    1.  Function is called with arguments.
    │
    ▼
2.  New execution context is created.
    │
    ▼
3.  Parameters are bound in the function's local scope:
    │   - Simple: bound to corresponding argument (or undefined)
    │   - Default: bound to argument, or default if undefined
    │   - Rest: bound to array of remaining arguments
    │   - Destructured: pattern is matched against argument
    │
    ▼
4.  Function body executes.
    │
    ▼
5.  Execution context is destroyed.

    Step-by-Step: Default Parameter Evaluation

    1.  Function is called.
    │
    ▼
2.  For each parameter with a default:
    │   - If argument is undefined → evaluate default expression.
    │   - Else → use the argument.
    │
    ▼
3.  Default expressions are evaluated left to right.
    │
    ▼
4.  Earlier parameters are available to later defaults.

    Step-by-Step: Rest Parameter Collection

    1.  Function is called with arguments.
    │
    ▼
2.  Named parameters before the rest are bound first.
    │
    ▼
3.  All remaining arguments are collected into an array.
    │
    ▼
4.  The rest parameter is bound to that array.

    Step-by-Step: Destructured Parameter Binding

    1.  Object argument is passed.
    │
    ▼
2.  Destructuring pattern is applied.
    │
    ▼
3.  Each property is extracted and bound to a local variable.
    │
    ▼
4.  Default values are applied for missing properties.
    │
    ▼
5.  If the argument is undefined and `= {}` is present → use empty object.
    │
    ▼
6.  If the argument is undefined and no `= {}` → TypeError.

    Step-by-Step: arguments Object Creation

    1.  Non-strict function with simple parameters is called.
    │
    ▼
2.  `arguments` object is created.
    │
    ▼
3.  It is **mapped** — `arguments[i]` stays in sync with parameter `i`.
    │
    ▼
4.  For functions with default/rest/destructured params → **unmapped**.
    │
    ▼
5.  Arrow functions → no `arguments` at all.

    7. Internal Architecture / Under the Hood

    The Spec's Treatment of Parameters

    The ECMAScript specification covers parameter lists in Section 15.1 (Parameter Lists). Key subclauses:

    Clause Title
    15.1.1 Static Semantics: Early Errors
    15.1.2 Static Semantics: ContainsExpression
    15.1.3 Static Semantics: ExpectedArgumentCount
    15.1.4 Static Semantics: BoundNames
    15.1.5 Static Semantics: IsSimpleParameterList
    15.1.6 Runtime Semantics: IteratorBindingInitialization

    ExpectedArgumentCount

    The spec defines ExpectedArgumentCount — the number of parameters before the first default or rest parameter. This is exposed as the function's length property.

    IsSimpleParameterList

    A parameter list is simple if it contains only simple identifiers. It is not simple if it contains default, rest, or destructured parameters. This distinction affects:

    • Whether the arguments object is mapped or unmapped.
    • Whether "use strict" can be applied inside the function.

    IteratorBindingInitialization

    For destructured parameters, the engine uses IteratorBindingInitialization — an abstract operation that iterates over the pattern and binds each extracted value to a local variable.

    Mapped vs. Unmapped arguments

    Per ES2026 §10.2.11 / §10.4.4.6 / §10.4.4.7:

    • Mapped — arguments[i] and parameter i are aliases. Changing one changes the other.
    • Unmapped — arguments[i] is a copy. Changing one does not affect the other.

    Only non-strict functions with simple parameter lists create mapped arguments objects. Functions with default, rest, or destructured parameters create unmapped arguments objects.

    Memory Layout

    Function Execution Context:
┌─────────────────────────────────────┐
│  Parameter Environment              │
│                                     │
│  a: 10        ← simple parameter    │
│  b: "hello"   ← simple parameter    │
│  c: [1,2,3]   ← rest parameter      │
│  {name, age}  ← destructured        │
│                                     │
│  arguments: [10, "hello", 1, 2, 3]  │
└─────────────────────────────────────┘

    Performance in the JIT

    • Parameter binding is free — parameters are allocated on the stack or in registers.
    • Default parameter evaluation — costs the same as a conditional check.
    • Rest parameter allocation — creates an array; minor cost.
    • Destructuring — property extraction; optimized by the JIT.

    8. Lifecycle / Workflow

    Parameter Lifecycle

    Function defined → Parameters declared → Function called → Arguments bound → Body executes → Context destroyed

    Default Parameter Lifecycle

    Function called → Check if argument is undefined → Evaluate default if needed → Bind parameter

    Rest Parameter Lifecycle

    Function called → Bind named parameters → Collect remaining arguments into array → Bind rest parameter

    Destructured Parameter Lifecycle

    Function called → Check if argument is undefined → Apply `= {}` if needed → Match pattern → Bind extracted values

    9. Practical Examples

    Example 1: Simple Parameters

    function add(a, b) {
    return a + b;
}

console.log(add(2, 3)); // 5

    Example 2: Default Parameters

    function createUser(name, role = "viewer", active = true) {
    return { name, role, active };
}

console.log(createUser("Ada"));
// { name: "Ada", role: "viewer", active: true }

    Breakdown:

    • role and active have defaults.
    • Calling with just name uses defaults.

    Example 3: Default Parameters with null

    function greet(name = "world") {
    return `Hello, ${name}!`;
}

console.log(greet());          // "Hello, world!"
console.log(greet(undefined)); // "Hello, world!"
console.log(greet(null));      // "Hello, null!"

    Breakdown:

    • null does not trigger the default.

    Example 4: Rest Parameters

    function sum(...numbers) {
    return numbers.reduce((total, n) => total + n, 0);
}

console.log(sum(1, 2, 3));       // 6
console.log(sum(1, 2, 3, 4, 5)); // 15

    Example 5: Rest with Leading Named Parameters

    function log(level, ...messages) {
    console.log(`[${level}]`, ...messages);
}

log("INFO", "Server started", "Port 3000");
// [INFO] Server started Port 3000

    Example 6: Destructured Parameters

    function createUser({ name, age, role = "viewer" }) {
    return { name, age, role };
}

console.log(createUser({ name: "Ada", age: 36 }));
// { name: "Ada", age: 36, role: "viewer" }

    Example 7: Destructured Parameters with Default Object

    function createConfig({ debug = false, timeout = 5000 } = {}) {
    return { debug, timeout };
}

console.log(createConfig());                 // { debug: false, timeout: 5000 }
console.log(createConfig({ debug: true })); // { debug: true, timeout: 5000 }

    Breakdown:

    • = {} is essential — without it, createConfig() throws.

    Example 8: Nested Destructuring

    function processOrder({ customer: { name }, items: [first, ...rest] }) {
    return { name, firstItem: first, otherCount: rest.length };
}

console.log(processOrder({
    customer: { name: "Ada" },
    items: ["book", "pen", "lamp"],
}));
// { name: "Ada", firstItem: "book", otherCount: 2 }

    Example 9: Arrow Function Parameters

    const add = (a, b) => a + b;
const greet = (name = "world") => `Hello, ${name}!`;
const sum = (...nums) => nums.reduce((a, b) => a + b, 0);
const f = ({ a, b }) => a + b;

    Breakdown:

    • Arrow functions support all parameter syntaxes.

    Example 10: arguments vs. Rest Parameters

    // ❌ Legacy — arguments is not a real array
function oldSum() {
    return Array.from(arguments).reduce((a, b) => a + b, 0);
}

// ✅ Modern — rest parameter is a real array
function newSum(...numbers) {
    return numbers.reduce((a, b) => a + b, 0);
}

    Scenario Parameter Style
    Simple function Simple parameters
    Optional configuration Default parameters
    Variadic function Rest parameters
    Configuration object Destructured parameters
    React props Destructured parameters
    API request options Destructured parameters with defaults
    Math utilities Rest parameters

    React components Destructured props
    CLI argument parsing Rest parameters

    11. Best Practices

    1. Use default parameters instead of || for defaults. Why: respects 0, "", and false.
    2. Use rest parameters instead of arguments. Why: real arrays, available in arrow functions.
    3. Use destructured parameters for configuration objects. Why: self-documenting, concise.
    4. Always provide = {} when destructuring. Why: prevents TypeError on no-argument calls.
    5. Place default parameters last. Why: earlier defaults make length unpredictable.
    6. Keep parameter lists short. Why: more than 3-4 params suggests a configuration object.
    7. Name parameters meaningfully. Why: billAmount beats b.
    8. Use null only when you mean "explicitly no value". Why: null does not trigger defaults.
    9. Document default values. Why: callers need to know what happens when they omit arguments.
    10. Use JSDoc or TypeScript for parameter types. Why: type safety and documentation.
    11. Enable ESLint default-param-last. Why: enforces default parameter placement.
    12. Enable ESLint prefer-rest-params. Why: discourages arguments.
    13. Avoid mutating parameter objects. Why: side effects on caller data are surprising.
    14. Use object destructuring for more than 3 parameters. Why: callers can use named arguments.
    15. Prefer arrow functions for callbacks with parameters. Why: concise and lexical this.

    12. Common Mistakes

    ❌ Mistake: Using || for Defaults

    function setVolume(vol) {
    vol = vol || 50; // ❌ 0 becomes 50
    return vol;
}
setVolume(0); // 50 — wrong!

    ✅ Correct:

    function setVolume(vol = 50) {
    return vol;
}
setVolume(0); // 0

    ❌ Mistake: Forgetting = {} in Destructured Parameters

    function f({ a, b }) {}
f(); // ❌ TypeError: Cannot destructure property 'a' of 'undefined'

    ✅ Correct:

    function f({ a, b } = {}) {}
f(); // ✅ works

    ❌ Mistake: Rest Parameter Not Last

    function f(...rest, last) {} // ❌ SyntaxError

    ✅ Correct:

    function f(first, ...rest) {}

    ❌ Mistake: Multiple Rest Parameters

    function f(...a, ...b) {} // ❌ SyntaxError

    ✅ Correct: Only one rest parameter.

    ❌ Mistake: Trailing Comma After Rest

    function f(...rest,) {} // ❌ SyntaxError

    ✅ Correct:

    function f(...rest) {}

    ❌ Mistake: Using arguments in Arrow Functions

    const f = () => arguments; // ❌ ReferenceError

    ✅ Correct:

    const f = (...args) => args;

    ❌ Mistake: Expecting Default to Trigger on null

    function f(x = 10) { return x; }
f(null); // null — not 10

    ✅ Correct: Use x ?? 10 inside the body if null should trigger the default.

    ❌ Mistake: Duplicate Parameter Names

    function f(a, a) {} // ❌ SyntaxError in strict mode

    ✅ Correct: Use distinct names.

    ❌ Mistake: Mutating Parameter Objects

    function addItem(cart, item) {
    cart.push(item); // ❌ mutates caller's array
}

    ✅ Correct:

    function addItem(cart, item) {
    return [...cart, item]; // returns a new array
}

    ❌ Mistake: Destructuring a Primitive

    function f({ length }) {}
f("hello"); // ✅ works — strings have length
f(42); // ✅ works — number wrapped, length undefined
f(null); // ❌ TypeError

    ✅ Correct: Always provide = {} or validate input.

    13. Performance Considerations

    • Parameter binding is free — stack/register allocation.
    • Default parameter evaluation — costs the same as a conditional check.
    • Rest parameter allocation — creates an array; minor cost.
    • Destructuring — property extraction; optimized by the JIT.
    • arguments object — creates a mapped array-like object; more expensive than rest.
    • Too many parameters — JIT may deoptimize; keep lists short.

    Performance Tips

    1. Use rest parameters instead of arguments — faster and cleaner.
    2. Avoid creating functions with many parameters — use configuration objects.
    3. Keep destructuring shallow when possible.
    4. Profile with --trace-opt / --trace-deopt if needed.

    14. Security Considerations

    Parameter Injection

    Untrusted input passed as arguments can lead to injection attacks if not validated.

    Defense: Validate all parameters at trust boundaries.

    Prototype Pollution via Destructuring

    Destructuring __proto__ from untrusted objects can pollute the prototype chain.

    Defense: Validate input; use Object.create(null) for dictionaries.

    Default Parameter Side Effects

    Default expressions can call functions with side effects.

    Defense: Keep default expressions pure.

    Rest Parameter Exhaustion

    A rest parameter can collect an unbounded number of arguments — a potential DoS vector.

    Defense: Limit input size at boundaries.

    arguments Object and Strict Mode

    In strict mode, arguments does not alias parameters — this prevents some classes of bugs.

    Defense: Use strict mode (or ES modules, which are strict by default).

    15. Debugging Tips

    • Check f.length — number of parameters before defaults/rest.
    • console.log(arguments) — inspect the legacy arguments object.
    • console.log([...args]) — inspect rest parameters as a real array.
    • debugger; — pause inside the function.
    • ESLint default-param-last — flags misplaced defaults.
    • ESLint prefer-rest-params — flags arguments usage.
    • TypeScript — catches type mismatches at compile time.

    16. When to Use

    Parameter Style When to Use
    Simple Required inputs
    Default Optional inputs with fallbacks
    Rest Variadic functions
    Destructured Configuration objects, React props
    arguments Legacy code only — prefer rest

    17. When Not to Use

    • || for defaults — use default parameters instead.
    • arguments in new code — use rest parameters.
    • Too many simple parameters — use a configuration object.
    • Destructuring without = {} — always provide the default object.
    • Rest parameter not last — syntax error.
    • Duplicate parameter names — syntax error in strict mode.

    19. Did You Know?

    • Default parameters were introduced in ES2015 (ES6) — along with rest and destructured parameters.
    • Default parameters trigger only on undefined — not on null.
    • Rest parameters must be last — and only one per function.
    • Destructured parameters are the standard for React props — function UserCard({ name }) {}.
    • arguments is not a real array — it lacks map, filter, and forEach.
    • Arrow functions have no arguments — use rest parameters.
    • ES2026 §10.2.11 clarifies mapped arguments — only non-strict simple parameter lists create mapped objects.
    • Function length counts parameters before defaults/rest — function f(a, b, c = 1) {}.length is 2.
    • Default parameters can reference earlier parameters — function f(a, b = a + 1) {}.
    • = {} is required for destructured parameters — without it, no-argument calls throw.
    • The arguments object was the original way to access all arguments — before rest parameters.
    • ES2026 does not add new parameter syntax — the feature set is mature.

    20. Summary

    • Parameters are named inputs declared in a function's signature.
    • Four parameter styles: simple, default, rest, destructured.
    • Default parameters — fallback values; trigger only on undefined.
    • Rest parameters — collect remaining arguments into a real array; must be last.
    • Destructured parameters — extract values from objects/arrays directly in the signature.
    • Always provide = {} with destructured parameters.
    • Use ?? not || when 0, "", or false are valid values.
    • Use rest instead of arguments — real arrays, arrow function compatible.
    • arguments is legacy — unmapped in ES2026 for default/rest/destructured params.
    • Function length counts parameters before defaults/rest.
    • ESLint rules — default-param-last, prefer-rest-params, max-params.
    • TypeScript adds type annotations and optional parameters.
    • ES2026 does not change parameter syntax — the features are mature.
    • Parameters are the interface between function and caller — master them for clean, reusable code.
