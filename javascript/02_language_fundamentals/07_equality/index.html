    Equality

    1. Overview

    Definition

    Equality in JavaScript is the determination of whether two values are considered the same. The language provides three distinct comparison operations — each using a different definition of "same":

    // Strict equality (===)
1 === 1;              // true
"1" === 1;            // false — different types
NaN === NaN;          // false — IEEE 754 rule
-0 === +0;            // true — signed zero ignored

// Loose equality (==)
"1" == 1;             // true — string coerced to number
null == undefined;    // true — special case
0 == false;           // true — boolean coerced to number

// SameValue (Object.is)
Object.is(NaN, NaN);  // true — unlike ===
Object.is(-0, +0);    // false — unlike ===
Object.is("1", 1);    // false — no coercion

    Under the hood, these correspond to four equality algorithms defined in the ECMAScript specification:

    Algorithm Operator / Method Coercion? NaN equal? -0 = +0?
    IsLooselyEqual == Yes No Yes
    IsStrictlyEqual === No No Yes
    SameValue Object.is() No Yes No
    SameValueZero Built-ins (Map, Set, includes) No Yes Yes

    The choice of operation depends entirely on what kind of comparison you need. The distinction between them is purely about how primitives are handled — none of them compares object structure, and for non-primitive objects that are structurally identical but distinct in memory, all four return false .

    Purpose

    Equality exists to answer a fundamental question in every program: "Is this value the same as that one?" Every conditional, every loop termination check, every lookup in a collection depends on some definition of equality. JavaScript gives you three — each optimized for a different use case:

    • === — the default. Strict, predictable, almost always correct.
    • == — loose equality. Performs type coercion; occasionally useful for null/undefined checks.
    • Object.is() — SameValue. Needed for NaN comparison and signed-zero distinction.

    2. Why It Exists

    The Problem

    A programming language must decide what it means for two values to be equal. This sounds trivial until you consider:

    • Should "1" equal 1? The string and the number represent the same idea but have different types.
    • Should NaN equal NaN? IEEE 754 says no — NaN is the result of an undefined operation, so two NaNs are not necessarily the same result.
    • Should -0 equal +0? Mathematically they are the same number, but they carry different sign information.
    • Should { a: 1 } equal { a: 1 }? They have the same structure but are different objects in memory.

    Every language answers these differently. JavaScript's answer is to provide multiple equality algorithms and let the developer choose.

    Previous Limitations

    Era Limitation
    Pre-ES2015 No Object.is() — no way to compare NaN or distinguish -0
    == only Coercion surprises were the only option for loose comparison
    No SameValueZero in spec Built-in behavior was inconsistent across engines
    No ES2020 BigInt Equality across numeric types was simpler but less precise

    Why Object.is() Was Introduced

    Before ES2015, there was no standard way to:

    • Check if two values are both NaN.
    • Distinguish -0 from +0.

    The Object.is() method was added in ES2015 to provide the SameValue algorithm — a stricter comparison that treats NaN as equal to itself and -0 as different from +0 .

    Why SameValueZero Exists

    The spec also defines SameValueZero — used internally by Map, Set, Array.prototype.includes, and other built-ins. It differs from SameValue only in that it treats +0 and -0 as equal . This is the algorithm that makes new Set([NaN, NaN]) contain only one element.

    3. Syntax / Basic Usage

    Strict Equality (===)

    // Same type — compare values
1 === 1;              // true
"hello" === "hello";  // true
true === true;        // true

// Different types — always false
1 === "1";            // false
null === undefined;   // false
true === 1;           // false

// Special numeric cases
NaN === NaN;          // false (IEEE 754)
-0 === +0;            // true (signed zero ignored)
Infinity === Infinity; // true

    Loose Equality (==)

    // Same type — behaves like ===
1 == 1;               // true

// Different types — coercion occurs
1 == "1";             // true (string → number)
0 == false;           // true (boolean → number)
"" == false;          // true (both → number: 0 == 0)
null == undefined;    // true (special case)
null == 0;            // false (null only equals undefined)
NaN == NaN;           // false

// Objects
[] == false;          // true (both → number: 0 == 0)
[] == 0;              // true
[1] == 1;             // true
[1, 2] == "1,2";      // true
{} == "[object Object]"; // true

    SameValue (Object.is())

    Object.is(1, 1);              // true
Object.is("1", 1);            // false
Object.is(NaN, NaN);          // true
Object.is(-0, +0);            // false
Object.is(null, null);        // true
Object.is(undefined, undefined); // true
Object.is({}, {});            // false (distinct objects)

    SameValueZero (Built-In Usage)

    // Map uses SameValueZero for keys
const map = new Map();
map.set(NaN, "value");
map.get(NaN); // "value" — NaN keys work

// Set uses SameValueZero
new Set([NaN, NaN]).size; // 1

// Array.prototype.includes uses SameValueZero
[NaN].includes(NaN);      // true
[NaN].indexOf(NaN);       // -1 (indexOf uses ===)

    Negation Operators

    1 !== 2;    // true (strict inequality)
1 != 2;     // true (loose inequality)
1 !== "1";  // true (different types)
1 != "1";   // false (coerced, so equal)

    ES2026 and Equality

    ES2026 does not introduce new equality operators. However, it adds features that interact with equality:

    // Object.is is recommended for memoization and diffing
Object.is(prevState, nextState); // ES2026 best practice

// Error.isError — reliable error detection
Error.isError(new Error()); // true
Error.isError({ message: "fake" }); // false

// Map.getOrInsert — upsert with SameValueZero key matching
map.getOrInsert(key, defaultValue);

    4. Mental Model

    The "Four Lenses" Mental Model

    Think of equality as looking at two values through four different lenses:

    ┌─────────────────────────────────────────────────────────────┐
│                    Equality Lenses                          │
│                                                             │
│  ┌─────────────────┐  ┌─────────────────┐                  │
│  │  IsLooselyEqual │  │  IsStrictlyEqual│                  │
│  │  (==)           │  │  (===)          │                  │
│  │                 │  │                 │                  │
│  │  Coerces types  │  │  No coercion    │                  │
│  │  NaN ≠ NaN      │  │  NaN ≠ NaN      │                  │
│  │  -0 = +0        │  │  -0 = +0        │                  │
│  └─────────────────┘  └─────────────────┘                  │
│                                                             │
│  ┌─────────────────┐  ┌─────────────────┐                  │
│  │  SameValue      │  │  SameValueZero  │                  │
│  │  (Object.is)    │  │  (Built-ins)    │                  │
│  │                 │  │                 │                  │
│  │  No coercion    │  │  No coercion    │                  │
│  │  NaN = NaN      │  │  NaN = NaN      │                  │
│  │  -0 ≠ +0        │  │  -0 = +0        │                  │
│  └─────────────────┘  └─────────────────┘                  │
└─────────────────────────────────────────────────────────────┘

    SameValueZero is the "middle ground" — it differs from Strict Equality only in treating NaN as equal to itself, and differs from SameValue only in treating -0 and +0 as equal.

    The "Same Value, Different Question" Mental Model

    The four algorithms answer different questions:

    Algorithm Question It Answers
    === "Are these the same value, ignoring signed zero, and treating NaN as unequal?"
    == "Are these equal after coercing types?"
    Object.is() "Are these the exact same value, including NaN and signed zero?"
    SameValueZero "Are these the same value for collection lookup, treating NaN as equal and signed zero as equal?"

    The "Coercion Ladder" Mental Model

    == follows a specific coercion order:

    1. Same type? → Use ===
2. null vs undefined? → true
3. Number vs String? → String → Number
4. Boolean? → Boolean → Number
5. Object vs Primitive? → ToPrimitive(Object)
6. Otherwise → false

    The "IEEE 754 vs. JavaScript" Mental Model

    NaN and -0 are inherited from IEEE 754 floating-point arithmetic:

    • NaN is the result of undefined operations (0/0, Math.sqrt(-1)).
    • -0 is a signed zero that preserves direction information.

    JavaScript's === follows IEEE 754 for NaN (not equal to itself) but deviates for -0 (treats it as equal to +0) . Object.is() restores the IEEE 754 view for both.

    5. Core Concepts

    Concept 1: The Four Equality Algorithms

    Algorithm Spec Name Used By Coercion NaN Equal -0 = +0
    Loose IsLooselyEqual == Yes No Yes
    Strict IsStrictlyEqual === No No Yes
    SameValue SameValue Object.is() No Yes No
    SameValueZero SameValueZero Map, Set, includes, indexOf (partially) No Yes Yes

    Concept 2: Strict Equality (===) — The Default

    Strict equality compares two values without type coercion:

    • If the types differ → false.
    • If both are NaN → false.
    • If one is +0 and the other -0 → true.
    • Otherwise, compare values directly.
    "0" === 0;     // false
null === undefined; // false
NaN === NaN;   // false
-0 === +0;     // true

    Strict equality is almost always the correct comparison to use .

    Concept 3: Loose Equality (==) — Coercion Rules

    == performs type coercion before comparing:

    Comparison Result Reason
    null == undefined true Special case
    null == 0 false null only equals undefined
    "5" == 5 true String → Number
    0 == false true Boolean → Number
    "" == false true Both → Number: 0 == 0
    [] == false true Both → Number: 0 == 0
    [1] == 1 true Array → String → Number
    NaN == NaN false IEEE 754

    Concept 4: SameValue (Object.is()) — The Strictest

    Object.is() uses the SameValue algorithm:

    • No type coercion.
    • NaN is equal to NaN.
    • -0 is not equal to +0.
    • Objects are compared by reference.
    Object.is(NaN, NaN);   // true
Object.is(-0, +0);     // false
Object.is(0, -0);      // false
Object.is({}, {});     // false

    Concept 5: SameValueZero — The Built-In Standard

    SameValueZero is used by:

    • Map keys
    • Set values
    • Array.prototype.includes
    • TypedArray.prototype.includes
    • String.prototype.includes (indirectly)

    It treats NaN as equal to itself and +0/-0 as equal .

    new Map([[NaN, "a"]]).get(NaN); // "a"
new Set([NaN, NaN]).size;       // 1
[NaN].includes(NaN);            // true
[NaN].indexOf(NaN);             // -1 (indexOf uses ===)

    Concept 6: Object Comparison Is Always by Reference

    None of the equality algorithms compare object structure.

    {} === {};              // false
[] === [];              // false
Object.is({}, {});      // false
new Date(0) === new Date(0); // false

    For deep equality, you need a library or custom function.

    Concept 7: NaN Is Never Equal to Itself with === or ==

    NaN === NaN;  // false
NaN == NaN;   // false

    This follows IEEE 754. To check for NaN, use:

    Number.isNaN(value);  // reliable, no coercion
Object.is(value, NaN); // also reliable

    Concept 8: -0 and +0 Are Equal with === and ==

    -0 === +0;  // true
-0 == +0;   // true

    But Object.is() distinguishes them:

    Object.is(-0, +0); // false

    Concept 9: null and undefined — Loose Equality Special Case

    null == undefined;   // true
null === undefined;  // false

    null does not equal 0, "", or false:

    null == 0;     // false
null == "";    // false
null == false; // false

    Concept 10: BigInt Equality

    1n === 1n;    // true
1n == 1;      // true (coercion)
1n === 1;     // false (different types)
0n == false;  // true (both → number: 0 == 0)
0n === false; // false

    BigInt can be loosely compared to Number, but strict comparison requires same type.

    Concept 11: Object.is() and === Differences

    Value Pair === Object.is()
    NaN, NaN false true
    -0, +0 true false
    0, -0 true false
    Everything else Same Same

    Concept 12: When to Use Each

    Need Use
    Default comparison ===
    null/undefined check == null (loose)
    NaN comparison Object.is() or Number.isNaN()
    Signed zero distinction Object.is()
    Collection keys SameValueZero (built-in)
    Deep object equality Custom or library

    Concept 13: ES2026 Equality-Related Features

    • Object.is() is recommended for memoization and diffing in modern code .
    • Error.isError() provides reliable error detection.
    • Map.getOrInsert() uses SameValueZero for key matching.
    • Math.sumPrecise() does not change equality but improves numeric precision.

    Concept 14: ESLint and Equality

    The ESLint rule eqeqeq enforces === and !== — it is considered good practice to use type-safe equality operators .

    Concept 15: isNaN() vs Number.isNaN() vs Object.is()

    isNaN("hello");          // true (coerces — unreliable)
Number.isNaN("hello");   // false (no coercion — reliable)
Object.is("hello", NaN); // false (no coercion — reliable)

    Concept 16: Equality in switch

    switch uses strict equality (===) for case matching:

    switch ("5") {
    case 5: console.log("number"); break;   // ❌ not matched
    case "5": console.log("string"); break; // ✅ matched
}

    Concept 17: Equality in Array.prototype.sort

    The default sort() converts elements to strings and compares lexicographically — not the same as === comparison:

    [10, 2, 1].sort(); // [1, 10, 2] — lexicographic
[10, 2, 1].sort((a, b) => a - b); // [1, 2, 10] — numeric

    Concept 18: Equality and Set/Map

    new Set([1, "1", 1]).size;   // 2 (1 and "1" are distinct)
new Set([NaN, NaN]).size;    // 1 (SameValueZero)
new Set([-0, +0]).size;      // 1 (SameValueZero)

    6. How It Works

    Step-by-Step: === Evaluation

    1.  If Type(x) ≠ Type(y) → return false.
    │
    ▼
2.  If both are Undefined → return true.
3.  If both are Null → return true.
4.  If both are Boolean → compare values.
5.  If both are String → compare code units.
6.  If both are Number:
    │   - If either is NaN → return false.
    │   - If same value → return true.
    │   - If +0 and -0 → return true.
7.  If both are BigInt → compare values.
8.  If both are Symbol → compare identity.
9.  If both are Object → compare references.

    Step-by-Step: == Evaluation (IsLooselyEqual)

    1.  If Type(x) = Type(y) → return IsStrictlyEqual(x, y).
    │
    ▼
2.  If x is null and y is undefined → return true.
3.  If x is undefined and y is null → return true.
4.  If x is Number and y is String → return x == ToNumber(y).
5.  If x is String and y is Number → return ToNumber(x) == y.
6.  If x is BigInt and y is String → String → BigInt.
7.  If x is String and y is BigInt → String → BigInt.
8.  If x is Boolean → return ToNumber(x) == y.
9.  If y is Boolean → return x == ToNumber(y).
10. If x is Number/String/BigInt/Symbol and y is Object → ToPrimitive(y).
11. If x is Object and y is Number/String/BigInt/Symbol → ToPrimitive(x).
12. If x is BigInt and y is Number → compare if mathematical values equal.
13. If x is Number and y is BigInt → compare if mathematical values equal.
14. Otherwise → return false.

    Step-by-Step: Object.is() Evaluation (SameValue)

    1.  If Type(x) ≠ Type(y) → return false.
    │
    ▼
2.  If both are Undefined → return true.
3.  If both are Null → return true.
4.  If both are Boolean → compare values.
5.  If both are String → compare code units.
6.  If both are Symbol → compare identity.
7.  If both are Number:
    │   - If both are NaN → return true.
    │   - If both are +0 → return true.
    │   - If both are -0 → return true.
    │   - If both are non-zero, not NaN, and same value → return true.
    │   - Otherwise → return false.
8.  If both are BigInt → compare values.
9.  If both are Object → compare references.

    Step-by-Step: SameValueZero

    Identical to SameValue except:

    If both are Number and one is +0 and the other is -0 → return true.

    Step-by-Step: Object.is() in Practice

    // Memoization example
function memoize(fn) {
    let lastArgs = null;
    let lastResult;
    return (...args) => {
        if (lastArgs && args.length === lastArgs.length &&
            args.every((arg, i) => Object.is(arg, lastArgs[i]))) {
            return lastResult;
        }
        lastArgs = args;
        lastResult = fn(...args);
        return lastResult;
    };
}

    Object.is() correctly handles NaN arguments and distinguishes -0 from +0 — important for numerical memoization.

    7. Internal Architecture / Under the Hood

    The Abstract Operations in ECMA-262

    The spec defines equality in Section 7.2:

    Operation Spec Section Operator/Method
    IsLooselyEqual 7.2.12 ==
    IsStrictlyEqual 7.2.13 ===
    SameValue 7.2.10 Object.is()
    SameValueZero 7.2.11 Built-ins

    SameValue vs. SameValueZero

    From the spec:

    SameValueZero differs from SameValue only in its treatment of +0 and -0 .

    • SameValue: +0 and -0 are different.
    • SameValueZero: +0 and -0 are the same.

    Object.is() Is Not ===

    Object.is() is not equivalent to ===. The only differences are in their treatment of signed zeros and NaN values :

    • === treats -0 and +0 as equal but NaN as unequal.
    • Object.is() treats -0 and +0 as unequal but NaN as equal.

    How V8 Optimizes Equality

    V8 compiles === and == into specialized bytecode based on type feedback:

    function compare(a, b) { return a === b; }
compare(1, 2);   // feedback: number, number → fast integer compare
compare("a", "b"); // guard fails → deoptimize → string compare

    Each comparison site records the types it has seen. The JIT emits speculative machine code with guards. If a guard fails, the function deoptimizes.

    SameValueZero in Built-Ins

    Map, Set, and Array.prototype.includes use SameValueZero internally. This is why NaN keys work in Map and why [NaN].includes(NaN) is true while [NaN].indexOf(NaN) is -1:

    • includes uses SameValueZero.
    • indexOf uses Strict Equality.

    The Spec's Treatment of NaN

    NaN is defined as not equal to itself by IEEE 754. The spec preserves this for == and === but reverses it for SameValue and SameValueZero.

    The Spec's Treatment of -0

    -0 and +0 are the same mathematical value but different IEEE 754 representations. The spec treats them as equal for == and === but different for SameValue.

    Equality Evaluation Lifecycle

    Values → Select algorithm → Apply type rules → Compare → Boolean result

    Loose Equality Workflow

    Values → Same type? → Yes → IsStrictlyEqual
              │
              ▼ No
         Special cases? → null/undefined → true
              │
              ▼
         Coerce → Compare → Result

    Strict Equality Workflow

    Values → Same type? → No → false
              │
              ▼ Yes
         Compare values → Result

    SameValue Workflow

    Values → Same type? → No → false

              ▼ Yes

    9. Practical Examples

    Example 1: Strict Equality Is the Default

    const a = 1;
const b = "1";

console.log(a === b); // false
console.log(a == b);  // true (coercion)

    Breakdown:

    • === returns false because types differ.
    • == returns true because "1" is coerced to 1.

    Example 2: NaN Comparison

    const result = 0 / 0;

console.log(result === result);          // false
console.log(Object.is(result, NaN));     // true
console.log(Number.isNaN(result));       // true

    Breakdown:

    • NaN is never equal to itself with ===.
    • Object.is() and Number.isNaN() are reliable.

    Example 3: Signed Zero

    console.log(-0 === +0);               // true
console.log(Object.is(-0, +0));       // false
console.log(1 / -0);                  // -Infinity
console.log(1 / +0);                  // Infinity

    Breakdown:

    • === ignores sign of zero.
    • Object.is() distinguishes them.

    Example 4: null vs undefined

    console.log(null == undefined);   // true
console.log(null === undefined);  // false
console.log(null == 0);           // false
console.log(undefined == 0);      // false

    Breakdown:

    • null and undefined are loosely equal.
    • Neither equals 0 loosely.

    Example 5: Object Comparison

    const obj1 = { a: 1 };
const obj2 = { a: 1 };

console.log(obj1 === obj2);           // false
console.log(Object.is(obj1, obj2));   // false
console.log(obj1 === obj1);           // true

    Breakdown:

    • Objects are compared by reference.
    • Deep equality requires a library.

    Example 6: Map and Set with SameValueZero

    const map = new Map();
map.set(NaN, "value");
console.log(map.get(NaN)); // "value"

const set = new Set([NaN, NaN, -0, +0]);
console.log(set.size); // 2 (NaN and 0)

    Breakdown:

    • Map and Set use SameValueZero.
    • NaN works as a key.
    • -0 and +0 are treated as the same value.

    Example 7: Array.prototype.includes vs indexOf

    const arr = [NaN, 1, 2];

console.log(arr.includes(NaN)); // true
console.log(arr.indexOf(NaN));  // -1

    Breakdown:

    • includes uses SameValueZero → NaN is found.
    • indexOf uses Strict Equality → NaN is not found.

    Example 8: BigInt Equality

    console.log(1n === 1n); // true
console.log(1n == 1);   // true
console.log(1n === 1);  // false
console.log(0n == false); // true

    Breakdown:

    • BigInt can be loosely compared to Number.
    • Strict comparison requires same type.

    Example 9: Object.is() for Memoization

    function memoize(fn) {
    const cache = new Map();
    return (...args) => {
        const key = args.map(a => Object.is(a, NaN) ? "NaN" : a).join("|");
        if (cache.has(key)) return cache.get(key);
        const result = fn(...args);
        cache.set(key, result);
        return result;
    };
}

    Breakdown:

    • Object.is() correctly identifies NaN.
    • Ensures NaN arguments don't break memoization.

    "rules": {
        "eqeqeq": ["error", "always"]
    }
}

    Breakdown:

    • Enforces === and !==.
    • Prevents accidental loose comparisons.

    11. Best Practices

    1. Use === and !== by default. Why: avoids coercion surprises; predictable.
    2. Use == null only for null/undefined checks. Why: the one legitimate loose equality use case.
    3. Use Object.is() for NaN and signed-zero comparison. Why: only way to distinguish them.
    4. Use Number.isNaN() for NaN detection. Why: reliable, no coercion.
    5. Enable ESLint eqeqeq. Why: enforces type-safe equality automatically.
    6. Avoid == except for null/undefined. Why: coercion rules are complex.
    7. Use includes over indexOf for NaN. Why: includes uses SameValueZero.
    8. Understand that objects compare by reference. Why: {a:1} === {a:1} is false.
    9. Use libraries for deep equality. Why: JavaScript has no built-in deep comparison.
    10. Be aware of -0 and NaN in numeric code. Why: === cannot distinguish them.
    11. Use Object.is() in memoization and diffing. Why: handles edge cases correctly (ES2026 best practice).
    12. Keep comparisons simple. Why: complex expressions are hard to debug.
    13. Use TypeScript to catch type mismatches. Why: prevents unintended comparisons.
    14. Document intentional loose equality. Why: == usage should be justified.
    15. Test edge cases: NaN, -0, null, undefined. Why: equality bugs hide there.

    12. Common Mistakes

    ❌ Mistake: Using == Instead of ===

    0 == "";    // true
0 == false; // true
"" == false; // true

    ✅ Correct:

    0 === "";    // false
0 === false; // false
"" === false; // false

    ❌ Mistake: NaN === NaN for NaN Check

    if (value === NaN) { /* never runs */ }

    ✅ Correct:

    if (Number.isNaN(value)) { /* ... */ }

    ❌ Mistake: Comparing Objects by Value

    if ({ a: 1 } === { a: 1 }) { /* never runs */ }

    ✅ Correct: Use a deep equality library.

    ❌ Mistake: Forgetting -0 vs +0

    if (value === 0) { /* matches -0 too */ }

    ✅ Correct:

    if (Object.is(value, 0)) { /* only +0 */ }

    ❌ Mistake: indexOf for NaN

    [NaN].indexOf(NaN); // -1

    ✅ Correct:

    [NaN].includes(NaN); // true

    ❌ Mistake: Assuming null == 0

    null == 0; // false

    ✅ Correct: null only loosely equals undefined.

    ❌ Mistake: Using Object.is() When === Works

    Object.is(1, 1); // true — but === is clearer

    ✅ Correct: Use === unless NaN or -0 matters.

    ❌ Mistake: Forgetting switch Uses ===

    switch ("5") {
    case 5: /* not matched */ break;
}

    ✅ Correct: Use the same type in case.

    ❌ Mistake: Not Understanding SameValueZero

    new Map([[NaN, 1]]).get(NaN); // 1 — works because SameValueZero

    ✅ Correct: Understand that Map and Set use SameValueZero.

    ❌ Mistake: ESLint eqeqeq Disabled

    ✅ Correct: Enable eqeqeq to catch loose equality mistakes automatically.

    13. Performance Considerations

    • === is fastest — no coercion, direct comparison.
    • == is slower — coercion adds overhead.
    • Object.is() — similar to ===; slight function call overhead.
    • Type stability — keep compared types consistent for JIT optimization.
    • Map/Set lookups — O(1) average with SameValueZero.
    • includes vs indexOf — includes is optimized for SameValueZero.
    • Deep equality — library-dependent; avoid in hot paths.
    • String comparison — can be expensive for long strings.

    Performance Tips

    1. Use === in hot loops.
    2. Avoid == in performance-critical code.
    3. Keep comparison types stable.
    4. Use Map/Set for lookups.
    5. Use includes over indexOf for correctness and speed.
    6. Profile with --trace-opt / --trace-deopt.

    14. Security Considerations

    Coercion Attacks

    if (input == 1) { /* bypassed with "1" or [1] */ }

    Defense: Always use ===.

    Prototype Pollution

    Objects with manipulated prototypes can affect equality checks.

    Defense: Validate input; use Object.create(null).

    NaN and DoS

    Comparing with NaN can lead to unexpected logic branches.

    Defense: Use Number.isNaN() explicitly.

    Signed Zero

    Security-sensitive numeric code may care about -0 vs +0.

    Defense: Use Object.is() when sign matters.

    Object Reference Comparison

    Comparing objects by reference can lead to security bugs if identity is assumed.

    Defense: Use deep equality for untrusted data.

    Map/Set Key Collisions

    SameValueZero treats -0 and +0 as the same key.

    Defense: Be aware of this when keys are numeric.

    15. Debugging Tips

    • console.log(a === b, a, b) — log comparison and both values.
    • Number.isNaN(value) — reliable NaN check.
    • Object.is(a, b) — SameValue check.
    • Object.prototype.toString.call(value) — precise type detection.
    • ESLint eqeqeq — flags ==.
    • debugger; — inspect values during comparison.
    • Chrome DevTools Console — type-aware autocomplete.
    • TypeScript — catches type mismatches.
    • Break comparisons into variables — easier to inspect.

    17. When Not to Use

    • == — never, except == null.
    • === for NaN — use Number.isNaN().
    • === for signed zero — use Object.is().
    • indexOf for NaN — use includes.
    • Object comparison with any operator — use deep equality.
    • Object.is() when === suffices — prefer === for clarity.

    19. Did You Know?

    • JavaScript has four equality algorithms, not three — SameValueZero is the fourth, used by built-ins .
    • NaN !== NaN is the only value not equal to itself — a direct consequence of IEEE 754.
    • Object.is() was added in ES2015 — before that, there was no standard way to compare NaN or distinguish -0 .
    • Object.is() is not equivalent to === — it differs only on NaN and signed zeros .
    • SameValueZero differs from SameValue only in treating +0 and -0 as equal .
    • Map and Set use SameValueZero, which is why NaN keys work.
    • Array.prototype.includes uses SameValueZero — indexOf uses Strict Equality.
    • null == undefined is true, but null == 0 is false.
    • "1" == 1 is true — string is coerced to number.
    • [] == false is true — both become 0.
    • switch uses === — no coercion occurs.
    • ESLint's eqeqeq rule enforces type-safe equality .
    • ES2026 recommends Object.is() for memoization and diffing .
    • ES2026 added Error.isError() for reliable error detection.
    • Objects always compare by reference — none of the four algorithms does deep comparison.

    20. Summary

    • JavaScript has four equality algorithms: IsLooselyEqual (==), IsStrictlyEqual (===), SameValue (Object.is()), and SameValueZero (built-ins).
    • === is the default — no coercion, predictable.
    • == performs coercion — only use == null for null/undefined checks.
    • Object.is() handles NaN and signed zeros correctly — use it when those matter.
    • SameValueZero is used by Map, Set, and includes — treats NaN as equal and +0/-0 as equal.
    • NaN !== NaN — use Number.isNaN() for detection.
    • -0 === +0 — use Object.is() to distinguish.
    • Objects compare by reference — no built-in deep equality.
    • null == undefined is true; null == 0 is false.
    • ESLint eqeqeq enforces === and !==.
    • ES2026 recommends Object.is() for memoization and diffing.
    • Use includes over indexOf for NaN.
    • Understand the four lenses — each answers a different question.
    • When in doubt, use === — it is almost always the correct choice.
