    Operators

    1. Overview

    Definition

    An operator is a symbol or keyword that performs an operation on one or more operands (values or expressions) and produces a result. JavaScript operators fall into several categories: arithmetic, assignment, comparison, logical, bitwise, string, ternary, comma, unary, relational, and the newer pipeline operator.

    const sum = 2 + 3;                    // arithmetic
const isEqual = sum === 5;            // comparison
const result = isEqual ? "yes" : "no"; // ternary
const value = data ?? "default";      // nullish coalescing
const name = user?.profile?.name;     // optional chaining
const processed = input |> validate |> transform; // pipeline (ES2026)

    Purpose

    Operators exist to express computation and logic concisely. They are the verbs of a programming language — the actions performed on data. Without operators, every computation would require a function call, making code verbose and unreadable.

    Where It Fits

    Language Fundamentals
├── Variables             ✅ done
├── Data Types            ✅ done
├── Operators             ← you are here
├── Expressions
├── Statements
├── Type Conversion
├── Equality
└── Strict Mode

    Operators sit directly after Data Types because types determine which operations are valid and how they behave. The next concept — Expressions — describes how operators and operands combine into evaluable units.

    2. Why It Exists

    The Problem

    Programming is fundamentally about transforming values. You need to add numbers, compare strings, combine conditions, assign results, and check types. Without a rich set of operators, every transformation would require verbose function calls, and code would become an unreadable nest of parentheses.

    Previous Limitations

    Era Limitation
    Pre-ES2015 No ** exponentiation, no ??, no ?.
    No optional chaining Deep property access required manual null checks
    No nullish coalescing || incorrectly handled 0, "", false
    No pipeline Function composition required nested calls
    Limited assignment operators Only =, +=, -=, etc. — no logical assignment

    Why New Operators Were Introduced

    • ** (ES2016) — exponentiation without Math.pow().
    • ?. (ES2020) — safe property access without manual null checks.
    • ?? (ES2020) — nullish coalescing that respects 0, "", false.
    • Logical assignment (&&=, ||=, ??=) (ES2021) — concise conditional assignment.
    • |> pipeline (ES2026) — readable left-to-right function composition.

    Each operator solves a specific readability or correctness problem. The language evolves by absorbing common patterns into syntax.

    3. Syntax / Basic Usage

    Arithmetic Operators

    2 + 3;        // 5 (addition)
10 - 4;       // 6 (subtraction)
3 * 4;        // 12 (multiplication)
10 / 2;       // 5 (division)
10 % 3;       // 1 (remainder)
2 ** 10;      // 1024 (exponentiation, ES2016)
+"5";         // 5 (unary plus, converts to number)
-"5";         // -5 (unary minus)

    Assignment Operators

    let x = 10;
x += 5;       // x = x + 5 → 15
x -= 3;       // x = x - 3 → 12
x *= 2;       // x = x * 2 → 24
x /= 4;       // x = x / 4 → 6
x %= 4;       // x = x % 4 → 2
x **= 2;      // x = x ** 2 → 4
x ??= 10;     // x = x ?? 10 (only if null/undefined)
x ||= 5;      // x = x || 5 (only if falsy)
x &&= 7;      // x = x && 7 (only if truthy)

    Comparison Operators

    1 == "1";       // true (loose equality, coerces)
1 === "1";      // false (strict equality, no coercion)
1 != "1";       // false (loose inequality)
1 !== "1";      // true (strict inequality)
2 > 1;          // true
2 >= 2;         // true
1 < 2;          // true
1 <= 1;         // true

    Logical Operators

    true && false;  // false (AND)
true || false;  // true (OR)
!true;          // false (NOT)
null ?? "default"; // "default" (nullish coalescing)
0 ?? "default";    // 0 (only null/undefined trigger fallback)

    Bitwise Operators

    5 & 1;          // 1 (AND)
5 | 1;          // 5 (OR)
5 ^ 1;          // 4 (XOR)
~5;             // -6 (NOT)
5 << 1;         // 10 (left shift)
5 >> 1;         // 2 (signed right shift)
5 >>> 1;        // 2 (unsigned right shift)

    Bitwise operators treat operands as 32-bit signed integers and return a 32-bit signed integer.

    String Operators

    "Hello" + " " + "World"; // "Hello World" (concatenation)
`Hello ${name}`;          // template literal

    Unary Operators

    typeof x;      // type string
void 0;        // undefined (evaluates, returns undefined)
delete obj.prop; // deletes a property
!x;            // logical NOT
-x;            // negation
+x;            // conversion to number
~x;            // bitwise NOT

    Ternary Operator

    const status = age >= 18 ? "adult" : "minor";

    Optional Chaining and Nullish Coalescing

    const street = user?.address?.street; // undefined if any link is nullish
const name = user.name ?? "Anonymous"; // "Anonymous" only if null/undefined

    Pipeline Operator (ES2026)

    const result = input
    |> validate
    |> normalize
    |> transform
    |> save;

// Equivalent to:
const result = save(transform(normalize(validate(input))));

    The pipeline operator |> passes the left-hand value as the argument to the right-hand function. It reached Stage 4 in ES2026 and is now supported in evergreen browsers behind a flag.

    With await support:

    const data = await input
    |> validate
    |> await fetchDetails
    |> transform;

    Comma Operator

    let a = (1, 2, 3); // a = 3 (evaluates each, returns last)

    The comma operator is rarely used outside for loop headers.

    Spread and Rest

    const arr = [1, 2, 3];
const copy = [...arr];           // spread
function sum(...nums) {}         // rest parameters
const { a, ...rest } = obj;      // object rest

    in, instanceof, new, new.target

    "key" in obj;                    // property existence
arr instanceof Array;            // prototype chain check
new Date();                      // constructor invocation
function F() { new.target; }     // constructor detection

    void and delete

    void 0;         // undefined
delete obj.key; // removes property

    4. Mental Model

    The "Operator Precedence Ladder" Mental Model

    Operators are evaluated in a specific order. Think of it as a ladder from highest to lowest precedence:

    18. Grouping ( )
17. Member access . []
16. new (with argument list)
15. Function call ()
14. new (without argument list)
13. Postfix ++ --
12. Unary ! ~ + - typeof void delete await
11. Exponentiation **
10. Multiplicative * / %
 9. Additive + -
 8. Bitwise shift << >> >>>
 7. Relational < > <= >= in instanceof
 6. Equality == != === !==
 5. Bitwise AND &
 4. Bitwise XOR ^
 3. Bitwise OR |
 2. Logical AND &&
 2. Nullish coalescing ??
 2. Logical OR ||
 1. Conditional ?:
 0. Assignment = += -= ...
-1. Comma ,

    Higher precedence binds tighter. 2 + 3 * 4 is 2 + (3 * 4) — not (2 + 3) * 4.

    The "Truthy/Falsy" Mental Model

    Logical operators and conditionals rely on truthiness:

    Falsy: false, 0, -0, 0n, "", null, undefined, NaN
Truthy: everything else — including "0", "false", [], {}, function(){}

    &&, ||, and ! operate on truthiness. ?? operates only on nullishness (null or undefined).

    The "Short-Circuit" Mental Model

    && and || short-circuit — they stop evaluating as soon as the result is determined:

    false && expensive(); // expensive() is never called
true || expensive();  // expensive() is never called

    This is not just an optimization — it is a control flow mechanism used constantly in JavaScript.

    The "Reference vs. Value" Mental Model

    Assignment operators copy values for primitives and references for objects:

    let a = 10;
let b = a;    // copies value
b = 20;       // a is still 10

const obj1 = { x: 1 };
const obj2 = obj1; // copies reference
obj2.x = 2;        // obj1.x is also 2

    The "Pipeline" Mental Model

    The pipeline operator |> reads left to right:

    input |> fn1 |> fn2 |> fn3

    This mirrors Unix pipes and functional composition. It eliminates nested calls and makes data flow explicit.

    5. Core Concepts

    Concept 1: Operator Categories

    Category Operators
    Arithmetic + - * / % **
    Assignment = += -= *= /= %= **= <<= >>= >>>= &= ^= \|= &&= \|\|= ??=
    Comparison == != === !== > >= < <=
    Logical && \|\| ! ??
    Bitwise & \| ^ ~ << >> >>>
    String + (concatenation)
    Unary typeof void delete ! - + ~
    Relational in instanceof
    Ternary ? :
    Comma ,
    Pipeline \|> (ES2026)
    Optional chaining ?.
    Spread/Rest ...

    Concept 2: Unary, Binary, and Ternary

    • Unary — one operand (!x, typeof x, -x).
    • Binary — two operands (a + b, a === b).
    • Ternary — three operands (cond ? a : b).

    Concept 3: Operator Precedence and Associativity

    Precedence determines which operator binds tighter. Associativity determines grouping direction:

    2 ** 3 ** 2;  // right-associative → 2 ** (3 ** 2) = 512
10 - 3 - 2;   // left-associative → (10 - 3) - 2 = 5

    When in doubt, use parentheses. Clarity beats cleverness.

    Concept 4: Loose vs. Strict Equality

    1 == "1";   // true — coerces
1 === "1";  // false — no coercion
null == undefined; // true
null === undefined; // false
NaN === NaN; // false

    Always use === and !== unless you have a specific reason for loose equality.

    Concept 5: Nullish Coalescing (??)

    0 ?? 10;          // 0 (0 is not nullish)
"" ?? "default";  // "" (not nullish)
null ?? "default"; // "default"
undefined ?? 10;  // 10

    ?? only falls back on null or undefined — unlike ||, which falls back on any falsy value.

    Concept 6: Optional Chaining (?.)

    user?.profile?.name;       // property access
arr?.[0];                  // element access
fn?.();                    // function call

    Returns undefined instead of throwing when a reference is null or undefined.

    Concept 7: Logical Assignment Operators (ES2021)

    a ||= b;  // a = a || b (assign if a is falsy)
a &&= b;  // a = a && b (assign if a is truthy)
a ??= b;  // a = a ?? b (assign if a is nullish)

    These are short-circuiting — the right side is only evaluated if needed.

    Concept 8: Exponentiation (**)

    2 ** 3;    // 8
2 ** 3 ** 2; // 512 (right-associative)

    Equivalent to Math.pow() but with operator syntax.

    Concept 9: Bitwise Operators and 32-bit Semantics

    JavaScript bitwise operators convert operands to 32-bit signed integers, perform the operation, and return a 32-bit signed integer.

    0xFFFFFFFF | 0; // -1 (32-bit signed)
(1 << 31) >>> 0; // 2147483648 (unsigned interpretation)

    Concept 10: The in Operator

    "name" in { name: "Ada" };  // true
"toString" in {};           // true (inherited)

    Checks the entire prototype chain, not just own properties.

    Concept 11: instanceof

    [] instanceof Array;      // true
[] instanceof Object;     // true (Array inherits from Object)
new Date() instanceof Date; // true

    Checks the prototype chain of the constructor.

    Concept 12: typeof

    typeof 42;        // "number"
typeof "hi";      // "string"
typeof null;      // "object" (historical bug)
typeof undefined; // "undefined"
typeof Symbol();  // "symbol"
typeof 42n;       // "bigint"
typeof function(){}; // "function"

    Concept 13: void

    void 0; // undefined — evaluates expression and returns undefined

    Used in contexts where undefined could be shadowed.

    Concept 14: delete

    const obj = { a: 1, b: 2 };
delete obj.a; // true
console.log(obj); // { b: 2 }

    delete removes own properties. It does not delete variables or inherited properties.

    Concept 15: Pipeline Operator (|>, ES2026)

    const result = input
    |> validate
    |> normalize
    |> transform;

// Reads as: transform(normalize(validate(input)))

    The pipeline operator is Stage 4 as of ES2026 and is supported in evergreen browsers behind a flag. It works with await for async pipelines.

    Concept 16: Operator Overloading via Symbol.toPrimitive

    Objects can customize how they behave with operators by implementing Symbol.toPrimitive:

    const obj = {
    [Symbol.toPrimitive](hint) {
        return hint === "number" ? 42 : "hello";
    },
};
+obj;   // 42
`${obj}`; // "hello"

    Concept 17: Falsy Values and Logical Operators

    false && anything    → false
true || anything     → true
false || anything    → anything
true && anything     → anything
null ?? anything     → anything
0 ?? anything        → 0

    Concept 18: The Comma Operator

    for (let i = 0, j = 10; i < j; i++, j--) { /* ... */ }

    Evaluates left to right, returns the last value. Rarely used elsewhere.

    6. How It Works

    Step-by-Step: Operator Evaluation

    1.  Parser reads expression.
    │
    ▼
2.  Operator precedence determines grouping.
    │
    ▼
3.  Operands are evaluated left to right.
    │
    ▼
4.  Operator is applied per its semantics.
    │
    ▼
5.  Result is produced.

    Step-by-Step: Short-Circuit Evaluation

    1.  `a && b` is evaluated.
    │
    ▼
2.  `a` is evaluated and coerced to boolean.
    │
    ▼
3.  If `a` is falsy → return `a`, skip `b`.
    │
    ▼
4.  If `a` is truthy → evaluate and return `b`.

    Step-by-Step: Optional Chaining

    1.  `obj?.prop` is evaluated.
    │
    ▼
2.  `obj` is evaluated.
    │
    ▼
3.  If `obj` is null or undefined → return `undefined`, skip rest.
    │
    ▼
4.  Otherwise → access `prop`.

    Step-by-Step: Pipeline Operator

    1.  `input |> fn` is evaluated.
    │
    ▼
2.  `input` is evaluated.
    │
    ▼
3.  `fn` is resolved.
    │
    ▼
4.  `fn(input)` is called.
    │
    ▼
5.  Result becomes the input to the next stage.

    Step-by-Step: Assignment

    1.  Right-hand side is evaluated.
    │
    ▼
2.  Left-hand side reference is resolved.
    │
    ▼
3.  Value is written to the reference.
    │
    ▼
4.  The assigned value is returned.

    7. Internal Architecture / Under the Hood

    How the Engine Evaluates Operators

    V8's bytecode interpreter (Ignition) compiles operators into bytecode instructions. The JIT compilers (Sparkplug, Maglev, TurboFan) optimize hot operator sequences using type feedback from previous executions.

    function add(a, b) { return a + b; }
add(1, 2); // feedback: both numbers → fast integer add
add("a", "b"); // guard fails → deoptimize → interpreter handles strings

    Operator Overloading via Symbol.toPrimitive

    When an operator needs a primitive value, it calls ToPrimitive on the operand. If the object has Symbol.toPrimitive, it is called with a hint ("number", "string", or "default").

    Type Coercion in Operators

    Operator Coercion
    + If either operand is string → string concatenation; else numeric addition
    - * / % Both operands → numbers
    == Complex coercion rules
    === No coercion
    && \|\| ! Boolean conversion
    ?? No coercion — only nullish check
    Bitwise Operands → 32-bit integers

    The ?? Operator in the Spec

    ?? is defined to check IsNullish — a value is nullish if it is null or undefined. Unlike ||, it does not coerce to boolean.

    Pipeline Operator Implementation

    The pipeline operator is syntactically transformed during parsing. x |> f becomes f(x) in the AST. It is a syntax-level construct, not a runtime function.

    Memory and Performance

    • SMI arithmetic — small integers operate directly on the stack.
    • HeapNumber — boxed doubles for larger numbers.
    • String concatenation — V8 uses ConsString for lazy concatenation.
    • Bitwise operations — always 32-bit; results are SMIs.

    8. Lifecycle / Workflow

    Expression Evaluation Lifecycle

    Parse → Precedence grouping → Operand evaluation → Operator application → Result

    Assignment Lifecycle

    RHS evaluated → LHS reference resolved → Value written → Value returned

    Short-Circuit Lifecycle

    Left operand evaluated → Truthiness checked → Short-circuit or continue

    Pipeline Lifecycle

    Stage 1 → Stage 2 → Stage 3 → ... → Final result

    Optimization Lifecycle

    Operator observed → Type feedback recorded → JIT compiles speculatively → Guard inserted → Deoptimize on mismatch

    Example 1: Arithmetic and Assignment

    let total = 0;

    Example 2: Comparison and Logical

console.log(status); // "adult"

    Example 4: Logical Assignment

    const config = {};
config.timeout ??= 5000;   // 5000 (was undefined)
config.retries ||= 3;      // 3 (was falsy)
config.debug &&= true;     // still undefined (debug was falsy)
console.log(config); // { timeout: 5000, retries: 3 }

    Example 5: Bitwise Operations

    const READ = 1;    // 001
const WRITE = 2;   // 010
const EXECUTE = 4; // 100

let permissions = READ | WRITE; // 011 = 3
const canRead = (permissions & READ) !== 0;   // true
const canExecute = (permissions & EXECUTE) !== 0; // false

permissions |= EXECUTE; // 111 = 7
console.log(permissions); // 7

    Example 6: Pipeline Operator (ES2026)

    const process = (input) =>
    input
        |> validate
        |> normalize
        |> transform
        |> save;

// Equivalent to:
const process = (input) => save(transform(normalize(validate(input))));

    With await:

    const result = await input
    |> validate
    |> await fetchDetails
    |> transform;

    Example 7: Operator Precedence

    2 + 3 * 4;     // 14 (not 20)
(2 + 3) * 4;   // 20
2 ** 3 ** 2;   // 512 (right-associative)
10 - 3 - 2;    // 5 (left-associative)

    Example 8: in and instanceof

    const obj = { name: "Ada" };
console.log("name" in obj);       // true
console.log("toString" in obj);   // true (inherited)
console.log([] instanceof Array); // true
console.log([] instanceof Object);// true

    11. Best Practices

    1. Use === and !== by default. Why: avoids coercion surprises.
    2. Use ?? instead of || for defaults. Why: respects 0, "", false.
    3. Use ?. for deep property access. Why: prevents TypeError on null/undefined.
    4. Use parentheses to clarify precedence. Why: readability beats cleverness.
    5. Use logical assignment (??=, ||=, &&=) for concise conditional assignment. Why: avoids redundant variable references.
    6. Avoid bitwise operators unless working with binary data. Why: 32-bit semantics are surprising.
    7. Use Number.isNaN() not isNaN(). Why: global isNaN coerces.
    8. Use Array.isArray() not instanceof. Why: works across realms.
    9. Avoid ++ and -- in complex expressions. Why: side effects are hard to track.
    10. Use the pipeline operator for data transformations. Why: reads left to right (ES2026).
    11. Never use delete on arrays. Why: leaves holes; use splice or filter.
    12. Use in for property existence, not value checks. Why: in checks keys.
    13. Understand short-circuiting. Why: it is a control flow mechanism, not just optimization.
    14. Use void 0 for undefined when it might be shadowed. Why: undefined is not a reserved word.
    15. Enable ESLint rules: eqeqeq, no-implicit-coercion. Why: enforces safe operator usage.

    12. Common Mistakes

    ❌ Mistake: Using == Instead of ===

    0 == "";    // true
0 == false; // true
"" == false; // true

    ✅ Correct: Always use ===.

    ❌ Mistake: Using || for Defaults

    const count = userCount || 10; // if userCount is 0, becomes 10!

    ✅ Correct:

    const count = userCount ?? 10; // only null/undefined become 10

    ❌ Mistake: Forgetting Operator Precedence

    2 + 3 * 4; // 14, not 20

    ✅ Correct: Use parentheses for clarity.

    ❌ Mistake: Misusing ++/--

    let a = 1;
const b = a++ + ++a; // confusing!

    ✅ Correct: Use separate statements.

    ❌ Mistake: delete on Arrays

    const arr = [1, 2, 3];
delete arr[1]; // leaves [1, <empty>, 3]

    ✅ Correct: Use arr.splice(1, 1) or arr.filter().

    ❌ Mistake: typeof null

    typeof null; // "object" — NOT "null"

    ✅ Correct: value === null.

    ❌ Mistake: Bitwise Operators on Large Numbers

    2 ** 31 | 0; // -2147483648 (32-bit wrap)

    ✅ Correct: Use Number or BigInt for large values.

    ❌ Mistake: Chaining ?? Without Parentheses

    a ?? b || c; // SyntaxError — cannot mix ?? with || without parentheses

    ✅ Correct:

    (a ?? b) || c; // or a ?? (b || c)

    ❌ Mistake: in on Primitives

    "length" in "hello"; // TypeError

    ✅ Correct: in works on objects only.

    ❌ Mistake: Overlooking + Coercion

    1 + "2";   // "12" (not 3)
"3" * "4"; // 12 (coerces to numbers)

    ✅ Correct: Be explicit — Number(x) + Number(y).

    13. Performance Considerations

    • SMI arithmetic — fastest; small integers stored inline.
    • HeapNumber — boxed doubles; slower.
    • String concatenation — ConsString lazy evaluation; flattening costs.
    • Bitwise ops — always 32-bit; fast but limited range.
    • Short-circuiting — avoids unnecessary work.
    • Pipeline operator — syntactic sugar; no runtime overhead.
    • ?? vs || — similar performance; ?? avoids coercion.
    • ?. — slight overhead for null checks; negligible.
    • Monomorphic operators — JIT optimizes stable types best.

    Performance Tips

    1. Keep operand types stable in hot loops.
    2. Avoid mixing types in arithmetic.
    3. Use ?? over || when defaults matter.
    4. Use bitwise operators only for binary data.
    5. Prefer explicit conversion over implicit coercion.
    6. Profile with --trace-opt / --trace-deopt.

    14. Security Considerations

    Prototype Pollution via in and instanceof

    Malicious objects can manipulate prototype chains. Validate inputs and use Object.create(null) for dictionaries.

    Coercion Attacks

    if (input == 1) { /* bypassed with "1" or [1] */ }

    Defense: Use ===.

    Symbol.toPrimitive Abuse

    Objects can override operator behavior. Never trust objects from untrusted sources without validation.

    delete and Hidden Classes

    delete destroys hidden class optimizations — a performance (and potentially DoS) vector in hot loops.

    Bitwise Overflow

    Bitwise operations wrap at 32 bits — unexpected results can cause logic bugs with security implications.

    Pipeline Operator and Injection

    When using |> with user-controlled functions, ensure the pipeline stages are trusted. The operator itself is safe, but the functions it invokes may not be.

    15. Debugging Tips

    • console.log both operands and result — see coercion in action.
    • Use typeof and Object.prototype.toString.call() — verify types.
    • Chrome DevTools Console — type-aware autocomplete for operators.
    • debugger; — pause and inspect operand values.
    • ESLint eqeqeq — flags ==.
    • ESLint no-implicit-coercion — flags !!x, +x, etc.
    • Number.isNaN() — reliable NaN check.
    • Parenthesize — when precedence is unclear, add parentheses.

    16. When to Use

    Operator When to Use
    === Always — unless loose equality is intentional
    ?? Default values — respects 0, "", false
    ?. Safe deep property access
    && / \|\| Guard clauses, short-circuit logic
    ??= Conditional assignment when nullish
    \|> Data pipelines (ES2026)
    Bitwise Binary data, flags, performance-critical code
    in Property existence checks
    instanceof Type checking (with caution)
    typeof Primitive type detection
    delete Removing own properties (not arrays)

    17. When Not to Use

    • == — never; use ===.
    • || for defaults — when 0, "", or false are valid.
    • delete on arrays — use splice/filter.
    • Bitwise operators — unless working with binary data.
    • instanceof — across realms; use Array.isArray().
    • void — rarely needed; use undefined.
    • Comma operator — outside for headers.
    • ++/-- — in complex expressions.

    19. Did You Know?

    • typeof null === "object" is a bug from 1995 that will never be fixed.
    • NaN !== NaN is the only value not equal to itself.
    • The pipeline operator |> reached Stage 4 in ES2026 — it is now supported in evergreen browsers behind a flag.
    • Optional chaining (?.) and nullish coalescing (??) were both introduced in ES2020.
    • Logical assignment operators (??=, ||=, &&=) were added in ES2021.
    • Exponentiation (**) was added in ES2016 — it replaced Math.pow().
    • Bitwise operators in JavaScript operate on 32-bit signed integers.
    • void 0 is a common idiom for undefined because undefined is not a reserved word.
    • delete on arrays leaves holes — it does not shift elements.
    • Short-circuit evaluation is not just optimization — it is a control flow mechanism.
    • ?? cannot be mixed with || or && without parentheses — it is a syntax error.
    • in checks the prototype chain, not just own properties.
    • instanceof fails across realms — use Array.isArray() for arrays.
    • ES2026 also added Error.isError(), Math.sumPrecise(), and Uint8Array base64/hex methods.
