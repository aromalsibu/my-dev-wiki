# GeneratedDatabase

`GeneratedDatabase` is the base class that all Drift database classes inherit from.

---

# What is it?

`GeneratedDatabase` is the core database class provided by Drift. It contains the functionality needed to communicate with SQLite, manage tables, execute queries, run transactions, and handle schema migrations.

When you create your own database class, you don't extend `GeneratedDatabase` directly. Instead, you extend a generated class (such as `_$AppDatabase`), which itself extends `GeneratedDatabase`.

```text
GeneratedDatabase
        ▲
        │
_$AppDatabase   (Generated)
        ▲
        │
AppDatabase     (Your Class)
```

Most developers never interact with `GeneratedDatabase` directly, but every Drift database is built upon it.

---

# Why does it exist?

Every database needs common functionality, such as:

* Opening connections
* Executing SQL
* Managing transactions
* Registering tables
* Running migrations
* Watching streams

Instead of generating all of this code for every project, Drift places this shared functionality inside `GeneratedDatabase`.

Your generated database class inherits these capabilities automatically.

---

# Syntax

## Creating a Database

```dart
@DriftDatabase(tables: [Users])
class AppDatabase extends _$AppDatabase {
  AppDatabase(super.executor);

  @override
  int get schemaVersion => 1;
}
```

Explanation:

* `_$AppDatabase` is generated by Drift.
* `_$AppDatabase` extends `GeneratedDatabase`.
* Your `AppDatabase` inherits all database functionality through the generated class.

---

## Inheritance Chain

```text
GeneratedDatabase
        │
        ▼
_$AppDatabase
        │
        ▼
AppDatabase
```

Explanation:

* `GeneratedDatabase` provides the core implementation.
* `_$AppDatabase` connects your tables and generated APIs.
* `AppDatabase` is where you add your own database-specific methods.

---

# Mental Model

Think of `GeneratedDatabase` as the engine of your database.

```text
                GeneratedDatabase
         (Database Engine)
                     │
      ┌──────────────┼──────────────┐
      │              │              │
 Transactions   Query Engine   Table Registry
      │              │              │
      └──────────────┼──────────────┘
                     │
             _$AppDatabase
                     │
              Your AppDatabase
```

Your database class doesn't implement these features itself—it inherits them from `GeneratedDatabase`.

# Examples

## Simple Example

A minimal database.

```dart
@DriftDatabase(tables: [Users])
class AppDatabase extends _$AppDatabase {
  AppDatabase(super.executor);

  @override
  int get schemaVersion => 1;
}
```

Explanation:

Although you never mention `GeneratedDatabase`, your database still gains:

* Query APIs
* CRUD operations
* Transactions
* Streams
* Migration support

---

## Real-World Example

You can add your own methods alongside the inherited functionality.

```dart
@DriftDatabase(tables: [Users])
class AppDatabase extends _$AppDatabase {
  AppDatabase(super.executor);

  @override
  int get schemaVersion => 1;

  Future<List<User>> activeUsers() {
    return (select(users)
          ..where((u) => u.isActive.equals(true)))
        .get();
  }
}
```

Explanation:

* `select()` is available because your database ultimately inherits from `GeneratedDatabase`.
* You can combine generated APIs with your own helper methods.

# When to Use

You typically don't use `GeneratedDatabase` directly.

Instead, you'll work with your own database class, which automatically inherits from it.

Understanding `GeneratedDatabase` is useful when:

* Learning how Drift is structured.
* Reading generated code.
* Understanding where database APIs come from.

---

# When NOT to Use

Don't write:

```dart
class AppDatabase extends GeneratedDatabase
```

Drift generates an intermediate class (`_$AppDatabase`) that should always be used instead.

---

# Best Practices

* Always extend the generated database class.
* Let Drift manage the inheritance hierarchy.
* Keep custom database methods small and focused.
* Move larger query logic into DAOs.

---

# Common Mistakes

## Extending the wrong class

**Wrong**

```dart
class AppDatabase extends GeneratedDatabase
```

Explanation:

* This bypasses Drift's generated implementation and won't work correctly.

**Correct**

```dart
class AppDatabase extends _$AppDatabase
```

Explanation:

* The generated class includes all table registrations and generated APIs.

---

## Modifying generated classes

**Wrong**

Editing:

```text
app_database.g.dart
```

Explanation:

* Generated files are overwritten every time code generation runs.

**Correct**

Modify only your own database class and regenerate the code when needed.

---

## Assuming `GeneratedDatabase` contains your tables

**Wrong**

Thinking `GeneratedDatabase` knows about your application's tables.

Explanation:

* `GeneratedDatabase` is generic.
* Your generated subclass (`_$AppDatabase`) registers the specific tables defined in your project.

**Correct**

Let Drift generate the subclass that connects your tables to the database engine.

# Summary

`GeneratedDatabase` is the foundation of every Drift database. It provides the core database functionality, while Drift generates a subclass that connects your tables and queries. Your own database class extends this generated class, giving you a clean, type-safe interface for interacting with SQLite without dealing with the underlying implementation.
