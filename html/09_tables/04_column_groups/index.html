    Chapter: Column Groups

    1. Overview

    Definition

    Column groups are a structural feature of HTML tables that allow you to define and style whole columns — or groups of columns — without targeting individual cells. They are created using two elements:

    • <colgroup> – a container for one or more column definitions.
    • <col> – a single column (or span of columns) within a <colgroup>.

    Together, they let authors:

    • Define column widths.
    • Apply styling to entire columns.
    • Group columns logically for styling or scripting.
    • Provide structure before the table's rows are parsed.

    Column groups are a presentational and structural feature. They do not contain data — they only describe the columns of the table. The <colgroup> element is a child of <table>, appearing after <caption> and before <thead>, <tbody>, <tfoot>, and <tr>.

    Example: 

    <table>
    <caption>Quarterly Sales</caption>
    <colgroup>
        <col class="label-column">
        <col span="3" class="data-columns">
    </colgroup>
    <thead>
        <tr>
            <th scope="col">Quarter</th>
            <th scope="col">Q1</th>
            <th scope="col">Q2</th>
            <th scope="col">Q3</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <th scope="row">2026</th>
            <td>$15k</td>
            <td>$18k</td>
            <td>$20k</td>
        </tr>
    </tbody>
</table>

    Purpose

    Column groups serve several essential purposes:

    • Column styling – apply styles to entire columns without repeating them on each cell.
    • Column widths – define widths for columns, improving layout predictability.
    • Semantic grouping – group related columns (e.g., "Q1, Q2, Q3" under "Sales").
    • Performance – reduce the number of CSS rules needed.
    • Accessibility – provide structural hints to assistive technologies.
    • Maintainability – centralise column definitions in one place.
    • Table layout – with table-layout: fixed, column widths are respected.

    Where It Fits

    The <colgroup> element is a child of <table>, positioned after <caption> (if present) and before <thead>, <tbody>, <tfoot>, and <tr>. It can contain:

    • <col> elements (one per column or group of columns).

    The <col> element is an empty (void) element — it has no closing tag and no content.

    <table>
    <caption>...</caption>     ← First
    <colgroup>                 ← Second
        <col>
        <col>
    </colgroup>
    <thead>...</thead>         ← After colgroup
    <tbody>...</tbody>
</table>

    2. Why It Exists

    The Problem

    In a table with many columns, applying styles to individual cells is repetitive and error-prone:

    /* Repetitive and error-prone */
td:nth-child(1) { width: 100px; background: #f0f0f0; }
td:nth-child(2) { width: 80px; background: #f8f9fa; }
td:nth-child(3) { width: 80px; background: #f8f9fa; }
td:nth-child(4) { width: 80px; background: #f8f9fa; }

    This approach has several problems:

    • Repetition – each column must be targeted individually.
    • Fragility – adding or removing a column breaks the nth-child selectors.
    • No semantic grouping – related columns (e.g., Q1, Q2, Q3) can't be styled as a unit.
    • Performance – many selectors increase CSS complexity.
    • Column widths – without <colgroup>, column widths are determined by content, which can lead to uneven layouts.

    Previous Limitations

    Limitation Consequence
    No column grouping Each column must be styled individually.
    nth-child fragility Adding a column breaks selectors.
    No group styling Related columns can't be styled as a unit.
    Unpredictable widths Column widths depend on content.
    No structural hints Assistive technologies lack column info.

    Why Column Groups Were Introduced

    The <colgroup> and <col> elements were introduced in HTML 4.0 (1997) as part of the table model. They were designed to:

    • Define column widths – with width attribute (now CSS).
    • Group columns – for styling and semantics.
    • Provide structure – before rows are parsed.
    • Improve performance – fewer CSS rules needed.

    The <col> element's span attribute allows one <col> to represent multiple columns, reducing markup.

    The width attribute on <col> was the original way to set column widths, but it's now obsolete. Use CSS width instead.

    4. Mental Model

    The "Column Template" Analogy

    Think of <colgroup> as a column template for the table. Just as a spreadsheet has column headers (A, B, C) with properties (width, format), <colgroup> defines those properties once, and they apply to the entire column below.

    The "CSS Grid Template" Analogy

    Think of <colgroup> as the grid template for a CSS Grid. Just as grid-template-columns: 1fr 3fr defines the width of columns, <colgroup> with <col> elements defines the columns of a table. The template is applied before the content.

    The "Skeleton" Analogy

    A table's structure can be thought of as a skeleton:

    • <colgroup> – the spine (column structure).
    • <thead> – the top of the skeleton (header rows).
    • <tbody> – the body (data rows).
    • <tfoot> – the bottom (footer rows).

    The <colgroup> is defined first, so the table "knows" its column structure before filling in the rows.

    The "Blueprint" Analogy

    The <colgroup> is like a blueprint for the table's columns. It specifies how many columns there are, how wide they are, and how they're styled. The rows fill in the blueprint with data.

    5. Core Concepts

    Concept 1: Position in the Table

    The <colgroup> element must appear after <caption> and before <thead>, <tbody>, <tfoot>, and <tr>.

    <table>
    <caption>Title</caption>
    <colgroup>
        <col>
    </colgroup>
    <thead>...</thead>
    <tbody>...</tbody>
</table>

    Why: The browser needs column definitions before it processes rows.

    Concept 2: <col> Is an Empty Element

    The <col> element is empty (void) — it has no closing tag and no content.

    <!-- Correct -->
<col>
<col span="2">

<!-- Incorrect -->
<col></col>
<col span="2"></col>

    Concept 3: The span Attribute

    The span attribute on <col> defines how many columns the <col> element applies to.

    <colgroup>
    <col span="2">  <!-- Applies to 2 columns -->
    <col>            <!-- Applies to 1 column -->
</colgroup>

    The total span of all <col> elements should equal the number of columns in the table.

    Concept 4: Number of Columns

    The number of columns in the table is determined by:

    1. The sum of span attributes on <col> elements.
    2. The maximum number of cells in any row (if <colgroup> is absent or incomplete).

    Best practice: Ensure the <colgroup> matches the actual number of columns.

    Concept 5: Styling Columns

    Only a limited set of CSS properties apply to <col>:

    • background (and its longhands).
    • border (in border-collapse: collapse mode).
    • width.
    • visibility.

    Other properties (e.g., color, font-size, text-align) do not apply to <col> — they must be applied to cells.

    col {
    background: #f0f0f0; /* Works */
    width: 100px;         /* Works */
    color: red;           /* Does NOT work on <col> */
}

    Why: The <col> element has no content of its own — it's a column definition. Only properties that affect the column's box (background, border, width) apply.

    Concept 6: Column Widths

    Column widths can be set with CSS width on <col>:

    col {
    width: 150px;
}

    Or inline:

    <col style="width: 150px;">

    Note: Column widths are respected more predictably with table-layout: fixed.

    Concept 7: table-layout: fixed

    With table-layout: fixed, column widths are determined by:

    1. The first row's cell widths.
    2. The <col> widths.
    3. The table's width.
    table {
    table-layout: fixed;
    width: 100%;
}

    Benefit: Faster rendering and predictable column widths.

    Concept 8: Multiple <colgroup> Elements

    A table can have multiple <colgroup> elements:

    <colgroup>
    <col class="label">
</colgroup>
<colgroup>
    <col class="data">
    <col class="data">
</colgroup>

    Use case: Grouping columns into logical sections.

    Concept 9: <colgroup> with span

    A <colgroup> element can have its own span attribute (without <col> children):

    <colgroup span="3"></colgroup>

    This defines a column group spanning 3 columns, but without individual column definitions.

    Rarely used — most authors use <col> children.

    Concept 10: Accessibility

    The <colgroup> and <col> elements are not announced by screen readers — they are purely presentational. However, they contribute to the table's structure.

    Best practice: Don't rely on <colgroup> for accessibility. Use <th>, scope, and headers for header–cell associations.

    Concept 11: SEO

    Search engines use the table's structure (rows, cells, headers) for indexing. <colgroup> is presentational and does not directly affect SEO.

    Concept 12: Performance

    Column groups improve performance by:

    • Reducing the number of CSS rules needed.
    • Providing column widths upfront (with table-layout: fixed).
    • Allowing the browser to lay out columns before parsing rows.

    Concept 13: The width Attribute (Obsolete)

    The width attribute on <col> was used in HTML4 but is obsolete in HTML5. Use CSS width instead.

    Concept 14: Styling Limitations

    Only a limited set of CSS properties apply to <col>:

    Property Applies?
    background Yes
    border Yes (with border-collapse: collapse)
    width Yes
    visibility Yes
    color No
    font-* No
    text-align No
    padding No (partially)

    Why: The <col> element has no content — it only affects the column's box.

    Concept 15: Column Borders

    With border-collapse: collapse, borders on <col> are applied to the cells in that column.

    table {
    border-collapse: collapse;
}
col {
    border-left: 2px solid #3498db;
}

    Note: Border behavior varies across browsers. Test carefully.

    6. How It Works

    Step-by-Step: Browser Processing of <colgroup>

    1.  The tokenizer encounters a `<colgroup>` tag.
    │
    ▼
2.  It creates a DOM node for the column group.
    │
    ▼
3.  It processes each `<col>` child:
    │   ├── Creates a `<col>` node.
    │   ├── Reads the `span` attribute (default 1).
    │   └── Applies CSS styles.
    │
    ▼
4.  When the closing tag is encountered (or the next section starts), the group is closed.
    │
    ▼
5.  The browser computes the table's column structure:
    │   ├── Determines the total number of columns.
    │   ├── Assigns widths from `<col>` elements (if `table-layout: fixed`).
    │   └── Applies backgrounds and borders.
    │
    ▼
6.  The browser processes rows and cells.
    │
    ▼
7.  The table is rendered with the column styles.

    The Table Grid Algorithm

    The browser uses the following to determine column structure:

    1. Count the <col> elements and their span attributes.
    2. If the count is less than the actual number of columns, the remaining columns are implicit.
    3. If the count is more, the extra <col> elements are ignored.

    Best practice: Make the <colgroup> match the table's columns exactly.

    CSS Application

    Only certain CSS properties apply to <col>. The browser applies them to the column's box, which affects all cells in that column.

    Default User Agent Styles

    colgroup {
    display: table-column-group;
}

col {
    display: table-column;
}

    These values make the elements behave like table columns. They have no visual rendering of their own.

    Interaction with table-layout

    • table-layout: auto – column widths are determined by content; <col> widths are suggestions.
    • table-layout: fixed – column widths are determined by the first row and <col> widths; more predictable.

    7. Internal Architecture / Under the Hood

    The HTMLTableColElement Interface

    Both <colgroup> and <col> are represented by the HTMLTableColElement interface:

    Property Description
    span Reflects the span attribute.
    width Reflects the obsolete width attribute.
    align Obsolete.
    valign Obsolete.
    ch Obsolete.
    chOff Obsolete. 
    const col = document.querySelector('col');
console.log(col.span);  // 1
console.log(col.width); // "" (obsolete)

    The Table's cols Property (Not Standard)

    There is no standard cols property on <table> (unlike rows). To access columns, you query <col> elements directly.

    The Accessibility Mapping

    The <colgroup> and <col> elements are not exposed in the accessibility tree. They are purely presentational.

    Default User Agent Styles

    colgroup {
    display: table-column-group;
}

col {
    display: table-column;
}

    These display values make the elements part of the table's column structure.

    CSS Properties on <col>

    Only a subset of CSS properties apply to <col>:

    • background and its longhands.
    • border and its longhands (with border-collapse: collapse).
    • width.
    • visibility.

    Other properties are ignored because <col> has no content.

    Browser Support

    <colgroup> and <col> are supported in all modern browsers. The CSS properties that apply to <col> vary slightly, so test in your target browsers.

    8. Lifecycle / Workflow

    The Lifecycle of a Column Group

    1.  Author writes the `<colgroup>` and `<col>` elements.
    │   └── <colgroup><col class="label"><col span="3" class="data"></colgroup>
    │
    ▼
2.  File is deployed.
    │
    ▼
3.  Browser parses the document and creates the DOM.
    │   └── The `<colgroup>` and `<col>` nodes are created.
    │
    ▼
4.  The browser computes the column structure.
    │   └── Determines the number of columns.
    │
    ▼
5.  The browser applies CSS styles to the columns.
    │   └── Backgrounds, widths, borders.
    │
    ▼
6.  The table is rendered with the column styles.
    │
    ▼
7.  JavaScript may modify the columns dynamically.
    │   └── Adding/removing `<col>`, changing classes.
    │
    ▼
8.  When the page is unloaded, the elements are destroyed.

    Dynamic Modification

    // Change a column's width
const col = document.querySelector('col');
col.style.width = '200px';

// Add a new column definition
const colgroup = document.querySelector('colgroup');
const newCol = document.createElement('col');
newCol.className = 'new-column';
colgroup.appendChild(newCol);

    11. Best Practices

    1. Place <colgroup> after <caption> – before row groups and rows.

    2. Use one <col> per column – or use span for multiple columns.

    3. Ensure the total span matches the number of columns – mismatches cause layout issues.

    4. Use classes for styling – not inline styles.

    5. Use width in CSS – not the obsolete width attribute.

    6. Use table-layout: fixed – for predictable column widths.

    7. Only use supported CSS properties – background, border, width, visibility.

    8. Don't rely on <col> for text styling – use cell-level styles.

    9. Test in multiple browsers – <col> behavior varies.

    10. Use <colgroup> for semantic grouping – not just styling.

    11. Don't use <colgroup> for accessibility – use <th> and scope.

    12. Keep the column count consistent – don't have more or fewer <col> elements than columns.

    13. Use span to reduce markup – for repeated columns.

    14. Consider visibility: collapse – for hiding columns (with caution).

    15. Test with border-collapse: collapse – for column borders.

    16. Use nth-child selectors as a fallback – if <col> styling doesn't work.

    17. Validate your HTML – check for correct structure.

    18. Document your column conventions – in a style guide.

    19. Use <colgroup> with table-layout: fixed – for performance.

    20. Keep the number of columns reasonable – too many columns are hard to read.

    12. Common Mistakes

    ❌ Mistake: Placing <colgroup> After <thead>

    <table>
    <thead>...</thead>
    <colgroup><col></colgroup>
</table>
    Why it's wrong: <colgroup> must come before row groups.

    ✅ Correct: 

    <table>
    <colgroup><col></colgroup>
    <thead>...</thead>
</table>

    ❌ Mistake: Using <col> with a Closing Tag

    <col></col>
    Why it's wrong: <col> is a void element.

    ✅ Correct: 

    <col>

    ❌ Mistake: Applying Unsupported CSS to <col>

    col {
    color: red;
    font-weight: bold;
    text-align: center;
}
    Why it's wrong: These properties don't apply to <col>.

    ✅ Correct: Apply to cells: 

    td, th {
    color: red;
}

    ❌ Mistake: <col> Span Mismatch

    <table>
    <colgroup>
        <col span="2">
    </colgroup>
    <tr>
        <td>1</td>
        <td>2</td>
        <td>3</td>  <!-- Third column not covered -->
    </tr>
</table>
    Why it's wrong: The span doesn't match the number of columns.

    ✅ Correct: 

    <colgroup>
    <col span="3">
</colgroup>

    ❌ Mistake: Using the Obsolete width Attribute

    <col width="100">
    Why it's wrong: The width attribute is obsolete.

    ✅ Correct: 

    <col style="width: 100px;">

    ❌ Mistake: No <colgroup> When Column Styling Is Needed

    <table>
    <tr>
        <td style="background: #f0f0f0;">...</td>
        <td style="background: #f0f0f0;">...</td>
        <td style="background: #f0f0f0;">...</td>
    </tr>
</table>
    Why it's wrong: Repetitive and error-prone.

    ✅ Correct: 

    <table>
    <colgroup>
        <col style="background: #f0f0f0;">
        <col style="background: #f0f0f0;">
        <col style="background: #f0f0f0;">
    </colgroup>
    <tr>...</tr>
</table>

    ❌ Mistake: Using <colgroup> for Accessibility

    <colgroup>
    <col aria-label="Name">
</colgroup>
    Why it's wrong: <col> is not announced by screen readers.

    ✅ Correct: Use <th scope="col"> for accessibility.

    ❌ Mistake: Adding More <col> Elements Than Columns

    <colgroup>
    <col>
    <col>
    <col>
    <col>
    <col>
</colgroup>
<table>
    <tr><td>1</td><td>2</td><td>3</td></tr>
</table>
    Why it's wrong: Extra <col> elements are ignored, causing confusion.

    ✅ Correct: Match the number of columns.

    ❌ Mistake: Forgetting to Close <colgroup>

    <colgroup>
    <col>
    <thead>...</thead>
    Why it's wrong: Missing </colgroup> can cause parsing issues.

    ✅ Correct: 

    <colgroup>
    <col>
</colgroup>
<thead>...</thead>

    ❌ Mistake: Using <colgroup> Outside <table>

    <colgroup><col></colgroup>
<table>...</table>
    Why it's wrong: <colgroup> must be inside <table>.

    ✅ Correct: 

    <table>
    <colgroup><col></colgroup>
</table>

    13. Performance Considerations

    • Faster rendering – <colgroup> provides column widths upfront, especially with table-layout: fixed.
    • Fewer CSS rules – column styles are applied once instead of per-cell.
    • Reduced DOM size – <col> elements are lightweight.
    • Table layout – table-layout: fixed with <col> widths is the fastest table layout algorithm.
    • Browser support – well-supported; no performance concerns.

    Performance Tips

    1. Use table-layout: fixed – for faster rendering.
    2. Define widths in <col> – not in cells.
    3. Use span – to reduce the number of <col> elements.
    4. Use classes – instead of inline styles.
    5. Keep the number of columns reasonable – very wide tables are slow.

    14. Security Considerations

    • XSS – if column classes or styles contain user-generated data, sanitize it.
    • innerHTML – avoid using innerHTML with user input; use textContent or a sanitizer.
    • Injection – never insert user input into <col> attributes without escaping.
    • No direct security implications – <colgroup> and <col> are not security risks.

    Security Best Practices

    1. Sanitize user input – before inserting into table attributes.
    2. Use textContent – instead of innerHTML for text.
    3. Validate structure – ensure <col> elements match the column count.
    4. Use CSP – to restrict inline scripts and styles.

    15. Debugging Tips

    • DevTools Elements panel – inspect <colgroup> and <col> elements.
    • Computed styles – check display: table-column-group and table-column.
    • Check column widths – with table-layout: fixed, verify the widths.
    • Console – use document.querySelectorAll('col') to count columns.
    • Validator – check for correct structure.
    • Test in multiple browsers – column styling varies.
    • Test with CSS disabled – ensure the table still makes sense.

    16. When to Use

    • For column styling – highlighting, zebra striping.
    • For column widths – predictable layouts.
    • For grouping columns – logical sections.
    • For performance – faster rendering with table-layout: fixed.
    • For financial tables – right-aligned amount columns.
    • For schedule tables – time column vs. day columns.

    17. When Not to Use

    • For accessibility – use <th> and scope.
    • For content styling – use cell-level styles.
    • For layout – use CSS Grid or Flexbox.
    • For small tables – the overhead may not be worth it.
    • For unpredictable column counts – if columns change dynamically.

    19. Did You Know?

    • The <colgroup> and <col> elements were introduced in HTML 4.0 (1997) as part of the table model.

    • The <col> element is a void element — it has no closing tag and no content.

    • Only a limited set of CSS properties apply to <col>: background, border, width, and visibility.

    • Other properties (e.g., color, font-size, text-align) do not apply to <col> — they must be applied to cells.

    • With table-layout: fixed, column widths are determined by the <col> elements and the first row.

    • table-layout: fixed is the fastest table layout algorithm.

    • The span attribute on <col> defines how many columns the <col> applies to.

    • A table can have multiple <colgroup> elements.

    • The width attribute on <col> is obsolete in HTML5 — use CSS width instead.

    • <colgroup> is not announced by screen readers — it's purely presentational.

    • <col> styling for background works in all modern browsers.

    • Border styling on <col> requires border-collapse: collapse.

    • visibility: collapse on <col> hides the column in most browsers, but behavior varies.

    • The HTMLTableColElement interface represents both <colgroup> and <col>.

    • The display: table-column-group and display: table-column values make the elements part of the table structure.

    • Zebra-striped columns are a common use case for <colgroup>.

    • Fixed-width columns are easier to achieve with <colgroup> and table-layout: fixed.

    • The nth-child selector can be used as a fallback for column styling.

    • Column groups improve performance by reducing the number of CSS rules needed.

    • Best practice: use <colgroup> for column styling and widths, but use <th> and scope for accessibility.

    • Common mistakes include placing <colgroup> after <thead>, using <col> with a closing tag, and applying unsupported CSS to <col>.

    • Following best practices for column groups leads to more maintainable, performant tables.

    • <colgroup> must appear after <caption> and before row groups and rows.
    • Only a limited set of CSS properties apply to <col>: background, border, width, visibility.
    • Use table-layout: fixed for predictable column widths and faster rendering.
    • Best practices: place <colgroup> correctly, use classes for styling, match the column count, and use <col> for presentational purposes only.
    • Common mistakes include placing <colgroup> after <thead>, using <col> with a closing tag, applying unsupported CSS, and span mismatches.
    • Column groups are essential for column styling, column widths, and performance in tables.
    • They are a small but powerful feature of HTML tables.
