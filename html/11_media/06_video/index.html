    Chapter: Video

    1. Overview

    Definition

    The <video> element is an HTML element that embeds video content directly into a web page. It allows developers to play video files — movies, tutorials, video calls, animations, and more — natively in the browser, without requiring third-party plugins like Adobe Flash, QuickTime, or Silverlight. The element provides built-in playback controls, supports multiple video formats through child <source> elements, and exposes a rich JavaScript API for programmatic control.

    The <video> element is a media element, alongside <audio>. It is embedded content and phrasing content. It can appear anywhere phrasing content is accepted — inside <p>, <figure>, <div>, <li>, <td>, and more. It is one of the most important additions of HTML5, eliminating the plugin dependency that plagued the early web and enabling video to become a first-class citizen of the web platform.

    Example: 

    <video controls width="640" height="360" poster="thumbnail.jpg">
    <source src="movie.mp4" type="video/mp4">
    <source src="movie.webm" type="video/webm">
    <track kind="subtitles" src="subtitles.vtt" srclang="en" label="English">
    <p>Your browser does not support the video element.</p>
</video>

    Purpose

    The <video> element serves several essential purposes:

    • Native video playback – no plugins required.
    • Multiple formats – fallback via <source> elements.
    • Playback controls – play, pause, volume, seek, fullscreen, picture-in-picture.
    • Programmatic control – play, pause, seek, volume via JavaScript.
    • Events – play, pause, ended, timeupdate, volumechange, etc.
    • Accessibility – captions, subtitles, descriptions, keyboard-accessible controls.
    • Streaming – supports streaming video (via HTTP range requests).
    • Adaptive streaming – via Media Source Extensions (MSE) and HLS/DASH.
    • Picture-in-Picture – native PiP support.
    • Fullscreen – native fullscreen support.

    Where It Fits

    The <video> element is embedded content and phrasing content. It is a block-level element when display: block is applied, but by default it is inline. It can be styled with CSS and controlled with JavaScript. It is the primary delivery mechanism for video on the web, from short clips to feature-length films, from live streams to interactive experiences.

    2. Why It Exists

    The Problem

    Before HTML5, playing video on the web required plugins. The dominant plugin was Adobe Flash, but others included QuickTime, RealPlayer, Windows Media Player, and Silverlight. Each plugin:

    • Required a separate installation.
    • Had its own security vulnerabilities.
    • Was proprietary and platform-specific.
    • Was often buggy and resource-heavy.
    • Was inaccessible to assistive technologies.
    • Didn't work on mobile devices (notably, iOS never supported Flash).
    • Consumed excessive CPU and battery.

    This created a fragmented, fragile, and insecure ecosystem. Developers had to encode video in multiple formats for multiple plugins, and users had to install and maintain them. Video on the web was a second-class experience compared to native apps.

    Previous Limitations

    Limitation Consequence
    Plugin dependency Users had to install Flash/QuickTime
    Security vulnerabilities Flash was a constant attack target
    Platform-specific Not available on all devices (iOS)
    Inaccessible Screen readers couldn't access plugins
    Battery drain Flash consumed excessive CPU
    No standardization Each plugin had its own API
    No mobile support Flash never worked on iOS
    No native API Developers couldn't control playback easily
    No fullscreen/PiP Limited playback experience
    No adaptive streaming Same video for all connections

    Why the <video> Element Was Introduced

    The <video> element was introduced in HTML5 (drafted in 2008, standardized in 2014) as part of the effort to eliminate plugin dependency. It was designed to:

    • Provide native video – no plugin required.
    • Support multiple formats – with <source> fallbacks.
    • Expose a JavaScript API – play, pause, seek, volume.
    • Fire events – for synchronization with other content.
    • Be accessible – native controls are keyboard-accessible; captions via <track>.
    • Work on mobile – iOS and Android support <video> natively.
    • Support captions – via <track> (WebVTT).
    • Be standardized – W3C/WHATWG specification.
    • Enable adaptive streaming – via MSE (Media Source Extensions).
    • Enable DRM – via EME (Encrypted Media Extensions).

    The <video> element is part of the broader HTML5 media effort, alongside <audio>, MSE, and EME. Together, they replaced Flash and made rich media a first-class citizen of the web.

    4. Mental Model

    The "Movie Theater" Analogy

    Think of <video> as a movie theater embedded in the page. It has:

    • The screen – the video itself.
    • The stage – the <video> element.
    • The control booth – the JavaScript API.
    • The audience – the user.
    • The program – the video file.

    The controls attribute opens the control booth to the user; without it, you build your own.

    The "Loading a Movie" Mental Model

    Loading video is like loading a movie on a streaming service:

    1. Poster – the thumbnail before playback.
    2. Preload – whether to fetch the video upfront or on demand.
    3. Fetch – the browser downloads the video bytes.
    4. Decode – the browser decodes the compressed video.
    5. Render – the browser paints frames to the screen.
    6. Play – the browser outputs audio and video.

    Each step is controllable via attributes and the JS API.

    The "Multiple Format" Mental Model

    Different browsers support different video formats. The <source> elements are candidates — the browser picks the first format it can play. This is exactly the same pattern as <picture> for images and <audio> for audio.

    The "Autoplay is Hostile" Mental Model

    Browsers deliberately block autoplay because it's hostile to users — unexpected video (especially with sound) is jarring and wastes data. To autoplay, the video must be:

    • Muted (muted), OR
    • Triggered by user interaction (a click, tap, or key press).

    Rule: Never autoplay unmuted video without user consent.

    The "Plugin-Free" Mental Model

    Before HTML5, video required a plugin. Now it's native. This is a huge win for:

    • Users – no plugin to install.
    • Developers – simpler API, better compatibility.
    • Security – no plugin vulnerabilities.
    • Mobile – native support on iOS and Android.
    • Accessibility – native controls are accessible.

    The "Adaptive Streaming" Mental Model

    Modern video delivery isn't just a single file — it's an adaptive stream that adjusts quality based on network conditions. This is achieved via:

    • MSE (Media Source Extensions) – allows JavaScript to feed video segments.
    • HLS (HTTP Live Streaming) – Apple's adaptive streaming protocol.
    • DASH (Dynamic Adaptive Streaming over HTTP) – open standard.
    • HLS.js and dash.js – JavaScript libraries for browsers without native support.

    The <video> element is the player; MSE/HLS/DASH are the delivery mechanisms.

    5. Core Concepts

    Concept 1: The <video> Element

    The <video> element is the container for video content. It can have:

    • src attribute (alternative to <source>).
    • <source> children (candidates).
    • <track> children (captions).
    • Fallback content (shown if video isn't supported).

    Concept 2: The <source> Element

    The <source> element provides a candidate video source:

    <source src="video.mp4" type="video/mp4">
    Attribute Purpose
    src The video URL
    type MIME type (e.g., video/mp4)

    The browser evaluates sources in order and picks the first supported one.

    Concept 3: The <track> Element

    The <track> element provides timed text tracks (captions, subtitles, descriptions, chapters):

    <track kind="captions" src="captions.vtt" srclang="en" label="English" default>
    Attribute Purpose
    kind captions, subtitles, descriptions, chapters, metadata
    src The WebVTT file URL
    srclang Language of the track
    label User-visible label
    default Enable by default

    Concept 4: Video Formats

    Format MIME Type Extension Browser Support
    MP4 (H.264) video/mp4 .mp4 All modern browsers
    WebM (VP8/VP9) video/webm .webm Chrome, Firefox, Edge
    Ogg (Theora) video/ogg .ogv Chrome, Firefox, Edge
    MOV (H.264) video/mp4 .mov Safari, Chrome
    AV1 video/mp4 .mp4 Chrome, Firefox, Edge
    HEVC/H.265 video/mp4 .mp4 Safari, Edge

    Best practice: Provide MP4 (H.264) for universal support, and WebM (VP9) for open-source browsers.

    Concept 5: The controls Attribute

    The controls boolean attribute shows the browser's native playback controls:

    <video controls>

    Controls typically include:

    • Play/pause.
    • Seek bar.
    • Volume.
    • Time display.
    • Fullscreen.
    • Picture-in-Picture.
    • Playback speed.
    • Captions/subtitles.

    Concept 6: The autoplay Attribute

    The autoplay boolean attribute tells the browser to start playing automatically:

    <video autoplay muted playsinline>

    Important: Browsers block autoplay unless:

    • The video is muted, OR
    • The user has interacted with the page.

    Best practice: Never autoplay unmuted video.

    Concept 7: The loop Attribute

    The loop boolean attribute restarts the video when it ends:

    <video loop>

    Concept 8: The muted Attribute

    The muted boolean attribute starts the video muted:

    <video muted>

    Concept 9: The preload Attribute

    The preload attribute tells the browser how much to preload:

    Value Behaviour
    none Don't preload
    metadata Preload metadata only (duration, dimensions)
    auto Let the browser decide

    Best practice: Use metadata for most cases.

    Concept 10: The poster Attribute

    The poster attribute specifies a thumbnail image shown before playback:

    <video poster="thumbnail.jpg">

    Why: Improves visual experience; shows content before the video loads.

    Concept 11: The width and height Attributes

    Set the video dimensions:

    <video width="640" height="360">

    Why: Prevents layout shift (CLS) while the video loads.

    Concept 12: The playsinline Attribute

    The playsinline attribute tells iOS Safari to play the video inline (not fullscreen):

    <video playsinline>

    Why: On iOS, videos autoplay fullscreen by default. playsinline keeps them in place.

    Concept 13: The crossorigin Attribute

    The crossorigin attribute controls CORS for cross-origin video:

    <video crossorigin="anonymous">

    Use case: When the video is used with Canvas or Web Audio API.

    The <track> element provides captions and subtitles:

    • Captions – for deaf and hard-of-hearing users (includes sound effects).
    • Subtitles – for translation of dialogue.
    • Descriptions – audio descriptions for blind users.
    • Chapters – navigation markers.

    • Native controls are keyboard-accessible.
    • <track> provides captions.
    • Transcripts should be provided.
    • aria-label for custom players.
    • Keyboard shortcuts for custom controls.

    Concept 19: Format Fallback

    The browser evaluates <source> elements in order:

    <source src="video.mp4" type="video/mp4">
<source src="video.webm" type="video/webm">

    If MP4 is supported, it plays. If not, WebM is tried.

    Concept 20: Adaptive Streaming

    • HLS – Apple's protocol; .m3u8 playlist.
    • DASH – open standard; .mpd manifest.
    • MSE – Media Source Extensions; JS API for feeding segments.
    • HLS.js – polyfill for browsers without native HLS.

    Concept 22: Fullscreen

    video.requestFullscreen();

    Native fullscreen expands the video.

    Concept 23: Video and CORS

    Cross-origin video requires CORS headers if:

    • Used with Canvas or Web Audio API.
    • Used with crossorigin attribute.

    Concept 24: Video and Mobile

    On mobile:

    • Video does not autoplay without user interaction (or must be muted).
    • playsinline keeps video inline on iOS.
    • Video may pause when the screen locks.
    • Video may continue in the background if the browser allows.

    Concept 25: Video and SEO

    • Search engines index video metadata (title, description).
    • Provide meaningful titles and descriptions.
    • Use structured data (VideoObject) for rich results.

    Format Selection Algorithm

    1. For each <source> in order:
    2. Read type.
    3. Call canPlayType(type).
    4. If supported, use this source.
    5. If none is supported, the <video> element shows fallback content.

    The play() Promise

    video.play()
    .then(() => console.log('Playing'))
    .catch(error => console.error('Failed:', error));

    Note: play() returns a Promise that rejects if autoplay is blocked.

    Event Sequence

    1. loadstart – loading begins.
    2. durationchange – duration known.
    3. loadedmetadata – metadata loaded.
    4. loadeddata – first frame loaded.
    5. canplay – can start playing.
    6. canplaythrough – can play without buffering.
    7. play – playback starts.
    8. playing – playback actually begins.
    9. timeupdate – current time updates.
    10. pause – playback paused.
    11. ended – playback ended.

    Accessibility Tree

    The <video> element is exposed as:

    • role: application or group (varies).
    • name: from aria-label, title, or fallback content.

    Note: Screen readers may treat <video> differently. Captions are essential.

    display: inline;
}

    display: none;
}

    The default size is typically 300 × 150 pixels when controls are visible.

    11. Best Practices

    1. Always include controls – unless building custom controls.
    2. Provide multiple formats – MP4 (H.264) and WebM.
    3. Use preload="metadata" – for most cases.
    4. Never autoplay unmuted – it's hostile.
    5. Use playsinline – for iOS inline playback.
    6. Provide a poster – for visual context before playback.
    7. Set width/height – prevent layout shift.
    8. Provide captions – for accessibility (WCAG 1.2.2).
    9. Provide audio descriptions – for blind users (WCAG 1.2.5).
    10. Provide transcripts – for SEO and accessibility.
    11. Label custom controls – with aria-label.
    12. Support keyboard – Space to play/pause, arrows for seek.
    13. Show loading state – with loadstart, canplay.
    14. Handle errors – listen for error events.
    15. Use crossorigin – if using Canvas/Web Audio.
    16. Test on mobile – iOS and Android behave differently.
    17. Test with screen readers – ensure controls are announced.
    18. Compress video – use appropriate bitrate and codec.
    19. Use a CDN – for faster delivery.
    20. Consider adaptive streaming – for long videos.

    <video>
    <source src="video.mp4" type="video/mp4">
</video>

    Why it's wrong: No way for users to play/pause.

    ✅ Correct: 

    <video controls>
    <source src="video.mp4" type="video/mp4">
</video>

    ❌ Mistake: Single Format

    <video controls src="video.webm">

    Why it's wrong: Safari doesn't support WebM.

    <source src="video.mp4" type="video/mp4">

    ✅ Correct: 

    <video controls poster="poster.jpg">
    <source src="video.mp4" type="video/mp4">
</video>

    ❌ Mistake: No Captions

    <video controls>
    <source src="video.mp4" type="video/mp4">
</video>

    Why it's wrong: Deaf and hard-of-hearing users can't access the content. WCAG violation.

    ✅ Correct: 

    <video controls>
    <source src="video.mp4" type="video/mp4">

</video>

    ❌ Mistake: No playsinline

    <video autoplay muted>
    <source src="video.mp4" type="video/mp4">
</video>

    Why it's wrong: iOS forces fullscreen playback.

    ✅ Correct: 

    <video autoplay muted playsinline>
    <source src="video.mp4" type="video/mp4">
</video>

    ❌ Mistake: No preload

    <video controls>
    <source src="large-video.mp4" type="video/mp4">

    ✅ Correct: 

    <video controls preload="metadata">

    ❌ Mistake: Missing type

    <video controls>
    <source src="video.mp4">
</video>

    Why it's wrong: Browser must download the file to determine the format.

    ✅ Correct: 

    <video controls>
    <source src="video.mp4" type="video/mp4">

    <video controls>

    video.play();

    13. Performance Considerations

    • File size – compress video; use appropriate bitrate and codec.
    • Format – MP4 (H.264) is universal; WebM (VP9) is smaller.
    • Preload – metadata avoids downloading the entire file.
    • Streaming – HTTP range requests enable seeking.
    • Adaptive streaming – HLS/DASH adjust quality to network.
    • CDN – for global delivery.
    • Caching – long cache lifetimes.
    • Bitrate – 2–5 Mbps for 720p, 5–10 Mbps for 1080p.
    • Resolution – 720p is often sufficient; 1080p for high-quality.
    • Frame rate – 24–30 fps for most content.
    • Lazy loading – don't load until needed.
    • Poster – reduces initial visual load.

    Performance Tips

    1. Compress video – use FFmpeg or HandBrake.
    2. Use preload="metadata".
    3. Use a CDN.
    4. Cache aggressively.
    5. Consider adaptive streaming for long videos.
    6. Use poster for visual context.
    7. Avoid autoplay.
    8. Monitor bandwidth.

    14. Security Considerations

    • CORS – use crossorigin when needed.
    • HTTPS – required for secure playback.
    • Content-Security-Policy – restrict media sources with media-src.
    • Autoplay abuse – avoid unexpected video.
    • User privacy – video may reveal user behavior.
    • Malicious files – validate video files.
    • DRM – use EME for protected content.

    Security Best Practices

    1. Use HTTPS – for all video.
    2. Set media-src in CSP.
    3. Validate uploads – file type, size, content.
    4. Avoid autoplay.
    5. Use crossorigin – for Canvas/Web Audio.
    6. Sanitize metadata – EXIF and ID3 tags.

    19. Did You Know?

    • The <video> element was introduced in HTML5 (drafted 2008, standardized 2014).

    • It replaced Adobe Flash and other plugins for video playback.

    • iOS never supported Flash — this was a major driver for native video.

    • The <video> element cannot autoplay unmuted in most browsers.

    • The preload="metadata" value loads only the duration and dimensions, not the entire file.

    • MP4 (H.264) is universally supported; WebM (VP9) is open-source.

    • Safari only supports MP4 (H.264) and HEVC.

    • WebVTT is the standard format for captions and subtitles.

    • The <track> element supports captions, subtitles, descriptions, chapters, and metadata.

    • Picture-in-Picture is natively supported in Chrome, Edge, and Safari.

    • Fullscreen is natively supported in all modern browsers.

    • The playsinline attribute is required for inline playback on iOS.

    • MSE (Media Source Extensions) enables adaptive streaming (HLS, DASH).

    • EME (Encrypted Media Extensions) enables DRM.

    • canPlayType() returns "probably", "maybe", or "".

    • The play() method returns a Promise (unlike pause()).

    • The play() Promise rejects if autoplay is blocked.

    • currentSrc tells you which source the browser chose.

    • videoWidth and videoHeight give the intrinsic dimensions.

    • readyState values: HAVE_NOTHING, HAVE_METADATA, HAVE_CURRENT_DATA, HAVE_FUTURE_DATA, HAVE_ENOUGH_DATA.

    • networkState values: NETWORK_EMPTY, NETWORK_IDLE, NETWORK_LOADING, NETWORK_NO_SOURCE.

    • Accessibility: captions are required for WCAG 1.2.2; audio descriptions for 1.2.5.

    • Best practices: controls, multiple formats, preload="metadata", playsinline, poster, captions.

    • Common mistakes: autoplay unmuted, no controls, single format, no captions, no playsinline.

    • Following best practices for video leads to accessible, performant, and pleasant experiences.

    • The <video> element embeds video content natively in HTML.
    • It replaced Adobe Flash and other plugins for video playback.
    • Attributes: controls, autoplay, loop, muted, preload, poster, width, height, playsinline, crossorigin.
    • Child elements: <source> (candidate sources), <track> (captions).
    • JavaScript API: play(), pause(), currentTime, duration, volume, playbackRate, muted, loop, videoWidth, videoHeight, requestFullscreen(), requestPictureInPicture().
    • Events: play, pause, ended, timeupdate, loadedmetadata, canplay, volumechange, seeking, error.
    • Best practices: controls, multiple formats, preload="metadata", never autoplay unmuted, playsinline, poster, captions.
    • Common mistakes include autoplay unmuted, no controls, single format, missing playsinline, and no captions.
