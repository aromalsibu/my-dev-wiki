    Chapter: Picture Element

    1. Overview

    Definition

    The <picture> element is an HTML container that allows developers to provide multiple image sources for a single <img> element, enabling the browser to choose the most appropriate image based on the user's device, viewport, screen resolution, format support, and other conditions. Unlike srcset on <img> — which is for resolution switching (same image at different sizes) — <picture> is for art direction (different images or crops for different layouts) and format fallback (serving modern formats like AVIF and WebP with fallbacks for older browsers).

    The <picture> element is a wrapper that contains zero or more <source> elements followed by exactly one <img> element. The <img> is required — it serves as the fallback for browsers that don't support <picture> and as the element that carries the alt text, width, height, and other attributes. The <source> elements provide alternative sources with conditions (media, type) that the browser evaluates in order.

    Example: 

    <picture>
    <source srcset="image.avif" type="image/avif">
    <source srcset="image.webp" type="image/webp">
    <img src="image.jpg" alt="A scenic mountain view" width="800" height="600">
</picture>

    Purpose

    The <picture> element serves several essential purposes:

    • Art direction – serve different crops or compositions for different viewports.
    • Format fallback – serve modern formats (AVIF, WebP) with fallbacks for older browsers.
    • Resolution switching – combine with srcset for multiple resolutions.
    • Dark mode images – serve different images for light and dark color schemes.
    • Localization – serve different images for different languages or regions.
    • Responsive design – adapt images to the layout.
    • Performance – serve the smallest suitable image.
    • Accessibility – preserve alt text on the <img> element.

    Where It Fits

    The <picture> element is phrasing content and embedded content. It is an inline element that can appear anywhere phrasing content is accepted — inside <p>, <figure>, <a>, <div>, <li>, <td>, and more. It is part of the responsive images system, alongside srcset and sizes on <img>.

    Responsive Images
│
├── srcset + sizes on <img>        → Resolution switching
└── <picture> + <source>           → Art direction + format fallback
    ├── <source media="...">       → Art direction
    ├── <source type="...">        → Format fallback
    ├── <source srcset="..." sizes="..."> → Resolution switching
    └── <img>                      → Fallback (required)

    2. Why It Exists

    The Problem

    Before <picture>, developers faced three impossible problems:

    Problem 1: Art Direction

    A wide landscape image that looks great on a desktop monitor might crop poorly on a narrow phone. A hero image with text on the left might have the text cut off on mobile. Developers needed to serve different images for different layouts — but <img> only allowed one src and srcset only allowed different sizes of the same image.

    Problem 2: Format Fallback

    New image formats (WebP, then AVIF) offered dramatically better compression than JPEG and PNG. But not all browsers supported them. Developers needed to serve modern formats to browsers that supported them, and fallbacks to those that didn't. srcset couldn't do this — it had no mechanism for format detection.

    Problem 3: Conditional Images

    Developers wanted to serve different images based on:

    • Color scheme (light vs. dark mode).
    • Language or region.
    • User preferences.
    • Media type (print vs. screen).

    srcset couldn't handle these conditions — it only handled resolution and viewport.

    Previous Limitations

    Limitation Consequence
    No art direction Poor crops on different viewports
    No format fallback Couldn't use modern formats
    No conditional images Same image for all contexts
    Manual JavaScript solutions Complex, fragile, often inaccessible
    srcset alone Only resolution switching
    CSS background-image No alt text, no accessibility

    Why <picture> Was Introduced

    The <picture> element was introduced through the Responsive Images Community Group (RICG) and became part of HTML5. It was designed to solve art direction and format fallback — the two problems srcset couldn't solve.

    The design was inspired by the <video> and <audio> elements, which already used <source> children to provide multiple media sources with fallbacks. The <picture> element adopted the same pattern:

    <picture>
    <source ...>
    <source ...>
    <img ...>  <!-- Required fallback -->
</picture>

    <picture> enables:

    • Art direction – different images for different layouts via media.
    • Format fallback – modern formats with fallbacks via type.
    • Resolution switching – combined with srcset and sizes.
    • Conditional images – via media queries (prefers-color-scheme, orientation, etc.).
    • Accessibility – the <img> carries alt text.
    • No JavaScript – the browser handles selection natively.
    • Progressive enhancement – works even in older browsers.

    The <picture> element is one of the most important additions to HTML for modern responsive design.

    4. Mental Model

    The "Menu with Courses" Analogy

    Think of <picture> as a restaurant menu with multiple courses:

    • The <img> is the "house special" — always available.
    • Each <source> is a different course — appetizer, main, dessert.
    • media is the "available at this time" condition.
    • type is the "available in this kitchen" condition.
    • The browser is the waiter who picks the best course for you.

    The "Travel Itinerary" Analogy

    A <picture> element is like a travel itinerary with multiple options:

    • If it's raining, take the indoor tour.
    • If it's sunny, take the outdoor tour.
    • If you're in Paris, take the French tour.
    • Otherwise, take the default tour.

    The browser picks the first option whose conditions match.

    The "Playlist" Analogy

    <source> elements are like songs on a playlist. The browser plays the first one it can (supported format, matching media query). If it can't play any, it falls back to the <img> — like a default track.

    The "If-Else" Mental Model

    The <picture> element is essentially a conditional chain:

    if (browser supports AVIF) → use AVIF
else if (browser supports WebP) → use WebP
else if (viewport ≥ 1200px) → use wide.jpg
else if (viewport ≥ 800px) → use medium.jpg
else → use fallback.jpg (the <img>)

    The browser evaluates conditions in order and uses the first match.

    The "Art Direction vs. Resolution Switching" Mental Model

    Problem Solution Element
    Same image, different sizes srcset + sizes <img>
    Different image, different contexts media <picture> + <source>
    Modern format with fallback type <picture> + <source>

    Rule: Use srcset on <img> for resolution switching; use <picture> for art direction and format fallback.

    5. Core Concepts

    Concept 1: The <picture> Element

    The <picture> element is a wrapper. It has no attributes of its own and no rendering. Its only purpose is to contain <source> elements and one <img>.

    <picture>
    <!-- sources -->
    <img src="..." alt="...">
</picture>

    Concept 2: The <source> Element

    The <source> element provides a candidate source with optional conditions:

    Attribute Purpose
    srcset Candidate image(s)
    sizes Display sizes for srcset
    media Media query condition
    type MIME type condition
    width Intrinsic width (rarely used)
    height Intrinsic height (rarely used)

    Concept 3: The <img> Element (Required)

    The <img> is required inside <picture>. It serves as:

    • The fallback for browsers that don't support <picture>.
    • The accessible element — carries the alt text.
    • The styled element — carries class, id, width, height, loading, etc.
    <img src="fallback.jpg" alt="A photo" width="800" height="600" loading="lazy">

    Concept 4: The Selection Algorithm

    The browser evaluates <source> elements in document order:

    1. For each <source>:
    2. If type is present and unsupported → skip.
    3. If media is present and doesn't match → skip.
    4. Otherwise, use this <source>.
    5. If no <source> matches → use the <img>.

    Important: The first matching <source> wins, not the best one.

    Concept 5: media for Art Direction

    The media attribute accepts any valid media query:

    <source media="(min-width: 1200px)" srcset="wide.jpg">
<source media="(orientation: landscape)" srcset="landscape.jpg">
<source media="(prefers-color-scheme: dark)" srcset="dark.jpg">
<source media="print" srcset="print.png">

    Concept 6: type for Format Fallback

    The type attribute specifies the MIME type:

    <source srcset="image.avif" type="image/avif">
<source srcset="image.webp" type="image/webp">

    The browser checks if it supports the type before using the source.

    Concept 7: Order of <source> Elements

    Order matters:

    1. Format fallback – put modern formats first (AVIF, then WebP, then JPEG).
    2. Art direction – put more specific media queries first.
    3. Resolution switching – put larger images first (browser picks).

    Best practice: 

    <picture>
    <!-- Most specific conditions first -->
    <source media="(min-width: 1200px)" srcset="wide.avif" type="image/avif">
    <source media="(min-width: 1200px)" srcset="wide.jpg" type="image/jpeg">
    <source media="(min-width: 800px)" srcset="medium.avif" type="image/avif">
    <source media="(min-width: 800px)" srcset="medium.jpg" type="image/jpeg">
    <img src="small.jpg" alt="A photo">
</picture>

    Concept 8: <source> Cannot Be Empty

    Each <source> must have a srcset (or src) attribute. A <source> without a source is invalid.

    Concept 9: The <img> Carries the Semantics

    The <img> inside <picture> is the actual element that:

    • Carries the alt text.
    • Carries width, height, class, id.
    • Is exposed to the accessibility tree.
    • Can be styled with CSS.

    The <source> elements are invisible — they only provide candidates.

    Concept 10: <picture> Does Not Appear in the Accessibility Tree

    The <picture> element is not exposed to the accessibility tree. Only the <img> is. This is why the <img> must carry the alt text.

    Concept 11: Format Support Detection

    The browser checks type against its supported formats. It does not download the image to check — it trusts the type attribute.

    Concept 12: Combining srcset and media

    A <source> can have both media and srcset with sizes:

    <source media="(min-width: 1200px)"
        srcset="wide-1200.jpg 1200w, wide-2400.jpg 2400w"
        sizes="100vw">

    Concept 13: The <picture> Element and CSS

    The <picture> element has no rendering — it's a transparent wrapper. CSS properties like width, height, display should be applied to the <img>, not <picture>.

    /* Bad */
picture { width: 100%; }

/* Good */
picture img { width: 100%; height: auto; }

    Concept 14: <picture> and loading

    The loading attribute goes on the <img>, not <picture> or <source>:

    <picture>
    <source srcset="image.avif" type="image/avif">
    <img src="image.jpg" alt="A photo" loading="lazy">
</picture>

    Concept 15: <picture> and fetchpriority

    The fetchpriority attribute goes on the <img>:

    <picture>
    <source srcset="hero.avif" type="image/avif">
    <img src="hero.jpg" alt="Hero" fetchpriority="high">
</picture>

    Concept 16: <picture> and Preload

    Preloading a <picture> source requires imagesrcset and imagesizes:

    <link rel="preload"
      as="image"
      href="hero.jpg"
      imagesrcset="hero.avif"
      imagesizes="100vw"
      type="image/avif">

    Note: Preloading <picture> sources is complex; test carefully.

    Concept 17: <picture> and Dark Mode

    <picture>
    <source srcset="logo-dark.svg" media="(prefers-color-scheme: dark)">
    <img src="logo-light.svg" alt="Company logo" width="200" height="60">
</picture>

    Use case: Different logos for light and dark themes.

    Concept 18: <picture> and Print

    <picture>
    <source srcset="logo-print.png" media="print">
    <img src="logo-screen.png" alt="Company logo" width="200" height="60">
</picture>

    Use case: High-resolution print versions.

    Concept 19: <picture> and <figure>

    <figure>
    <picture>
        <source srcset="image.avif" type="image/avif">
        <img src="image.jpg" alt="A scenic view" width="800" height="600">
    </picture>
    <figcaption>Figure 1: A scenic view.</figcaption>
</figure>

    Use case: Combining art direction with captions.

    Concept 20: Browser Support

    Feature Support
    <picture> All modern browsers
    <source> in <picture> All modern browsers
    media All modern browsers
    type All modern browsers
    AVIF Chrome, Firefox, Safari (2022+)
    WebP All modern browsers
    prefers-color-scheme All modern browsers

    Concept 21: Fallback for Older Browsers

    Older browsers that don't support <picture> will:

    • Ignore the <source> elements.
    • Render the <img> inside.

    This is progressive enhancement — the <img> is the fallback.

    Concept 22: The srcset Attribute in <source>

    The srcset in <source> uses the same syntax as <img srcset>:

    <source srcset="image-400.jpg 400w, image-800.jpg 800w" sizes="100vw">

    Concept 23: <picture> vs. <img srcset>

    Aspect <picture> <img srcset>
    Art direction Yes No
    Format fallback Yes No
    Resolution switching Yes Yes
    Required <img> Yes N/A
    Complexity Higher Lower
    Use case Different images Same image, different sizes

    Concept 24: <picture> and SEO

    • Search engines index the <img> and its alt.
    • The <source> elements are not indexed.
    • Use meaningful alt text on the <img>.

    Concept 25: <picture> and Accessibility

    • The <img> carries the alt text.
    • The <picture> element is not exposed.
    • Screen readers announce the <img> with its alt.
    • Ensure the alt text describes the image in all contexts.

    6. How It Works

    Step-by-Step: Browser Processing a <picture>

    1.  The parser encounters a `<picture>` element.
    │
    ▼
2.  It creates a DOM node for the picture.
    │
    ▼
3.  It processes each `<source>` child:
    │   ├── Creates a source node.
    │   └── Reads `srcset`, `sizes`, `media`, `type`.
    │
    ▼
4.  It processes the `<img>` child:
    │   ├── Creates an img node.
    │   └── Reads `src`, `alt`, `width`, `height`, etc.
    │
    ▼
5.  When the closing tag is encountered, the picture is closed.
    │
    ▼
6.  The browser evaluates the sources in order:
    │   ├── For each `<source>`:
    │   │   ├── If `type` is present and unsupported → skip.
    │   │   ├── If `media` is present and doesn't match → skip.
    │   │   └── Otherwise, use this source.
    │   └── If no source matches, use the `<img>`.
    │
    ▼
7.  The browser resolves the chosen source's `srcset` and `sizes`:
    │   └── Selects the best candidate based on viewport and DPR.
    │
    ▼
8.  The browser fetches the chosen image.
    │
    ▼
9.  The browser decodes and paints the image.
    │
    ▼
10. The `<img>` element exposes the chosen URL via `currentSrc`.

    The <picture> Selection Algorithm

    For each <source> in document order:
    If source.type is present:
        If browser doesn't support source.type → skip
    If source.media is present:
        If media query doesn't match → skip
    Use this <source> (break)

If no <source> matched:
    Use the <img>

    The srcset Selection (Within a Chosen <source>)

    1. Parse srcset candidates.
    2. Evaluate sizes to get display width.
    3. Multiply by DPR to get required width.
    4. Choose the smallest candidate ≥ required width.

    The currentSrc Property

    const img = document.querySelector('picture img');
console.log(img.currentSrc); // The URL actually used

    This tells you which source the browser chose.

    The Accessibility Tree

    • <picture> is not exposed.
    • <source> elements are not exposed.
    • <img> is exposed with its alt, width, height.

    Default User Agent Styles

    picture {
    display: inline;
}

    No visual rendering. The <img> inside is rendered normally.

    Fallback Behaviour

    If a browser doesn't support <picture>:

    • It ignores <source> elements.
    • It renders the <img> inside.

    This is why the <img> is required and must have a valid src.

    7. Internal Architecture / Under the Hood

    The HTMLPictureElement Interface

    Property Description
    (none) No specific properties

    The <picture> element has no properties of its own. It's a transparent wrapper.

    The HTMLSourceElement Interface

    Property Description
    src The src attribute
    srcset The srcset attribute
    sizes The sizes attribute
    media The media attribute
    type The type attribute
    width The width attribute
    height The height attribute

    The HTMLImageElement (Inside <picture>)

    The <img> inside <picture> behaves exactly like a normal <img>:

    Property Description
    src Fallback URL
    srcset Candidates
    sizes Sizes
    currentSrc The URL actually used
    alt Alternative text
    width Display width
    height Display height
    naturalWidth Intrinsic width
    naturalHeight Intrinsic height
    loading lazy or eager
    fetchPriority Fetch priority

    The Selection Algorithm in Detail

    The HTML spec defines the algorithm:

    1. Let picture be the <picture> element.
    2. Let img be the <img> child.
    3. For each child of picture in order:
    4. If the child is a <source>:
      • If type is present and unsupported → continue.
      • If media is present and doesn't match → continue.
      • Let selectedSource be this source.
      • Break.
    5. If selectedSource is set:
    6. Use its srcset and sizes.
    7. Else:
    8. Use the img's src, srcset, and sizes.

    The currentSrc Algorithm

    After selection, currentSrc is set to the chosen URL. If the <img>'s src was used, currentSrc equals src.

    The type Support Check

    The browser checks type against its list of supported MIME types. This is a synchronous check — no network request is made.

    The media Match

    The browser evaluates the media query against the current environment (viewport, orientation, color scheme, etc.). This is a synchronous check.

    Browser Differences

    Browser <picture> Support AVIF Support
    Chrome Yes Yes
    Firefox Yes Yes (2021+)
    Safari Yes Yes (2022+)
    Edge Yes Yes

    The <source> Element and <picture> vs. <video>

    The <source> element is used in both <picture> and <video>/<audio>, but the attributes differ:

    • <picture>: srcset, sizes, media, type.
    • <video>: src, type, media.

    Fallback for <picture>-Unaware Browsers

    Older browsers (IE 11 and earlier) ignore <picture> and <source>, rendering only the <img>. This is the intended fallback.

    │
    ▼
7.  Browser fetches the chosen image.
    │
    ▼
8.  Browser decodes and paints the image.
    │
    ▼
9.  `<img>` `load` event fires.
    │
    ▼
10. `currentSrc` is set to the chosen URL.
    │
    ▼
11. If the environment changes (resize, color scheme), the browser may re-evaluate.

    Re-evaluation on Environment Change

    When the viewport resizes or the color scheme changes, the browser:

    1. Re-evaluates the <source> elements.
    2. May choose a different source.
    3. Fetches the new image if not cached.

    Dynamic Modification

    const picture = document.querySelector('picture');
const img = picture.querySelector('img');
console.log(img.currentSrc); // The URL actually used

    Note: You cannot dynamically add or remove <source> elements and expect immediate re-evaluation in all browsers. Test carefully.

    11. Best Practices

    1. Always include <img> – it's required and the fallback.
    2. Put alt on the <img> – not on <source>.
    3. Put width/height on the <img> – prevent layout shift.
    4. Put loading on the <img> – not on <picture>.
    5. Put fetchpriority on the <img> – for LCP.
    6. Put class/id on the <img> – not on <picture>.
    7. Order sources by specificity – most specific first.
    8. Put modern formats first – AVIF, then WebP, then JPEG.
    9. Use type for format fallback – not media.
    10. Use media for art direction – not type.
    11. Combine type and media – for art direction + format.
    12. Combine srcset and sizes – within a <source>.
    13. Test in multiple browsers – especially Safari for AVIF.
    14. Test with JavaScript disabled – works natively.
    15. Don't use <picture> for resolution switching alone – use <img srcset>.
    16. Use <img srcset> for simpler cases – less complex.
    17. Preload hero images – with imagesrcset and imagesizes.
    18. Test on real devices – DPR and color scheme vary.
    19. Validate your HTML – check for required <img>.
    20. Document your strategy – in a style guide.

    12. Common Mistakes

    ❌ Mistake: Missing <img>

    <picture>
    <source srcset="image.avif" type="image/avif">
</picture>

    Why it's wrong: The <img> is required.

    ✅ Correct: 

    <picture>
    <source srcset="image.avif" type="image/avif">
    <img src="image.jpg" alt="A photo">
</picture>

    ❌ Mistake: alt on <source>

    <picture>
    <source srcset="image.avif" type="image/avif" alt="A photo">
    <img src="image.jpg">
</picture>

    Why it's wrong: alt belongs on the <img>, not <source>.

    ✅ Correct: 

    <picture>
    <source srcset="image.avif" type="image/avif">
    <img src="image.jpg" alt="A photo">
</picture>

    ❌ Mistake: Wrong Source Order

    <picture>
    <source srcset="image.jpg" type="image/jpeg">
    <source srcset="image.avif" type="image/avif">
    <img src="fallback.jpg" alt="A photo">
</picture>

    Why it's wrong: The browser always picks JPEG (first supported), never AVIF.

    ✅ Correct: Put AVIF first.

    ❌ Mistake: loading on <picture>

    <picture loading="lazy">
    <source srcset="image.avif" type="image/avif">
    <img src="image.jpg" alt="A photo">
</picture>

    Why it's wrong: loading belongs on the <img>.

    ✅ Correct: 

    <picture>
    <source srcset="image.avif" type="image/avif">
    <img src="image.jpg" alt="A photo" loading="lazy">
</picture>

    ❌ Mistake: Using <picture> for Resolution Switching Only

    <picture>
    <source srcset="image-400.jpg 400w, image-800.jpg 800w" sizes="100vw">
    <img src="image-800.jpg" alt="A photo">
</picture>

    Why it's wrong: This is simpler with <img srcset>.

    ✅ Correct: 

    <img src="image-800.jpg"
     srcset="image-400.jpg 400w, image-800.jpg 800w"
     sizes="100vw"
     alt="A photo">

    ❌ Mistake: media on <img>

    <picture>
    <img src="image.jpg" media="(min-width: 800px)" alt="A photo">
</picture>

    Why it's wrong: media is not valid on <img>.

    ✅ Correct: Use <source media="...">.

    ❌ Mistake: No type for Format Fallback

    <picture>
    <source srcset="image.avif">
    <source srcset="image.webp">
    <img src="image.jpg" alt="A photo">
</picture>

    Why it's wrong: Without type, the browser uses the first source regardless of format support.

    ✅ Correct: 

    <picture>
    <source srcset="image.avif" type="image/avif">
    <source srcset="image.webp" type="image/webp">
    <img src="image.jpg" alt="A photo">
</picture>

    ❌ Mistake: No width/height

    <picture>
    <source srcset="image.avif" type="image/avif">
    <img src="image.jpg" alt="A photo">
</picture>

    Why it's wrong: Causes layout shift (CLS).

    ✅ Correct: Add width and height to the <img>.

    ❌ Mistake: <source> Without srcset

    <picture>
    <source type="image/avif">
    <img src="image.jpg" alt="A photo">
</picture>

    Why it's wrong: A <source> must have a srcset (or src).

    ✅ Correct: 

    <picture>
    <source srcset="image.avif" type="image/avif">
    <img src="image.jpg" alt="A photo">
</picture>

    ❌ Mistake: Styling <picture> Instead of <img>

    picture {
    width: 100%;
    height: auto;
    border-radius: 8px;
}

    Why it's wrong: <picture> has no rendering; styles should be on the <img>.

    ✅ Correct: 

    picture img {
    width: 100%;
    height: auto;
    border-radius: 8px;
}

    ❌ Mistake: No Fallback for Older Browsers

    <picture>
    <source srcset="image.avif" type="image/avif">
</picture>

    Why it's wrong: Older browsers show nothing (no <img>).

    ✅ Correct: Always include <img>.

    ❌ Mistake: Nested <picture>

    <picture>
    <picture>
        <source srcset="image.avif" type="image/avif">
    </picture>
    <img src="image.jpg" alt="A photo">
</picture>

    Why it's wrong: <picture> cannot be nested.

    ✅ Correct: Use a single <picture>.

    13. Performance Considerations

    • Format fallback – AVIF can reduce file size by 50% vs. JPEG.
    • Art direction – serving mobile-optimized crops reduces bytes.
    • Lazy loading – defer off-screen images.
    • Preloading – hero images can be preloaded with imagesrcset.
    • Fetch priority – fetchpriority="high" for LCP images.
    • Decoding – decoding="async" for non-critical images.
    • Caching – each candidate is cached separately.
    • CDN – use a CDN for global delivery.

    Performance Tips

    1. Use AVIF – best compression.
    2. Use WebP – fallback for AVIF.
    3. Lazy load – below the fold.
    4. Preload – hero images.
    5. Use fetchpriority – for LCP.
    6. Set dimensions – prevent CLS.
    7. Compress images – before uploading.
    8. Use a CDN – for global delivery.

    14. Security Considerations

    • SVG injection – sanitize user-uploaded SVGs.
    • EXIF data – strip GPS coordinates.
    • Hotlinking – use a CDN or referrer policy.
    • Mixed content – HTTPS pages should load HTTPS images.
    • CSP – restrict image sources with img-src.
    • CORS – use crossorigin when needed.

    Security Best Practices

    1. Strip EXIF – for user-uploaded images.
    2. Sanitize SVG – remove scripts.
    3. Use HTTPS – for all images.
    4. Set img-src in CSP – restrict sources.
    5. Use referrerpolicy – for sensitive images.

    • DevTools Elements panel – inspect the <picture>, <source>, and <img>.

    16. When to Use

    • For format fallback – AVIF/WebP with JPEG fallback.
    • For art direction – different crops for different viewports.
    • For dark mode images – via prefers-color-scheme.
    • For print-specific images – via media="print".
    • For orientation-based images – via media="(orientation: ...)".
    • For combining multiple conditions – type + media + srcset.

    17. When Not to Use

    • For simple resolution switching – use <img srcset>.
    • For SVG – resolution-independent.
    • For background images – use CSS background-image.
    • For small icons – use SVG or icon fonts.
    • For a single image – no need for <picture>.

    19. Did You Know?

    • The <picture> element was introduced through the Responsive Images Community Group (RICG).

    • It was inspired by the <video> and <audio> elements, which also use <source> children.

    • The <img> inside <picture> is required — it's the fallback for browsers that don't support <picture>.

    • The <picture> element is not exposed to the accessibility tree — only the <img> is.

    • The order of <source> elements matters — the first matching one wins.

    • The type attribute is checked before the image is downloaded — the browser trusts the MIME type.

    • AVIF offers up to 50% better compression than JPEG.

    • WebP offers about 25–35% better compression than JPEG.

    • Safari added AVIF support in 2022 (Safari 16).

    • The <source> element is used in both <picture> and <video>/<audio>, but the attributes differ.

    • The media attribute accepts any valid CSS media query.

    • prefers-color-scheme is a media query for light/dark mode.

    • orientation is a media query for landscape/portrait.

    • Print-specific images can be served with media="print".

    • The <picture> element has no rendering — it's a transparent wrapper.

    • CSS should target the <img>, not the <picture>.

    • currentSrc tells you which image the browser chose.

    • srcset inside <source> uses the same syntax as <img srcset>.

    • You cannot mix w and x descriptors in the same srcset.

    • Preloading a <picture> source requires imagesrcset and imagesizes.

    • The fallback for <picture>-unaware browsers is the <img> element.

    • Best practices include always including <img>, putting alt on the <img>, and ordering sources correctly.

    • Common mistakes include missing <img>, wrong source order, and no type.

    • Following best practices for <picture> leads to faster, sharper, and more efficient web pages.

    • The <picture> element is essential for modern responsive design — it solves problems that srcset alone cannot.

    20. Summary

    • The <picture> element provides multiple image sources for a single <img>.
    • It is used for art direction (different images for different layouts) and format fallback (AVIF/WebP with JPEG fallback).
    • It contains zero or more <source> elements and exactly one <img> (required).
    • The <img> carries the alt, width, height, class, id, loading, and fetchpriority.
    • The <source> elements carry srcset, sizes, media, and type.
    • The browser evaluates <source> elements in order and picks the first match.
    • Order matters: put modern formats first, then more specific media queries.
    • media is for art direction; type is for format fallback.
    • srcset + sizes inside a <source> enables resolution switching.
    • Best practices: always include <img>, put alt on the <img>, order sources correctly, and test in multiple browsers.
    • Common mistakes include missing <img>, wrong source order, no type, and putting alt on <source>.
    • <picture> is essential for modern responsive design — it solves problems that srcset alone cannot.
