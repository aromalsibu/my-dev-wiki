    Resource Hints

    1. Overview

    Definition

    Resource hints are a set of <link> elements that tell the browser about resources it will need in the future — before the browser would otherwise discover them. They allow the browser to start work early: resolving DNS, opening connections, or downloading resources, all before the main HTML parser reaches the point where the resource is actually referenced.

    <head>
    <!-- Resolve DNS early for a third-party origin -->
    <link rel="dns-prefetch" href="https://fonts.gstatic.com">

    <!-- Establish a full connection early -->
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

    <!-- Download a critical resource at high priority -->
    <link rel="preload" href="/fonts/inter-var.woff2" as="font" type="font/woff2" crossorigin>

    <!-- Preload an ES module -->
    <link rel="modulepreload" href="/js/app.js">

    <!-- Fetch a likely next-page resource at low priority -->
    <link rel="prefetch" href="/next-page.html">
</head>

    There are five primary resource hints:

    Hint What it does When to use
    dns-prefetch Resolve a hostname only Cross-origin asset hosts you may use later
    preconnect DNS + TCP/QUIC + TLS handshake Critical third-party origins (fonts, analytics, image CDN)
    preload Fetch and cache a specific subresource at high priority Above-the-fold CSS, hero image, primary font
    modulepreload Preload an ES module and its declared static dependencies Critical entry-point modules in an ESM-shipped app
    prefetch Low-priority fetch for a future navigation Likely next pages (e.g., article in a list)

    Beyond the <link> hints, there are two additional mechanisms that serve the same purpose:

    • 103 Early Hints — an HTTP status code that lets the server send preload/preconnect directives before the full response is ready.
    • The Speculation Rules API — a JSON-based declarative API for prefetching and prerendering future page navigations.

    Resource hints are performance hypotheses, not configuration — a preload for a font that the browser would have discovered 50ms later is harmless; a preload for the wrong file pays full bandwidth cost without a win.

    Purpose

    Resource hints serve several essential purposes:

    • Reduce latency — eliminate DNS, TCP, and TLS round-trips before they happen.
    • Prioritize critical resources — tell the browser which resources matter most for the current page.
    • Prepare for future navigation — fetch next-page resources during idle time.
    • Improve Core Web Vitals — faster LCP, lower INP, better TBT.
    • Compensate for late discovery — preload resources that the preload scanner misses (fonts in CSS, LCP images in JS).
    • Enable instant navigation — prerender likely next pages for single-digit-millisecond navigation.

    Where It Fits

    Performance Stack
│
├── Critical HTML        ← minimum markup for first paint
├── Lazy Loading         ← defer non-critical resources
├── Resource Hints       ← preload, preconnect, prefetch
├── Preload              ← high-priority fetch for critical assets
├── Prefetch             ← low-priority fetch for next navigation
├── DNS Prefetch         ← resolve third-party origins early
├── Script Loading       ← defer, async, module
└── Rendering Impact     ← layout shift, paint, compositing

    Resource hints sit between critical HTML and script loading in the performance stack. They are the mechanism for telling the browser what to do before it would otherwise figure it out.

    2. Why It Exists

    The Problem

    A browser is a reactive machine. It parses HTML, discovers resources as it encounters them, and fetches them in the order it finds them. This works — but it is slow.

    Consider a page that loads a font. The font is referenced in a CSS file. The CSS file is referenced in the HTML. The browser must:

    1. Parse the HTML.
    2. Fetch the CSS.
    3. Parse the CSS.
    4. Discover the font reference.
    5. Fetch the font.

    That is five sequential steps before the font even starts downloading. The font is on the critical path for text rendering (FOIT/FOUT), and every step adds latency.

    Resource hints break this sequential dependency. A preload for the font tells the browser "fetch this now, at high priority" — the browser starts fetching the font in parallel with the CSS, eliminating four round-trips.

    The same logic applies to third-party origins. A preconnect for a font CDN starts the DNS, TCP, and TLS handshake before the browser knows it needs to fetch from that origin. When the font request is finally made, the connection is already warm.

    Previous Limitations

    Limitation Consequence
    No way to hint future resources Browser discovered resources sequentially
    No DNS pre-resolution Every new origin required a DNS round-trip
    No connection pre-warming TCP + TLS handshake blocked first request
    No priority control Browser fetched resources in discovery order
    No next-page preparation Every navigation started from scratch
    No declarative prerendering rel=prerender was Chrome-only and resource-heavy

    Why It Was Introduced

    dns-prefetch and preconnect were the earliest hints, introduced around 2008–2013. They solved the problem of third-party origins adding latency to the critical path.

    preload shipped in Chrome 50 (2016) and standardized the ability to fetch a resource at high priority before the browser would normally discover it.

    prefetch shipped alongside preload as the low-priority counterpart for future navigations.

    modulepreload shipped in Chrome 66 (2018) to solve the problem of ES modules having a nested dependency graph — the browser needed to fetch the entry module first, parse it, discover its imports, then fetch those. modulepreload fetches the entry module and its declared static dependencies in one go.

    103 Early Hints was standardized as RFC 8297 in 2017 and shipped in Chrome 103 (2022). It lets the server send preload directives before the full HTML response is ready.

    The Speculation Rules API shipped in Chrome 105 (2022) as a replacement for the deprecated <link rel="prerender"> hint. Chrome deprecated rel=prerender because it was not broadly supported beyond Chrome, and it was not a very expressive API.

    In 2026, resource hints are baseline and expected. Browsers support them universally; frameworks emit them automatically; the question is whether you are over-using them. Over-using preconnect can exhaust the per-origin connection budget on mobile networks. A preload for the wrong file pays full bandwidth cost without a win.

    3. Syntax / Basic Usage

    dns-prefetch — DNS Resolution Only

    <link rel="dns-prefetch" href="https://fonts.googleapis.com">
<link rel="dns-prefetch" href="https://www.google-analytics.com">
<link rel="dns-prefetch" href="https://cdn.example.com">

    Code Breakdown

    • rel="dns-prefetch" — resolves the hostname to an IP address in advance.
    • Costs almost nothing — just a DNS lookup.
    • Use when: you have many third-party origins and want to pre-resolve their DNS in bulk.
    • Do not use when: you have only one or two critical origins — use preconnect instead.

    preconnect — Full Connection Priming

    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="preconnect" href="https://cdn.example.com">

    Code Breakdown

    • rel="preconnect" — completes the full connection handshake: DNS + TCP + TLS.
    • crossorigin — required for origins that serve CORS-enabled resources (fonts, modules).
    • Use when: you know the browser will connect to a third-party origin, and that connection is on the critical path.
    • Do not use when: you are unsure the origin will be used — preconnect opens a real socket.

    preload — High-Priority Fetch for the Current Page

    <!-- Preload a font -->
<link rel="preload" href="/fonts/inter-var.woff2" as="font" type="font/woff2" crossorigin>

<!-- Preload a hero image -->
<link rel="preload" as="image" href="/hero.avif" fetchpriority="high">

<!-- Preload critical CSS -->
<link rel="preload" href="/critical.css" as="style">

    Code Breakdown

    • rel="preload" — fetches the resource at high priority for the current page.
    • as — required. Tells the browser the resource type (font, image, style, script, etc.). Without as, the browser cannot set the correct priority or apply the correct security checks.
    • crossorigin — required for fonts and other CORS-enabled resources, even same-origin.
    • fetchpriority="high" — reinforces the priority signal for LCP images.
    • Critical rule: preload only resources the browser would discover late (fonts in CSS, LCP images in JS). Preloading resources the browser already discovers early (same-origin scripts, stylesheets in <head>) wastes bandwidth.

    modulepreload — ES Module Preloading

    <link rel="modulepreload" href="/js/app.js">

    Code Breakdown

    • rel="modulepreload" — fetches an ES module and its declared static dependencies.
    • Unlike preload as="script", it parses the module's import statements and fetches them recursively.
    • Use when: you have a critical entry-point module in an ESM-shipped app.
    • Browser support: Chrome 66+, Edge 79+, Safari 17+, Firefox 115+.

    prefetch — Low-Priority Fetch for Future Navigation

    <link rel="prefetch" href="/next-page.html" as="document">
<link rel="prefetch" href="/product-details.js" as="script">

    Code Breakdown

    • rel="prefetch" — fetches the resource at low priority for future navigation.
    • The browser downloads during idle time, after the current page has loaded.
    • Use when: the user is likely to navigate to a specific next page (e.g., the next article in a list).
    • Do not use when: you are unsure the user will navigate there — prefetch wastes bandwidth on unused resources.

    The as Attribute

    The as attribute is required for preload and recommended for prefetch. It tells the browser the resource type, which determines:

    • Fetch priority.
    • Request headers (Accept, etc.).
    • Security checks (CSP, SRI).
    • Cache behavior.
    as value Resource type
    font Web font
    image Image
    style Stylesheet
    script Script
    document HTML document
    fetch Fetch/XHR
    video Video
    audio Audio
    track Text track
    worker Web Worker

    The fetchpriority Attribute

    <link rel="preload" as="image" href="/hero.avif" fetchpriority="high">
    Value Effect
    high Fetch at highest priority
    low Fetch at low priority
    auto Default priority

    4. Mental Model

    The "Warm-Up" Mental Model

    Resource hints are a warm-up for the browser:

    ┌─────────────────────────────────────────────┐
│  dns-prefetch    → "Learn the address"       │
│  preconnect      → "Open the connection"     │
│  preload         → "Fetch this now"          │
│  prefetch        → "Fetch this later"        │
│  modulepreload   → "Fetch this module tree"  │
└─────────────────────────────────────────────┘

    Think of a race car driver. dns-prefetch is looking up the track address. preconnect is driving to the track. preload is starting the engine. prefetch is warming up the tires for the next race. modulepreload is loading the entire pit crew.

    The "Cost vs. Benefit" Mental Model

    Each hint has a cost and a benefit:

    ┌─────────────────────────────────────────────┐
│  dns-prefetch                                │
│  Cost: Very low    Benefit: Low–Medium       │
│  └── DNS lookup only                         │
├─────────────────────────────────────────────┤
│  preconnect                                  │
│  Cost: Low–Medium  Benefit: Medium–High      │
│  └── DNS + TCP + TLS handshake              │
├─────────────────────────────────────────────┤
│  preload                                     │
│  Cost: Medium–High Benefit: High (if correct)│
│  └── Full resource download                  │
├─────────────────────────────────────────────┤
│  prefetch                                    │
│  Cost: Low         Benefit: High (next page) │
│  └── Low-priority download                   │
├─────────────────────────────────────────────┤
│  modulepreload                               │
│  Cost: Medium      Benefit: High (ESM)       │
│  └── Module + dependencies                   │
└─────────────────────────────────────────────┘

    Over-using preconnect can exhaust the per-origin connection budget on mobile networks. Over-using preload can delay other critical resources by competing for bandwidth.

    The "Discover vs. Hint" Mental Model

    The browser has a preload scanner that runs ahead of the main parser. It discovers resources early — but it cannot see:

    • Fonts referenced inside CSS files.
    • Images referenced inside CSS background-image.
    • Resources loaded dynamically by JavaScript.
    • Resources behind @import in CSS.

    These are the resources that preload helps. If the browser already discovers a resource early, preloading it is redundant:

    ┌─────────────────────────────────────────────┐
│  BROWSER DISCOVERS EARLY (no preload needed) │
│  └── <script src> in <head>                  │
│  └── <link rel="stylesheet"> in <head>       │
│  └── <img src> in initial HTML               │
├─────────────────────────────────────────────┤
│  BROWSER DISCOVERS LATE (preload helps)      │
│  └── Fonts in CSS @font-face                 │
│  └── Images in CSS background-image          │
│  └── LCP image loaded by JavaScript          │
│  └── Module dependencies                     │
└─────────────────────────────────────────────┘

    The "Hypothesis, Not Configuration" Mental Model

    Resource hints are performance hypotheses — not configuration. Each hint is a bet that the browser will need the resource. If the bet is right, performance improves. If the bet is wrong, bandwidth is wasted.

    A preload for a font the browser would have
discovered 50ms later is harmless.

A preload for the wrong file pays full
bandwidth cost without a win.

    Validate every hint with WebPageTest's "no-cache" filmstrip before shipping.

    The "Three Tiers of Preparation" Mental Model

    Resource hints prepare for three time horizons:

    ┌─────────────────────────────────────────────┐
│  CURRENT PAGE (right now)                    │
│  └── preload                                 │
│  └── modulepreload                           │
│  └── preconnect                              │
├─────────────────────────────────────────────┤
│  NEXT NAVIGATION (seconds from now)          │
│  └── prefetch                                │
│  └── Speculation Rules API (prefetch)        │
├─────────────────────────────────────────────┤
│  POSSIBLE NAVIGATION (maybe)                 │
│  └── dns-prefetch                            │
│  └── Speculation Rules API (prerender)       │
└─────────────────────────────────────────────┘

    5. Core Concepts

    Concept 1: dns-prefetch

    Resolves a hostname to an IP address in advance. Costs almost nothing — just a DNS lookup. Use when you have many third-party origins and want to pre-resolve their DNS in bulk.

    <link rel="dns-prefetch" href="https://fonts.googleapis.com">

    Concept 2: preconnect

    Completes the full connection handshake: DNS + TCP + TLS. Costs more than dns-prefetch because it opens a real socket. Use for critical third-party origins — fonts, analytics, image CDN. Limit to 1–2 origins to avoid exhausting the connection budget.

    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

    Concept 3: preload

    Fetches a current-page resource at high priority. Requires the as attribute. Use for resources the browser discovers late — fonts in CSS, LCP images in JS, critical CSS.

    <link rel="preload" href="/fonts/inter-var.woff2" as="font" type="font/woff2" crossorigin>

    Concept 4: modulepreload

    Preloads an ES module and its declared static dependencies. Unlike preload as="script", it parses the module's import statements and fetches them recursively. Use for critical entry-point modules in ESM-shipped apps.

    <link rel="modulepreload" href="/js/app.js">

    Concept 5: prefetch

    Fetches a future-navigation resource at low priority. The browser downloads during idle time. Use for likely next pages — the next article in a list, the next step in a funnel.

    <link rel="prefetch" href="/next-page.html" as="document">

    Concept 6: 103 Early Hints

    An HTTP status code (RFC 8297) that lets the server send preload and preconnect directives before the final response is ready. The browser starts opening connections and pulling critical assets in parallel with the origin's render time.

    HTTP/1.1 103 Early Hints
Link: </styles/main.css>; rel=preload; as=style
Link: </fonts/inter-var.woff2>; rel=preload; as=font; crossorigin
Link: <https://cdn.example.com>; rel=preconnect

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

    Critical detail: 103 Early Hints only works over HTTP/2 and HTTP/3. HTTP/1.1 cannot interleave a 1xx response with a later 200 on the same connection.

    Concept 7: The Speculation Rules API

    A JSON-based declarative API that lets you prefetch or prerender likely next pages. Replaces the deprecated <link rel="prerender">.

    <script type="speculationrules">
{
    "prerender": [{
        "where": { "href_matches": "/product/*" },
        "eagerness": "moderate"
    }],
    "prefetch": [{
        "where": { "href_matches": "/blog/*" },
        "eagerness": "conservative"
    }]
}
</script>

    Concept 8: Prerender vs. Prefetch

    rel="prefetch" Speculation Rules (prefetch) Speculation Rules (prerender)
    What it loads HTML only HTML only Full page
    JS execution No No Yes
    Dynamic rules No Yes Yes
    Eagerness control No Yes Yes
    URL pattern matching No Yes Yes
    Cross-site support No Limited No
    Cache-Control bypass No Yes Yes
    Battery/Data Saver aware No Yes Yes

    Concept 9: Eagerness Levels

    Speculation Rules support three eagerness levels:

    Level When it triggers
    conservative On click
    moderate On hover (200ms)
    eager Immediately on page load

    Concept 10: The as Attribute

    Required for preload. Tells the browser the resource type, which determines fetch priority, request headers, security checks, and cache behavior. Without as, the browser may fetch the resource twice.

    Concept 11: fetchpriority

    <link rel="preload" as="image" href="/hero.avif" fetchpriority="high">
    Value Effect
    high Highest priority
    low Low priority
    auto Default

    Concept 12: crossorigin for Fonts

    <link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

    Fonts always require crossorigin, even same-origin. Without it, the browser fetches the font twice.

    Concept 13: The Preload Scanner

    The browser's preload scanner runs ahead of the main parser and discovers resources early. It cannot see fonts in CSS, images in CSS background, or resources loaded by JavaScript. These are the resources preload helps.

    Concept 14: Browser Support

    Hint Chrome Edge Firefox Safari
    dns-prefetch ✅ ✅ ✅ ✅
    preconnect ✅ ✅ ✅ ✅
    preload ✅ ✅ ✅ ✅
    modulepreload ✅ 66+ ✅ 79+ ✅ 115+ ✅ 17+
    prefetch ✅ ✅ ✅ ❌
    Speculation Rules ✅ 105+ ✅ ❌ ❌ (26.2, disabled)
    103 Early Hints ✅ 103+ ✅ 103+ ✅ 120+ ❌ (preconnect only)

    Concept 15: 103 Early Hints Browser Support

    • Chrome 103+
    • Edge 103+
    • Firefox 120+
    • Safari: honors only preconnect hints

    Concept 16: Cloudflare Early Hints

    Cloudflare runs the most pragmatic deployment: the edge sniffs Link: rel=preload / rel=preconnect headers from cached origin responses and replays them as 103 hints on subsequent requests. Reports a typical median LCP improvement of ~30%.

    Concept 17: The prerender Sunset

    Chrome deprecated <link rel="prerender"> because it was not broadly supported beyond Chrome, and it was not a very expressive API. The Speculation Rules API replaces it.

    Concept 18: Shared Dictionary Compression

    A related performance optimization that allows the server to compress a response against a previously-fetched response. Chrome team measured 99% byte savings on a same-origin app.js update against the previous build. Standardized in Chrome 130+ and Edge 130+.

    Concept 19: The Per-Origin Connection Budget

    Browsers limit the number of concurrent connections per origin (typically 6 for HTTP/1.1, unlimited multiplexing for HTTP/2+). Over-using preconnect can exhaust this budget on mobile networks, delaying other resources.

    Concept 20: Resource Hints Don't Help Googlebot

    Resource hints like prefetch, preload, and preconnect are irrelevant to Google's crawling infrastructure. Browser performance features solve latency problems that Google's infrastructure doesn't have. Google caches page resources separately and doesn't fetch them in real time the way a browser does. The hints still help users — faster page loads improve retention and conversion — but they do not influence crawling, indexing, or rankings.

    7. Internal Architecture / Under the Hood

    The Preload Scanner

    Modern browsers include a preload scanner that runs ahead of the main parser. It scans the raw HTML bytes for resource references and starts fetching them before the parser reaches them. The scanner can see <script src>, <link rel="stylesheet">, and <img src> in the initial HTML.

    The scanner cannot see:

    • Fonts referenced inside CSS files.
    • Images referenced in CSS background-image.
    • Resources loaded dynamically by JavaScript.
    • Resources behind @import in CSS.

    These are the resources that preload helps.

    The Connection Pool

    Browsers maintain a connection pool per origin. For HTTP/1.1, the limit is typically 6 connections per origin. For HTTP/2 and HTTP/3, multiplexing allows unlimited concurrent streams over a single connection.

    preconnect opens a socket in this pool. Over-using it can exhaust the pool on mobile networks.

    The Fetch Priority Engine

    The browser assigns a priority to every resource based on:

    • Resource type (as attribute).
    • Position in the document.
    • fetchpriority attribute.
    • Whether it is render-blocking.

    preload with as="font" gets a higher priority than a font discovered via CSS.

    The Speculation Rules Engine

    The Speculation Rules API is browser-managed. The browser decides whether to honor a rule based on:

    • Available memory.
    • Network conditions.
    • CPU load.
    • Battery level.
    • Data Saver mode.

    With hardcoded <link> tags, the browser has less context and cannot be as smart about what it actually executes.

    The 103 Early Hints Architecture

    103 Early Hints requires HTTP/2 or HTTP/3 because HTTP/1.1 cannot interleave a 1xx response with a later 200 on the same connection. The server sends an interim response with Link headers, then the final response.

    9. Practical Examples

    Example 1: Font Preloading

    <head>
    <!-- Preconnect to the font origin -->
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

    <!-- Preload the primary font -->
    <link rel="preload" href="/fonts/inter-var.woff2" as="font" type="font/woff2" crossorigin>

    <style>
        @font-face {
            font-family: 'Inter';
            src: url('/fonts/inter-var.woff2') format('woff2-variations');
            font-display: swap;
            font-weight: 100 900;
        }
        body { font-family: 'Inter', system-ui, sans-serif; }
    </style>
</head>

    Code Breakdown:

    • preconnect to fonts.gstatic.com starts the connection handshake early.
    • preload for the font fetches it at high priority, before the CSS is parsed.
    • crossorigin is required for font preloads, even same-origin.
    • font-display: swap renders text immediately with fallback.

    Example 2: LCP Image Preloading

    <head>
    <link rel="preload" as="image" href="/hero-1200.avif"
          imagesrcset="/hero-400.avif 400w,
                       /hero-800.avif 800w,
                       /hero-1200.avif 1200w"
          imagesizes="(max-width: 600px) 400px,
                      (max-width: 1200px) 800px,
                      1200px"
          fetchpriority="high">
</head>
<body>
    <img src="/hero-1200.avif"
         srcset="/hero-400.avif 400w,
                 /hero-800.avif 800w,
                 /hero-1200.avif 1200w"
         sizes="(max-width: 600px) 400px,
                (max-width: 1200px) 800px,
                1200px"
         alt="Product hero image"
         width="1200"
         height="600"
         fetchpriority="high">
</body>

    Code Breakdown:

    • preload with imagesrcset and imagesizes matches the <img> attributes.
    • fetchpriority="high" tells the browser this is the LCP element.
    • width and height prevent layout shift.
    • The image is in the initial HTML — not lazy-loaded — because it is the LCP element.

    Example 3: modulepreload for ESM Entry Point

    <head>
    <link rel="modulepreload" href="/js/app.js">
</head>
<body>
    <script type="module" src="/js/app.js"></script>
</body>

    Code Breakdown:

    • modulepreload fetches /js/app.js and its declared static dependencies.
    • The browser parses the module's import statements and fetches them recursively.
    • When <script type="module"> executes, the module graph is already in the module map.

    Example 4: Prefetch for Likely Next Page

    <head>
    <!-- Prefetch the next article in the list -->
    <link rel="prefetch" href="/blog/next-article.html" as="document">
</head>

    Code Breakdown:

    • prefetch fetches the HTML at low priority during idle time.
    • When the user clicks the link, the HTML is already in the cache.
    • Reduces TTFB on the next navigation.
    • Does not execute JavaScript or apply styles until the user clicks.

    Example 5: Speculation Rules for Instant Navigation

    <script type="speculationrules">
{
    "prerender": [{
        "where": { "href_matches": "/product/*" },
        "eagerness": "moderate"
    }],
    "prefetch": [{
        "where": { "href_matches": "/blog/*" },
        "eagerness": "conservative"
    }]
}
</script>

    Code Breakdown:

    • prerender on hover (moderate) for product pages — likely next navigation.
    • prefetch on click (conservative) for blog pages — less certain next navigation.
    • The browser decides whether to honor the rule based on device conditions.

    Example 6: 103 Early Hints with Express

    app.get('/', (req, res) => {
    res.writeEarlyHints({
        'link': [
            '</styles/main.css>; rel=preload; as=style',
            '</fonts/inter-var.woff2>; rel=preload; as=font; crossorigin',
            '<https://cdn.example.com>; rel=preconnect'
        ]
    });

    res.sendFile('index.html');
});

    Code Breakdown:

    • The server sends 103 Early Hints with preload/preconnect directives.
    • The browser starts fetching critical resources while the server prepares the HTML.
    • Requires HTTP/2 or HTTP/3.
    • Supported in Chrome 103+, Edge 103+, Firefox 120+.

    Example 7: Complete Production Head

    <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">

    <title>How SVG Embedding Works — Dev Notes</title>

    <!-- Preconnect to critical third-party origins -->
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

</head>

    11. Best Practices

    1. Preload only late-discovered resources. Why: the browser already discovers early resources; preloading them wastes bandwidth.
    2. Use preconnect for critical third-party origins only. Why: limit to 1–2 origins to avoid exhausting the connection budget.
    3. Use dns-prefetch for many third-party origins. Why: cheaper than preconnect and effective in bulk.
    4. Always include the as attribute on preload. Why: without it, the browser cannot set the correct priority or security checks.
    5. Always include crossorigin on font preloads. Why: fonts require CORS, even same-origin.
    6. Use fetchpriority="high" on the LCP image preload. Why: reinforces the priority signal.
    7. Use modulepreload for ESM entry points. Why: fetches the module and its dependencies.
    8. Use prefetch for likely next pages. Why: reduces TTFB on the next navigation.
    9. Use Speculation Rules for instant navigation. Why: replaces the deprecated rel=prerender.
    10. Choose the right eagerness level. Why: conservative for click, moderate for hover, eager for immediate.
    11. Validate with WebPageTest "no-cache" filmstrip. Why: resource hints are hypotheses — test them.
    12. Check for unused preloads in Chrome console. Why: Chrome warns about preloaded resources that were never used.
    13. Do not preload the same resource twice. Why: duplicate preloads waste bandwidth.
    14. Do not preload resources behind authentication. Why: the browser will fetch them again after auth.
    15. Do not over-use preconnect. Why: each opens a real socket and consumes the connection budget.
    16. Combine 103 Early Hints with preload/preconnect. Why: sends directives before the HTML response.
    17. Use HTTP/2 or HTTP/3 for 103 Early Hints. Why: HTTP/1.1 cannot interleave 1xx and 200.
    18. Remember resource hints don't help Googlebot. Why: they help users, not crawlers.
    19. Audit resource hints after every framework upgrade. Why: framework behavior changes.
    20. Measure with Lighthouse and CrUX. Why: lab + field data reveals different issues.

    12. Common Mistakes

    ❌ Mistake: Preloading Resources the Browser Discovers Early

    <link rel="preload" href="/styles/main.css" as="style">
<link rel="preload" href="/js/app.js" as="script">

    Why it's wrong: The browser discovers these in the HTML anyway. Preloading them wastes bandwidth.

    ✅ Correct: Preload only late-discovered resources — fonts in CSS, LCP images in JS.

    ❌ Mistake: Missing as on Preload

    <link rel="preload" href="/fonts/inter.woff2">

    Why it's wrong: Without as, the browser cannot set the correct priority or security checks. It may fetch the resource twice.

    ✅ Correct:

    <link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

    ❌ Mistake: Missing crossorigin on Font Preload

    <link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2">

    Why it's wrong: Fonts require CORS. Without crossorigin, the browser fetches the font twice.

    ✅ Correct:

    <link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

    ❌ Mistake: Over-Using preconnect

    <link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com">
<link rel="preconnect" href="https://cdn.example.com">
<link rel="preconnect" href="https://analytics.example.com">
<link rel="preconnect" href="https://ads.example.com">

    Why it's wrong: Each preconnect opens a real socket. Over-using it exhausts the per-origin connection budget on mobile networks.

    ✅ Correct: Limit to 1–2 critical origins. Use dns-prefetch for the rest.

    ❌ Mistake: Preloading the Wrong Image

    <link rel="preload" as="image" href="/logo.png">

    Why it's wrong: The logo is not the LCP element. Preloading it wastes bandwidth.

    ✅ Correct: Preload the LCP image.

    ❌ Mistake: Using rel="prerender" Instead of Speculation Rules

    <link rel="prerender" href="/next-page">

    Why it's wrong: rel=prerender is deprecated and Chrome-only. It consumed too much memory and network bandwidth.

    ✅ Correct: Use the Speculation Rules API.

    ❌ Mistake: Not Using modulepreload for ESM Entry Points

    <script type="module" src="/js/app.js"></script>

    Why it's wrong: The browser fetches the entry module, parses it, discovers its imports, then fetches those — sequentially.

    ✅ Correct:

    <link rel="modulepreload" href="/js/app.js">
<script type="module" src="/js/app.js"></script>

    ❌ Mistake: No Preload for the LCP Image

    <img src="/hero.jpg" alt="Hero" width="1200" height="600">

    Why it's wrong: The LCP image is discovered late, delaying LCP.

    ✅ Correct:

    <link rel="preload" as="image" href="/hero.jpg" fetchpriority="high">

    ❌ Mistake: Assuming Resource Hints Help SEO

    <link rel="preload" href="/hero.jpg" as="image">

    Why it's wrong: Resource hints are irrelevant to Google's crawling infrastructure. They help users, not crawlers.

    ✅ Correct: Use them for user experience; use critical HTML and SSR for crawlability.

    ❌ Mistake: Not Validating with WebPageTest

    Why it's wrong: Resource hints are hypotheses. Without validation, you may be wasting bandwidth.

    ✅ Correct: Validate with WebPageTest "no-cache" filmstrip before shipping.

    14. Security Considerations

    Preload and CSP

    Preloaded resources must satisfy CSP directives:

    Content-Security-Policy: font-src 'self' https://fonts.gstatic.com

    Preload and Subresource Integrity

    Preloaded scripts and styles should use SRI where possible:

    <link rel="preload" href="/js/lib.js" as="script" integrity="sha384-...">

    Prefetch and Privacy

    prefetch reveals what resources the page will load next. Do not prefetch URLs that leak sensitive information.

    Speculation Rules and Privacy

    Prerendering fetches and renders pages in the background. Do not prerender pages behind authentication or pages that perform side effects on load.

    103 Early Hints and CORS

    103 Early Hints responses must respect CORS. Cross-origin preloads require crossorigin.

    Resource Hints and Cache Poisoning

    A malicious prefetch or preload for a sensitive URL could leak information through timing. Validate all hint URLs.

    16. When to Use

    • dns-prefetch — for many third-party origins.
    • preconnect — for 1–2 critical third-party origins.
    • preload — for late-discovered critical resources (fonts, LCP images, critical CSS).
    • modulepreload — for ESM entry points.
    • prefetch — for likely next pages.
    • Speculation Rules — for instant navigation on multi-page sites.
    • 103 Early Hints — when server/CDN support exists.

    17. When Not to Use

    • Do not preload resources the browser discovers early. Use the HTML.
    • Do not preconnect to more than 2–3 origins. Use dns-prefetch for the rest.
    • Do not prefetch pages the user is unlikely to visit. Wastes bandwidth.
    • Do not prerender pages behind authentication. Side effects on load.
    • Do not rely on resource hints for SEO. They help users, not crawlers.
    • Do not use rel="prerender". It is deprecated.
