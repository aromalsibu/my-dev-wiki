    Chapter: Object

    1. Overview

    Definition

    The <object> element is an HTML element that embeds external resources — HTML documents, images, PDFs, SVG, video, audio, or plugin-based content — into the current document. Unlike <embed>, which is a void element, <object> is a container element that can hold fallback content rendered when the resource cannot be displayed. It provides a generic, standardized way to embed any resource the browser can handle, with graceful degradation built in.

    <object> is one of the oldest embedding mechanisms on the web, predating <iframe> in some contexts. It is the successor to the obsolete <applet> element and a more flexible alternative to <embed>. It supports nested fallbacks — you can nest <object> elements inside each other, each attempting a different resource until one succeeds.

    Example: 

    <object data="document.pdf" type="application/pdf" width="800" height="600">
    <p>Your browser doesn't support PDFs. <a href="document.pdf">Download the PDF</a>.</p>
</object>

    Purpose

    The <object> element serves several essential purposes:

    • Generic embedding – embed any resource by MIME type.
    • Fallback content – provide alternatives if the resource cannot be displayed.
    • Nested fallbacks – chain multiple attempts for maximum compatibility.
    • Accessibility – fallback content can describe the resource for screen readers.
    • Plugin delegation – historically used for plugins (Flash, QuickTime, Java).
    • PDF and SVG embedding – modern use case for document display.
    • Micro-frontends – embedding independent HTML applications.

    Where It Fits

    The <object> element is embedded content, flow content, and phrasing content. It is a replaced element that occupies space like an image. It can appear anywhere phrasing content is accepted — inside <p>, <div>, <figure>, <td>, and more.

    <figure>
    <object data="brochure.pdf" type="application/pdf" width="800" height="600">
        <p>PDF not supported. <a href="brochure.pdf">Download the brochure</a>.</p>
    </object>
    <figcaption>Product Brochure (PDF)</figcaption>
</figure>

    2. Why It Exists

    The Problem

    Before <object>, embedding external content was fragmented:

    • <img> – only raster images.
    • <applet> – only Java applets.
    • <embed> – generic but no fallback content.
    • Plugins – each used its own markup, often proprietary.

    Developers needed a generic, standardized, fallback-capable embedding element. If one resource type failed, another should be tried. If all failed, a text description should be shown. The <object> element was that solution.

    Previous Limitations

    Limitation Consequence
    <img> limited to images No PDFs, SVG, plugins
    <applet> limited to Java No flexibility
    <embed> has no fallback Users see nothing on failure
    Plugin markup varied Fragmented, non-standard
    No nesting No chained fallbacks
    Poor accessibility Screen readers couldn't describe

    Why the <object> Element Was Introduced

    The <object> element was introduced in HTML 4.0 (1997) as the modern, standardized, generic embedding element. It was designed to:

    • Embed any resource – images, PDFs, SVG, HTML, plugins.
    • Provide fallback content – rendered when the resource fails.
    • Support nesting – fallback can itself be an <object>.
    • Improve accessibility – fallback text describes the resource.
    • Delegate to plugins – Flash, QuickTime, Java.
    • Standardize embedding – one element for all cases.

    The <object> element replaces both <applet> (for Java) and <embed> (in most cases). Modern browsers support it universally, and it remains the preferred generic embedding element alongside <iframe> and <embed>.

    3. Syntax / Basic Usage

    The Basic Syntax of <object>

    <object data="URL" type="MIME-TYPE" width="W" height="H">
    <!-- Fallback content -->
</object>
    • data – the URL of the resource (note: data, not src).
    • type – the MIME type.
    • width / height – dimensions.
    • Fallback content – shown if the resource cannot be displayed.

    Simple PDF Embed

    <object data="document.pdf" type="application/pdf" width="800" height="600">
    <p>Your browser doesn't support PDFs. <a href="document.pdf">Download the PDF</a>.</p>
</object>

    SVG Embed

    <object data="diagram.svg" type="image/svg+xml" width="400" height="300">
    <img src="diagram.png" alt="A system diagram" width="400" height="300">
</object>

    Image Embed (Alternative to <img>)

    <object data="photo.jpg" type="image/jpeg" width="800" height="600">
    <img src="photo.jpg" alt="A scenic view" width="800" height="600">
</object>

    Note: Prefer <img> for raster images.

    HTML Embed (Alternative to <iframe>)

    <object data="page.html" type="text/html" width="800" height="600">
    <p>Your browser doesn't support embedded HTML. <a href="page.html">Open page</a>.</p>
</object>

    Note: <iframe> is preferred for HTML documents.

    Nested Fallbacks

    <object data="movie.mp4" type="video/mp4" width="640" height="360">
    <object data="movie.webm" type="video/webm" width="640" height="360">
        <object data="movie.ogv" type="video/ogg" width="640" height="360">
            <p>Your browser doesn't support this video. <a href="movie.mp4">Download</a>.</p>
        </object>
    </object>
</object>

    Note: Each <object> tries to render its resource; if it fails, the fallback (the next <object>) is attempted.

    Object with Parameters

    <object data="animation.swf" type="application/x-shockwave-flash" width="400" height="300">
    <param name="autoplay" value="true">
    <param name="loop" value="false">
    <p>Flash not supported. <a href="animation.swf">Download</a>.</p>
</object>

    Note: <param> is obsolete but historically used with plugins.

    Object with name

    <object data="page.html" type="text/html" name="myFrame" width="800" height="600">
    <p>Fallback content</p>
</object>

    Note: The name attribute allows targeting via <a target> and <form target>. However, <iframe> is more commonly used for this purpose.

    Code Breakdown

    Attribute Purpose
    data The URL of the resource
    type The MIME type
    width / height Dimensions
    name Name for targeting (rarely used)
    form Associates with a form (rarely used)
    <param> Parameters for plugins (obsolete)
    Fallback content Any flow content, including nested <object>

    4. Mental Model

    The "Nested Boxes" Analogy

    Think of <object> as a set of nested boxes. The outermost box tries to display a resource. If it can't, it opens to reveal a smaller box inside, which tries another resource. If that also fails, a third box, and so on — until finally a text description is shown. This is the essence of fallback chaining.

    The "Backup Plan" Mental Model

    <object> always has a backup plan:

    • Plan A: Display the primary resource.
    • Plan B: Display a fallback resource.
    • Plan C: Display a fallback resource.
    • Plan D: Show text content.

    Unlike <embed>, <object> is never left empty — there's always something to show.

    The "Universal Wrapper" Mental Model

    <object> is a universal wrapper for external content. It can wrap:

    • Images (image/jpeg).
    • SVG (image/svg+xml).
    • PDFs (application/pdf).
    • HTML (text/html).
    • Video (video/mp4).
    • Audio (audio/mpeg).
    • Flash (application/x-shockwave-flash — obsolete).
    • Any MIME type.

    The type attribute tells the browser how to interpret the wrapped content.

    The "Object vs. Embed" Mental Model

    Aspect <object> <embed>
    Fallback Yes No
    Nesting Yes No
    Closing tag Yes No (void)
    Attributes data, type src, type
    Use case Preferred for reliability Legacy, simple embedding

    Rule: Use <object> when you need fallback; use <embed> for simple, trusted embeds.

    The "Replace the Obsolete" Mental Model

    <object> is designed to replace obsolete elements:

    • <applet> (Java) → <object>.
    • <embed> → <object> with fallback.
    • Plugin-specific markup → <object> with type.

    5. Core Concepts

    Concept 1: The data Attribute

    The data attribute specifies the URL of the resource:

    <object data="document.pdf" type="application/pdf">

    Note: Unlike <embed>, which uses src, <object> uses data.

    Concept 2: The type Attribute

    The type attribute specifies the MIME type:

    <object data="document.pdf" type="application/pdf">

    Why: The browser uses type to decide how to render the resource.

    Concept 3: The width and height Attributes

    Set the dimensions in pixels:

    <object data="document.pdf" type="application/pdf" width="800" height="600">

    Concept 4: Fallback Content

    The content between <object> and </object> is the fallback:

    <object data="document.pdf" type="application/pdf">
    <p>PDF not supported. <a href="document.pdf">Download</a>.</p>
</object>

    Rendered when:

    • The resource fails to load.
    • The MIME type is unsupported.
    • The plugin is missing.

    Fallback can be:

    • Text and inline elements.
    • Block elements (paragraphs, lists).
    • Images (<img>).
    • Another <object> (nested fallback).
    • Video or audio.

    Concept 5: Nested Fallbacks

    <object data="video.mp4" type="video/mp4">
    <object data="video.webm" type="video/webm">
        <object data="video.ogv" type="video/ogg">
            <p>No video support. <a href="video.mp4">Download</a>.</p>
        </object>
    </object>
</object>

    Why: Provides multiple chances for the browser to render a resource.

    Concept 6: The <param> Element (Obsolete)

    The <param> element passes parameters to plugins:

    <object data="animation.swf" type="application/x-shockwave-flash">
    <param name="autoplay" value="true">
    <param name="quality" value="high">
</object>

    Note: <param> is obsolete in HTML5 for most uses, but still valid in <object>.

    Concept 7: The name Attribute

    The name attribute allows the <object> to be targeted by links and forms:

    <a href="page.html" target="myFrame">Load in object</a>
<object data="page.html" type="text/html" name="myFrame" width="800" height="600">
    <p>Fallback</p>
</object>

    Note: <iframe> is preferred for this use case.

    Concept 8: Object vs. iframe

    Aspect <object> <iframe>
    Content Any resource HTML documents
    Browsing context Limited Full
    DOM access No Same-origin only
    Fallback Yes Yes (content between tags)
    Sandbox No Yes
    Accessibility Good (fallback) Good (title)

    Best practice: Use <iframe> for HTML documents and sandboxing; <object> for non-HTML resources with fallback.

    Concept 9: Object vs. Embed

    Aspect <object> <embed>
    Fallback Yes No
    Nesting Yes No
    Attributes data src
    Preferred Yes Less preferred

    Concept 10: Object vs. img

    Aspect <object> <img>
    Content Any resource Raster images
    alt No Yes
    Use case PDFs, SVG Photos

    Best practice: Use <img> for images, <object> for other resources.

    Concept 11: PDF Embedding

    <object data="document.pdf" type="application/pdf" width="800" height="600">
    <p>PDF not supported. <a href="document.pdf">Download</a>.</p>
</object>

    Browser behaviour:

    • Chrome, Firefox, Edge: render inline.
    • Safari: may download.
    • Mobile: often downloads.

    Concept 12: SVG Embedding

    <object data="diagram.svg" type="image/svg+xml" width="400" height="300">
    <img src="diagram.png" alt="System diagram" width="400" height="300">
</object>

    Note: For inline SVG (with CSS/JS access), use <svg>.

    Concept 13: HTML Embedding

    <object data="page.html" type="text/html" width="800" height="600">
    <p>Fallback</p>
</object>

    Note: Some browsers restrict embedding HTML via <object> for security. Use <iframe>.

    Concept 14: Video Embedding

    <object data="video.mp4" type="video/mp4" width="640" height="360">
    <p>Video not supported. <a href="video.mp4">Download</a>.</p>
</object>

    Note: <video> is the modern, preferred element.

    Concept 15: Audio Embedding

    <object data="audio.mp3" type="audio/mpeg" width="300" height="50">
    <p>Audio not supported. <a href="audio.mp3">Download</a>.</p>
</object>

    Note: <audio> is the modern, preferred element.

    Concept 16: Accessibility

    <object> supports fallback content — this is its accessibility advantage:

    <object data="chart.png" type="image/png">
    <p>Bar chart showing sales growth from 2020 to 2026. Q1 2020: $1M, Q2 2020: $1.2M, ...</p>
</object>

    Note: The fallback text describes the resource for screen readers and browsers that can't render the resource.

    Best practice: Always provide meaningful fallback.

    Concept 17: The form Attribute

    The form attribute associates the <object> with a form (rarely used).

    Concept 18: Browser Support

    <object> is supported in all modern browsers. Rendering varies by MIME type and browser.

    Concept 19: CSP and Object

    The CSP object-src directive restricts <object>:

    Content-Security-Policy: object-src 'self'

    Why: Prevents embedding of untrusted content.

    Concept 20: The <param> Legacy

    While <param> is obsolete in modern HTML, it still works inside <object> for legacy plugins.

    Concept 21: The classid Attribute (Obsolete)

    classid was used to identify the plugin (e.g., the Java plugin). It is obsolete.

    Concept 22: The codebase Attribute (Obsolete)

    codebase was used to specify the base URL for plugin downloads. It is obsolete.

    Concept 23: The archive Attribute (Obsolete)

    archive was used to list archives needed by a Java applet. It is obsolete.

    Concept 24: Modern Use Cases

    • PDF display – inline PDF viewer.
    • SVG display – standalone SVG.
    • Fallback chaining – for maximum compatibility.
    • Legacy applets – rarely, for old content.

    Concept 25: Deprecation of Plugin Content

    Since Flash and Java applets are deprecated, <object> is now used primarily for native resources (PDFs, SVG, images).

    6. How It Works

    Step-by-Step: Browser Processing <object>

    1.  Parser encounters `<object>` element.
    │
    ▼
2.  Creates a DOM node (replaced element).
    │
    ▼
3.  Reads `data` and `type` attributes.
    │
    ▼
4.  Checks if a handler is available for `type`:
    │   ├── Native handler (PDF, SVG, image) → use it.
    │   ├── Plugin handler → use it (if installed).
    │   └── No handler → use fallback content.
    │
    ▼
5.  Fetches the resource.
    │
    ▼
6.  Renders the resource inside the element's box.
    │
    ▼
7.  If rendering fails, the fallback content is displayed.
    │   ├── Fallback may be another `<object>` (nested).
    │   ├── Fallback may be text (accessible description).
    │   └── Fallback may be a link (download).

    The Fallback Algorithm

    1. Browser attempts to render the resource at data.
    2. If it can't (unsupported MIME type, missing plugin, failed fetch), it tries the fallback.
    3. The fallback may be:
    4. Text – displayed inline.
    5. Another <object> – recursively attempted.
    6. An <img> – displayed.
    7. A <video> or <audio> – played.
    8. A <p> – descriptive text.
    9. If the fallback also fails, continue to the next level.
    10. Eventually, text is displayed if all else fails.

    Rendering vs. Browsing Context

    • <object> – creates a replaced element, not a browsing context.
    • <iframe> – creates a browsing context (separate document, JS, DOM).
    • <object type="text/html"> – may create a limited context in some browsers.

    CSP object-src

    The CSP object-src directive restricts <object>:

    • If object-src 'none', <object> is blocked.
    • If object-src 'self', only same-origin <object> allowed.

    Accessibility Tree

    <object> is exposed as:

    • role: document, img, or application (varies by resource).
    • name: from title or fallback content.

    Note: Fallback content is critical for accessibility. If the resource is visual and can't be rendered, the fallback text describes it.

    Browser Differences

    Browser PDF SVG HTML
    Chrome ✅ inline ✅ inline Limited
    Firefox ✅ pdf.js ✅ inline Limited
    Safari ✅ / download ✅ inline Limited
    Edge ✅ inline ✅ inline Limited

    The contentDocument Property

    For same-origin <object> with HTML content, contentDocument may be accessible:

    const obj = document.querySelector('object');
console.log(obj.contentDocument); // Same-origin only

    Note: This varies by browser and content type.

    7. Internal Architecture / Under the Hood

    The HTMLObjectElement Interface

    Property Description
    data The URL
    type The MIME type
    name The name
    width Width
    height Height
    contentDocument The Document (if HTML, same-origin)
    contentWindow The Window (if HTML, same-origin)
    form Associated form
    validity Form validity

    The Replaced Element Model

    <object> is a replaced element — the interior is not DOM, but a rendered resource:

    • CSS cannot style the interior.
    • JavaScript cannot access the interior (unless HTML same-origin).
    • The element's box is defined by width/height or intrinsic size.

    Fallback Rendering

    The browser decides which fallback to render based on:

    1. Support for the MIME type.
    2. Success fetching the resource.
    3. Presence of a plugin (historically).

    Content Types

    • PDFs – rendered by the browser's built-in or pdf.js viewer.
    • SVG – rendered natively.
    • Images – rendered as replaced content.
    • HTML – rendered in a limited browsing context (varies).
    • Plugins – obsolete in modern browsers.

    CSP Interaction

    object-src is checked before rendering:

    Content-Security-Policy: object-src 'none';

    Blocks all <object> elements.

    Accessibility API

    <object> is exposed with:

    • Role – document, img, application.
    • Name – from title, fallback text.
    • Description – from fallback text.

    The fallback is essential — without it, screen readers have nothing to announce.

    8. Lifecycle / Workflow

    The Lifecycle of an <object>

    1.  Author writes `<object>` with `data`, `type`, and fallback.
    │
    ▼
2.  File deployed.
    │
    ▼
3.  Browser parses HTML and creates the DOM node.
    │
    ▼
4.  Browser reads `data` and `type`.
    │
    ▼
5.  Browser fetches the resource.
    │
    ▼
6.  Browser selects the appropriate handler.
    │
    ▼
7.  Browser attempts to render the resource.
    │   ├── Success → resource displayed.
    │   └── Failure → fallback content displayed.
    │
    ▼
8.  The replaced element (or fallback) is visible.
    │
    ▼
9.  When the page is unloaded, the object is destroyed.

    Dynamic Creation

    const obj = document.createElement('object');
obj.data = 'document.pdf';
obj.type = 'application/pdf';
obj.width = 800;
obj.height = 600;
obj.innerHTML = '<p>PDF not supported. <a href="document.pdf">Download</a>.</p>';
document.body.appendChild(obj);

    Video with fallback <object> wrapping <video>

    11. Best Practices

    1. Always provide fallback content – that's the point of <object>.
    2. Specify type – helps the browser choose a handler.
    3. Set width and height – prevent layout shift.
    4. Wrap in <figure> – for captions and context.
    5. Provide a download link – as final fallback.
    6. Use <iframe> – for HTML documents.
    7. Use <video> / <audio> – for media.
    8. Use <img> – for raster images.
    9. Use <svg> – for inline SVG.
    10. Use <object> – for PDFs, SVG, and fallback chains.
    11. Avoid plugins – obsolete.
    12. Set CSP object-src – restrict sources.
    13. Test in multiple browsers – rendering varies.
    14. Test on mobile – embeds can be slow.
    15. Use title – for advisory information.
    16. Prefer <object> over <embed> – for fallback.
    17. Avoid nesting too deeply – 2–3 levels max.
    18. Document your object strategy – in a style guide.

    12. Common Mistakes

    ❌ Mistake: No Fallback Content

    <object data="document.pdf" type="application/pdf"></object>

    Why it's wrong: Users with browsers that can't render the PDF see nothing.

    ✅ Correct: 

    <object data="document.pdf" type="application/pdf" width="800" height="600">
    <p>PDF not supported. <a href="document.pdf">Download the PDF</a>.</p>
</object>

    ❌ Mistake: Using src Instead of data

    <object src="document.pdf" type="application/pdf"></object>

    Why it's wrong: <object> uses data, not src.

    ✅ Correct: 

    <object data="document.pdf" type="application/pdf"></object>

    ❌ Mistake: No type Attribute

    <object data="document.pdf"></object>

    Why it's wrong: The browser may not know how to render it.

    ✅ Correct: 

    <object data="document.pdf" type="application/pdf"></object>

    ❌ Mistake: No Dimensions

    <object data="document.pdf" type="application/pdf"></object>

    Why it's wrong: The embed may collapse or use unpredictable size.

    ✅ Correct: 

    <object data="document.pdf" type="application/pdf" width="800" height="600"></object>

    ❌ Mistake: Using <object> for HTML Documents

    <object data="page.html" type="text/html"></object>

    Why it's wrong: <iframe> is preferred; some browsers restrict HTML in <object>.

    ✅ Correct: 

    <iframe src="page.html" title="Embedded page"></iframe>

    ❌ Mistake: Using <object> for Video

    <object data="video.mp4" type="video/mp4"></object>

    Why it's wrong: <video> is the modern element.

    ✅ Correct: 

    <video src="video.mp4" controls></video>

    ❌ Mistake: No Accessibility

    <object data="chart.png" type="image/png"></object>

    Why it's wrong: Screen readers can't describe the chart.

    ✅ Correct: 

    <object data="chart.png" type="image/png" width="800" height="400">
    <p>Bar chart showing sales growth: 2020: $1M, 2021: $1.2M, 2022: $1.5M.</p>
</object>

    ❌ Mistake: Using <object> for Flash

    <object data="animation.swf" type="application/x-shockwave-flash"></object>

    Why it's wrong: Flash is no longer supported.

    ✅ Correct: Convert to HTML5, video, or SVG.

    ❌ Mistake: Nesting Too Deeply

    <object data="a" type="...">
    <object data="b" type="...">
        <object data="c" type="...">
            <object data="d" type="...">
                <p>Too deep.</p>
            </object>
        </object>
    </object>
</object>

    Why it's wrong: Complex and hard to maintain.

    ✅ Correct: Use 2–3 levels max.

    ❌ Mistake: No width/height

    Why it's wrong: Causes layout shift (CLS).

    ✅ Correct: Always set dimensions.

    13. Performance Considerations

    • Separate HTTP request – each <object> fetches a resource.
    • Rendering cost – delegated to the handler.
    • No native lazy loading – use JavaScript for off-screen objects.
    • Caching – server must send caching headers.
    • Memory – depends on the resource.
    • Blocking – can delay page load.
    • No priority hints – no fetchpriority.

    Performance Tips

    1. Set dimensions – prevent CLS.
    2. Lazy load with JS – for off-screen objects.
    3. Cache aggressively – with Cache-Control.
    4. Use a CDN – global delivery.
    5. Compress resources – smaller files.
    6. Limit objects – fewer is better.

    14. Security Considerations

    • Plugins – historically a major security risk.
    • CSP object-src – restrict embed sources.
    • No sandbox – <object> cannot be sandboxed.
    • Untrusted content – avoid; use <iframe sandbox>.
    • HTTPS – required for secure embeds.
    • Download fallback – ensure downloads are trusted.

    Security Best Practices

    1. Restrict object-src – CSP.
    2. Avoid untrusted objects – no sandbox.
    3. Use HTTPS – for all objects.
    4. Validate resources – before serving.
    5. Prefer <iframe sandbox> – for untrusted content.

    15. Debugging Tips

    • DevTools Elements panel – inspect the <object> element.
    • Network panel – verify the resource request.
    • Console – check for errors.
    • Browser-specific testing – PDF, SVG rendering varies.
    • obj.data – check the URL.
    • obj.type – check the MIME type.
    • obj.contentDocument – same-origin only.
    • Lighthouse – audits.
    • Accessibility Inspector – check role and name.

    16. When to Use

    • For PDFs – with fallback.
    • For SVG documents – with image fallback.
    • For fallback chaining – nested <object> for multiple formats.
    • For accessible rich media – with descriptive fallback.
    • As an alternative to <embed> – when fallback is needed.

    17. When Not to Use

    • For HTML documents – use <iframe>.
    • For raster images – use <img>.
    • For video/audio – use <video>/<audio>.
    • For inline SVG – use <svg>.
    • For untrusted content – use <iframe sandbox>.
    • For simple embeds – use <embed>.

    19. Did You Know?

    • The <object> element was introduced in HTML 4.0 (1997).

    • It uses data, not src — a common mistake.

    • <object> can contain fallback content — the key advantage over <embed>.

    • Fallback content can be nested <object> elements for multiple attempts.

    • <object> replaced the obsolete <applet> element.

    • Flash was deprecated in 2020; <object> for Flash no longer works.

    • PDFs render inline in Chrome, Firefox, and Edge; Safari may download.

    • SVG renders inline in all modern browsers.

    • <object> cannot be sandboxed — unlike <iframe>.

    • CSP object-src controls <object>.

    • <object> has good accessibility — fallback text describes the resource.

    • The name attribute allows targeting via links and forms.

    • The <param> element passes parameters to plugins.

    • classid, codebase, archive are obsolete attributes.

    • Best practices: fallback content, type, dimensions, figure caption, download link.

    • Common mistakes: no fallback, src instead of data, no type, no dimensions.

    • Following best practices for <object> leads to accessible, robust, and compatible embedding of external content.

    20. Summary

    • The <object> element embeds external resources — PDFs, SVG, images, video, audio, HTML, plugins.
    • It uses data (not src) and type attributes.
    • It is a container element — can contain fallback content.
    • Fallback can be text, images, video, audio, or nested <object>.
    • Nested fallbacks chain multiple attempts for maximum compatibility.
    • Best practices: always provide fallback, specify type, set dimensions, wrap in <figure>, provide download link.
    • Common mistakes include no fallback, using src instead of data, no type, no dimensions.
    • <object> is the preferred generic embedding element for non-HTML content with fallback.
