    Chapter: Text Formatting

    1. Overview

    Definition

    Text formatting in HTML refers to the set of inline elements used to apply semantic meaning or stylistic emphasis to portions of text within a block-level element like a paragraph. These elements allow authors to mark up specific words or phrases to convey importance, emphasis, emphasis, code, abbreviations, and other textual nuances.

    HTML provides two broad categories of text formatting elements:

    • Semantic (logical) elements – convey meaning and importance (e.g., <strong>, <em>, <mark>, <code>, <abbr>, <cite>, <dfn>, <kbd>, <samp>, <var>, <time>, <del>, <ins>, <sub>, <sup>, <small>).
    • Presentational (physical) elements – convey visual styling without semantic meaning (e.g., <b>, <i>, <u>, <s>). These are discouraged in favor of CSS and semantic equivalents.

    The key principle is: use semantic elements to convey meaning, and use CSS to control appearance.

    Purpose

    Text formatting elements serve several essential purposes:

    • Convey meaning – indicate importance, emphasis, definition, citation, or code.
    • Improve accessibility – screen readers interpret semantic elements and adjust pronunciation or tone.
    • Enhance SEO – search engines use semantic markup to understand content emphasis.
    • Enable styling hooks – CSS can target semantic elements to apply visual styles.
    • Support internationalization – elements like <bdi> and <bdo> handle bidirectional text.
    • Provide machine-readable data – <time>, <data>, and <var> expose structured information.

    Where It Fits

    Text formatting elements are phrasing content and inline elements. They appear inside block-level containers like <p>, <h1>–<h6>, <li>, <td>, <figcaption>, and others. They do not create new blocks; they flow within the text.

    <p>
    This is a paragraph with <strong>important</strong> text,
    <em>emphasized</em> words, and a <a href="#">link</a>.
</p>

    2. Why It Exists

    The Problem

    Plain text has no way to distinguish between different types of emphasis or meaning. Is a bold word simply visually bold, or is it important? Is an italicized phrase just stylized, or is it a technical term? Without semantic markup, machines (browsers, screen readers, search engines) cannot tell the difference.

    Previous Limitations

    Limitation Consequence
    No semantic markup Machines couldn't distinguish importance from styling.
    Presentational elements only <b> and <i> conveyed no meaning beyond appearance.
    Inconsistent rendering Different browsers styled elements differently.
    Poor accessibility Screen readers couldn't adjust tone for emphasis.
    No machine-readable data Dates, times, and variables weren't identifiable.

    Why Text Formatting Elements Were Introduced

    HTML introduced text formatting elements to provide semantic meaning alongside visual presentation. The evolution went from purely presentational (<b>, <i>) to semantic (<strong>, <em>) as the web matured and accessibility became a priority. This enables:

    • Meaningful markup – <strong> means "important", <em> means "emphasized".
    • Accessibility – screen readers announce emphasis and importance.
    • SEO – search engines understand which content is emphasized.
    • Styling flexibility – CSS can style semantic elements differently.
    • Machine readability – elements like <time> and <data> provide structured data.

    4. Mental Model

    The "Highlighter and Pen" Analogy

    Think of text formatting elements as different writing tools:

    • <strong> – a bold marker that says "this is important".
    • <em> – an italic pen that says "stress this word".
    • <mark> – a highlighter that says "this is relevant".
    • <code> – a typewriter font that says "this is code".
    • <abbr> – a footnote that provides the full expansion.
    • <del> – a red pen that crosses out deleted text.
    • <ins> – a green pen that underlines inserted text.

    Each tool conveys a specific meaning, not just a visual style.

    The "Semantic vs Presentational" Analogy

    Think of the difference between semantic and presentational elements as the difference between:

    • Saying "This is important" (semantic) – the meaning is in the message.
    • Saying "This is bold" (presentational) – the meaning is in the appearance.

    If you use <strong>, you're saying "this is important". If you use <b>, you're saying "this is bold". The first is meaningful; the second is just visual.

    The "Language of Emphasis" Analogy

    In spoken language, you can emphasize words by:

    • Speaking louder – like <strong> (importance).
    • Speaking slower – like <em> (emphasis).
    • Pausing – like <mark> (highlighting).
    • Changing tone – like <cite> (quoting).
    • Spelling out – like <abbr> (abbreviation).

    HTML provides elements to capture these nuances in written text.

    5. Core Concepts

    Concept 1: Semantic vs Presentational Elements

    • Semantic elements (<strong>, <em>, <mark>, <code>, etc.) – convey meaning. They tell the browser, screen reader, and search engine what the text represents.
    • Presentational elements (<b>, <i>, <u>, <s>) – convey visual style. They don't add meaning; they just change appearance.

    Rule: Use semantic elements whenever possible. Use presentational elements only when no semantic element fits.

    Concept 2: <strong> vs <b>

    Aspect <strong> <b>
    Meaning Strong importance Stylistic offset (no importance)
    Screen readers Announces emphasis May not announce
    SEO Considered important Not considered
    Use case Warnings, critical information Keywords in a product name, stylized text

    Example: <strong>Warning!</strong> vs <b>Product Name</b>.

    Concept 3: <em> vs <i>

    Aspect <em> <i>
    Meaning Stress emphasis Alternative voice (technical term, foreign word, thought)
    Screen readers Announces emphasis May not announce
    SEO Considered emphasized Not considered
    Use case "You must read this" "The term Homo sapiens"

    Example: You <em>must</em> try this vs The <i>E. coli</i> bacterium.

    Concept 4: <mark> – Highlighting

    The <mark> element represents text that is highlighted for reference purposes, often in a context where it's relevant to the user's current activity (e.g., search results).

    <p>Search results for "HTML": <mark>HTML</mark> is the standard markup language...</p>

    Concept 5: <code>, <kbd>, <samp>, <var>

    These elements represent different types of technical content:

    • <code> – a fragment of computer code.
    • <kbd> – user keyboard input.
    • <samp> – sample output from a program.
    • <var> – a variable in a mathematical or programming context.
    <p>Use <code>print()</code> to output. Press <kbd>Enter</kbd>. The result is <samp>Hello</samp>. The variable <var>x</var> holds the value.</p>

    Concept 6: <abbr> – Abbreviations

    The <abbr> element represents an abbreviation or acronym. The title attribute provides the full expansion.

    <p><abbr title="World Health Organization">WHO</abbr> was founded in 1948.</p>

    Concept 7: <time> – Machine-Readable Dates

    The <time> element represents a specific period in time. The datetime attribute provides a machine-readable format.

    <p>The concert is on <time datetime="2026-12-25">Christmas Day</time>.</p>

    Concept 8: <del> and <ins> – Document Changes

    • <del> – represents text that has been deleted from the document.
    • <ins> – represents text that has been inserted into the document.
    <p>The price was <del>$99</del> <ins>$79</ins>.</p>

    Concept 9: <sub> and <sup> – Subscript and Superscript

    • <sub> – subscript text (lowered baseline).
    • <sup> – superscript text (raised baseline).
    <p>H<sub>2</sub>O and E=mc<sup>2</sup>.</p>

    Concept 10: <small> – Side Comments

    The <small> element represents side comments and small print (e.g., legal disclaimers, copyright notices).

    <p><small>&copy; 2026 My Company. All rights reserved.</small></p>

    Concept 11: <bdi> and <bdo> – Bidirectional Text

    • <bdi> – isolates a span of text that might be formatted in a different direction.
    • <bdo> – overrides the current text direction.
    <p>User <bdi>مرحبا</bdi> wrote a comment.</p>
<p><bdo dir="rtl">This text is reversed.</bdo></p>

    Concept 12: <u> – Unarticulated Annotation

    The <u> element represents text with a non-textual annotation (e.g., a misspelled word). It's often rendered with an underline.

    <p>This is <u>underlined</u> text.</p>

    Note: In HTML5, <u> is not for underlining arbitrary text. Use CSS text-decoration: underline for that.

    Concept 13: <s> – Strikethrough

    The <s> element represents text that is no longer accurate or relevant.

    <p><s>Sold out</s> Available now!</p>

    Note: <s> is for text that is no longer accurate. <del> is for text that has been deleted from the document.

    Concept 14: CSS for Text Styling

    While HTML elements provide semantic meaning, CSS controls the visual presentation:

    strong { font-weight: bold; }
em { font-style: italic; }
mark { background-color: yellow; }
code { font-family: monospace; }

    You can style any element to look like any other, but the semantic meaning remains.

    6. How It Works

    Step-by-Step: Browser Processing of Text Formatting Elements

    1.  The tokenizer encounters an inline formatting element (e.g., `<strong>`).
    │
    ▼
2.  It creates a DOM node for the element.
    │
    ▼
3.  It processes the content inside (text and other inline elements).
    │
    ▼
4.  When the closing tag is encountered, the element is closed.
    │
    ▼
5.  Default browser styles are applied:
    │   ├── <strong> → font-weight: bold
    │   ├── <em> → font-style: italic
    │   ├── <mark> → background-color: yellow
    │   ├── <code> → font-family: monospace
    │   └── etc.
    │
    ▼
6.  CSS can override these default styles.
    │
    ▼
7.  The element is exposed in the accessibility tree with its semantic role.
    │   └── Screen readers announce <strong> as "important" and <em> as "emphasized".
    │
    ▼
8.  Search engines index the emphasized text with additional weight.

    Accessibility Tree

    • <strong> – exposed as "strong" or "important".
    • <em> – exposed as "emphasis".
    • <mark> – exposed as "highlighted" or "marked".
    • <code> – exposed as "code".
    • <abbr> – exposed with the title as the expansion.
    • <del> – exposed as "deleted".
    • <ins> – exposed as "inserted".

    SEO Impact

    Search engines treat <strong> and <em> as signals of importance. Content inside these elements may be given more weight in ranking algorithms. However, overuse dilutes the effect.

    7. Internal Architecture / Under the Hood

    The HTMLElement Interface

    All text formatting elements inherit from HTMLElement and have specific interfaces:

    • <strong> → HTMLElement
    • <em> → HTMLElement
    • <mark> → HTMLElement
    • <code> → HTMLElement
    • <abbr> → HTMLElement
    • <time> → HTMLTimeElement
    • <del> → HTMLModElement
    • <ins> → HTMLModElement

    Default User Agent Styles

    Browsers apply default styles to text formatting elements. For example:

    strong { font-weight: bold; }
em { font-style: italic; }

    The Accessibility API

    Screen readers use the accessibility tree to determine how to announce text. For example:

    • <strong> may be announced with a change in voice or a slight pause.
    • <em> may be announced with a different tone.
    • <abbr> may announce the full expansion from the title attribute.

    11. Best Practices

    1. Use semantic elements over presentational – <strong> instead of <b>, <em> instead of <i>.

    2. Use <strong> for importance, <em> for emphasis – don't confuse the two.

    3. Use <mark> for highlighting relevance – not for arbitrary highlighting.

    4. Use <code> for code, <kbd> for keyboard, <samp> for output – each has a specific meaning.

    5. Provide title on <abbr> – for the full expansion.

    6. Use <time> with datetime – for machine-readable dates.

    7. Use <del> and <ins> for document changes – not just for visual strikethrough/underline.

    8. Don't use <u> for underlining arbitrary text – use CSS text-decoration: underline instead.

    9. Don't use <b> and <i> for emphasis – use <strong> and <em>.

    10. Style with CSS – use CSS to control appearance, not presentational elements.

    11. Keep formatting minimal – too much emphasis dilutes meaning.

    12. Test with screen readers – ensure semantic elements are announced correctly.

    13. Use <small> for side comments – not for making text smaller in general.

    14. Use <sub> and <sup> for typographic purposes – not for visual effects.

    15. Use <bdi> for user-generated content – to prevent bidirectional text issues.

    12. Common Mistakes

    ❌ Mistake: Using <b> Instead of <strong>

    <p><b>Warning!</b> This is important.</p>
    Why it's wrong: <b> has no semantic meaning. Screen readers won't announce it as important.

    ✅ Correct: 

    <p><strong>Warning!</strong> This is important.</p>

    ❌ Mistake: Using <i> Instead of <em>

    <p>You <i>must</i> read this.</p>
    Why it's wrong: <i> is for alternative voice, not emphasis.

    ✅ Correct: 

    <p>You <em>must</em> read this.</p>

    ❌ Mistake: Using <u> for Underlining

    <p>This is <u>underlined</u> text.</p>
    Why it's wrong: <u> is for unarticulated annotations (e.g., misspellings), not arbitrary underlining. Underlined text can be confused with links.

    ✅ Correct: 

    <p>This is <span style="text-decoration: underline;">underlined</span> text.</p>

    ❌ Mistake: Using <s> for Deleted Text

    <p><s>Old price: $99</s> New price: $79</p>
    Why it's wrong: <s> is for text that is no longer accurate, not for document changes. <del> is for deletions.

    ✅ Correct: 

    <p><del>Old price: $99</del> <ins>New price: $79</ins></p>

    ❌ Mistake: Using <mark> for General Highlighting

    <p>This is <mark>important</mark> information.</p>
    Why it's wrong: <mark> is for highlighting text relevant to a specific context (like search results). For importance, use <strong>.

    ✅ Correct: 

    <p>This is <strong>important</strong> information.</p>

    ❌ Mistake: Not Providing title on <abbr>

    <p><abbr>HTML</abbr> is the standard.</p>
    Why it's wrong: Without title, the abbreviation has no expansion. Screen readers can't announce it.

    ✅ Correct: 

    <p><abbr title="HyperText Markup Language">HTML</abbr> is the standard.</p>

    ❌ Mistake: Using <time> Without datetime

    <p>The event is on <time>next Friday</time>.</p>
    Why it's wrong: Without datetime, the time isn't machine-readable.

    ✅ Correct: 

    <p>The event is on <time datetime="2026-09-11">next Friday</time>.</p>

    ❌ Mistake: Using <sub> and <sup> for Visual Effects

    <p>This is <sup>superscript</sup> for no reason.</p>
    Why it's wrong: <sub> and <sup> are for typographic conventions (chemical formulas, mathematical exponents).

    ✅ Correct: Use CSS vertical-align for visual effects.

    13. Performance Considerations

    • Inline elements are lightweight – each adds a small DOM node.
    • Excessive formatting – too many inline elements can slow down rendering and increase DOM size.
    • CSS styling – applying complex styles to text formatting elements can trigger repaints.
    • Accessibility tree – semantic elements add nodes to the accessibility tree, but the impact is minimal.

    14. Security Considerations

    • XSS (Cross-Site Scripting) – when inserting user-generated content into text formatting elements, use textContent instead of innerHTML.
    • innerHTML – if you must use it, sanitize the input.
    • title on <abbr> – can be used for XSS if user-controlled; sanitize.
    • datetime on <time> – should be validated to prevent injection.

    15. Debugging Tips

    • DevTools Elements panel – inspect text formatting elements to see their semantic role.
    • Accessibility Inspector – check how elements are announced by screen readers.
    • Computed styles – see the applied font-weight, font-style, text-decoration.
    • Console – use document.querySelectorAll('strong') to list all strong elements.
    • Validator – check for deprecated elements and attributes.

    <samp> For sample output.
    <var> For variables.
    <time> For dates and times.
    <del> For deleted text in document revisions.
    <ins> For inserted text in document revisions.
    <sub> For subscripts (chemical formulas, footnotes).
    <sup> For superscripts (exponents, ordinal numbers).
    <small> For side comments, legal text.
    <bdi> For user-generated content with unknown direction.
    <bdo> For overriding text direction.

    17. When Not to Use

    • <b> and <i> – when semantic elements fit better.
    • <u> – for arbitrary underlining; use CSS.
    • <s> – for deleted text; use <del>.
    • <mark> – for importance; use <strong>.
    • <sub> and <sup> – for visual effects; use CSS.
    • <small> – for making all text smaller; use CSS.
    • <big> – deprecated; use CSS font-size.

    19. Did You Know?

    • The <b> and <i> elements were originally presentational, but HTML5 redefined them as "stylistic offsets" with no semantic meaning.

    • The <strong> element is not just "bold" – it represents importance. Similarly, <em> is not just "italic" – it represents stress emphasis.

    • The <mark> element was introduced in HTML5 to represent highlighted text, particularly in search results.

    • The <time> element can represent dates, times, durations, and time zones using the datetime attribute.

    • The <abbr> element's title attribute is announced by screen readers when the user hovers or focuses on the abbreviation.

    • The <del> and <ins> elements can carry cite and datetime attributes to reference the source of the change and the time it was made.

    • The <bdi> element is particularly useful for user-generated content (like comments) that may contain text in a different direction.

    • The <small> element is not just for making text smaller – it represents "side comments" like legal disclaimers.

    • The <var> element is for variables in mathematical expressions or programming code, not just italic text.

    • In HTML5, the <u> element is redefined to represent text with a non-textual annotation (like a misspelling), not just underlining.

    20. Summary

    • Text formatting elements in HTML convey semantic meaning and/or visual style to portions of text.
    • Semantic elements (<strong>, <em>, <mark>, <code>, <abbr>, <cite>, <dfn>, <kbd>, <samp>, <var>, <time>, <del>, <ins>, <sub>, <sup>, <small>, <bdi>, <bdo>) should be used over presentational elements.
    • Presentational elements (<b>, <i>, <u>, <s>) are discouraged; use semantic equivalents or CSS.
    • Best practices: use <strong> for importance, <em> for emphasis, <mark> for highlighting, <code> for code, and CSS for visual styling.
    • Common mistakes include using <b> instead of <strong>, <i> instead of <em>, <u> for underlining, and <s> for deleted text.
    • Text formatting is essential for accessibility, SEO, and semantic clarity.
    • Use CSS to control appearance, and HTML to convey meaning.
