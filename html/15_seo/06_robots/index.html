    Robots (SEO)

    1. Overview

    Definition

    Robots — in the SEO context — refers to the mechanisms by which a site owner communicates crawling and indexing instructions to search engine and AI crawlers. There are three primary mechanisms:

    • robots.txt — a plain text file at the root of the domain that controls crawling (which URLs bots may access).
    • robots meta tag — an HTML meta tag that controls indexing and content presentation on a per-page basis.
    • X-Robots-Tag — an HTTP response header that controls indexing and presentation, equivalent to the meta tag but available for non-HTML resources (PDFs, images, video).
    <!-- robots meta tag: do not index this page -->
<meta name="robots" content="noindex, nofollow">

    # robots.txt: block all crawlers from /admin/
User-agent: *
Disallow: /admin/

    # X-Robots-Tag: do not index this PDF
X-Robots-Tag: noindex

    These three mechanisms are complementary, not interchangeable. robots.txt controls whether a crawler is allowed to fetch a URL. The robots meta tag and X-Robots-Tag control whether a fetched URL is indexed and shown. A page blocked in robots.txt can still be indexed if it is linked externally — just without a snippet. A page with noindex can be crawled but will not be indexed.

    Robots.txt, the Robots Exclusion Protocol (REP), is the implementation of the Robots Exclusion Standard, formally standardized as RFC 9309 in 2022. Since 2022, the landscape has shifted dramatically: robots.txt is no longer just about search engines — it is now the primary mechanism for governing AI crawler access. A 2026-ready robots.txt covers four jobs: hide sensitive paths, trim crawl waste, declare the sitemap, and govern AI crawler access (GPTBot, ClaudeBot, Google-Extended).

    Purpose

    Robots directives serve several essential purposes:

    • Crawl control — prevents crawlers from wasting resources on low-value URLs (admin panels, checkout flows, internal search results).
    • Indexing control — prevents specific pages from appearing in search results (staging environments, private pages, duplicate content).
    • Snippet control — controls whether a text snippet appears in search results (nosnippet, max-snippet).
    • Image preview control — controls whether large image previews appear (max-image-preview).
    • AI crawler governance — controls whether AI training crawlers (GPTBot, ClaudeBot, Google-Extended) and retrieval crawlers (OAI-SearchBot, PerplexityBot) can access content.
    • Crawl budget optimization — ensures crawlers spend their time on pages that matter.
    • Security posture — prevents crawling of sensitive paths, though it is not a security tool.
    • Compliance — robots.txt and noindex are the standard mechanisms for excluding pages from search, as required by privacy and data-protection practices.

    Where It Fits

    SEO Stack
│
├── Semantic Structure    ← document outline (headings, landmarks)
├── Heading Hierarchy     ← navigable tree within the structure
├── Metadata              ← title, description, canonical, robots
├── Structured Data       ← entity-level metadata (JSON-LD, Schema.org)
└── Content Quality       ← E-E-A-T, depth, originality

    Robots directives sit inside the crawl and index control layer — they are the first gatekeepers in the SEO pipeline. A crawler must pass robots.txt to access a URL, and it must pass the robots meta tag or X-Robots-Tag to be indexed. Every other SEO signal — content quality, backlinks, structured data — is meaningless if the page is blocked at this layer.

    2. Why It Exists

    The Problem

    A search engine crawler is a finite resource. It cannot crawl every URL on the internet. It has a crawl budget — a finite number of URLs it will fetch from a given site within a given time period. If a site allows crawlers to access every URL — including admin panels, checkout flows, internal search results, session-ID-decorated URLs, and infinite faceted navigation — the crawler wastes its budget on low-value pages and never reaches the pages that matter.

    Similarly, a site may have pages that should not appear in search results: staging environments, private user data, duplicate content, or pages that exist for technical reasons but have no search value. Without a mechanism to exclude these pages, they compete with the pages that should rank.

    Previous Limitations

    Limitation Consequence
    No crawl control Crawlers waste budget on low-value URLs
    No indexing control Staging and private pages indexed accidentally
    No snippet control Full text content scraped into SERPs
    No image preview control Large images shown without context
    No AI crawler governance AI companies train on content without permission
    noindex in robots.txt Unsupported directive; Google deprecated it in 2019

    Why It Was Introduced

    The Robots Exclusion Protocol (REP) — better known as robots.txt — has been around since 1994 and was officially adopted as an IETF standard in 2022 (RFC 9309).

    The robots meta tag was introduced in the late 1990s as a page-level mechanism for indexing control. The X-Robots-Tag HTTP header followed as an equivalent for non-HTML resources.

    In 2019, Google deprecated the unsupported noindex directive in robots.txt — a directive that had been used by some site owners but was never officially supported. Since September 1, 2019, the noindex directive in robots.txt no longer works; site owners must use the robots meta tag or X-Robots-Tag instead.

    The most significant evolution has been the rise of AI crawlers. Since 2022, Google introduced Google-Extended (control over AI training usage), OpenAI introduced GPTBot (training crawler) and OAI-SearchBot (retrieval crawler), Anthropic introduced ClaudeBot, and Perplexity introduced PerplexityBot. In 2026, the most common reason to edit a robots.txt file is to control AI crawler access.

    3. Syntax / Basic Usage

    The robots.txt File

    A robots.txt file is a plain text file placed at the root of the domain. It must be UTF-8 or ASCII encoded. The file uses simple directives:

    User-agent: *
Disallow: /admin/
Disallow: /checkout/
Allow: /

Sitemap: https://example.com/sitemap.xml

    Code Breakdown

    Directive Purpose
    User-agent Specifies the crawler the rules apply to. * means all crawlers
    Disallow Tells the crawler which paths it cannot access
    Allow Tells the crawler which paths it can access (overrides Disallow)
    Sitemap Declares the location of the XML sitemap
    Crawl-delay Non-standard — requests a delay between requests (not supported by Google)

    The robots Meta Tag

    <head>
    <meta name="robots" content="noindex, nofollow">
</head>

    Code Breakdown

    Directive Purpose
    index / noindex Allow or forbid indexing
    follow / nofollow Allow or forbid following links
    noarchive Prevent cached copy
    nosnippet Prevent text snippet in SERPs
    max-snippet: [number] Limit snippet length (-1 for unlimited)
    max-image-preview: [size] Control image preview size (none, standard, large)
    max-video-preview: [number] Limit video preview length
    notranslate Prevent translation in search results
    noimageindex Prevent images on the page from being indexed
    unavailable_after: [date] Remove from index after a specified date

    The X-Robots-Tag HTTP Header

    HTTP/1.1 200 OK
X-Robots-Tag: noindex

    For non-HTML resources (PDFs, images, video):

    X-Robots-Tag: noindex, nofollow

    With a user-agent specification:

    X-Robots-Tag: googlebot: noindex
X-Robots-Tag: otherbot: noindex, nofollow

    The AI Crawler Template (2026)

    # Allow AI search crawlers (retrieval)
User-agent: GPTBot
Allow: /blog/
Disallow: /premium/

User-agent: OAI-SearchBot
Allow: /

User-agent: ClaudeBot
Allow: /blog/
Disallow: /premium/

User-agent: PerplexityBot
Allow: /

# Block training-only crawlers
User-agent: CCBot
Disallow: /

User-agent: Bytespider
Disallow: /

# Block Google AI training (does not affect Search)
User-agent: Google-Extended
Disallow: /

Sitemap: https://example.com/sitemap.xml

    Code Breakdown

    • GPTBot — OpenAI training crawler. Blocking removes content from future model training but does not affect current ChatGPT browsing.
    • OAI-SearchBot — OpenAI retrieval crawler for ChatGPT search citations. Blocking this costs you traffic.
    • ClaudeBot — Anthropic training crawler. Same tradeoff as GPTBot.
    • PerplexityBot — Perplexity retrieval crawler. Perplexity links aggressively, so this crawler has high traffic-per-crawl value.
    • CCBot — Common Crawl. Feeds training at many organizations; blocking removes content from academic and research use.
    • Bytespider — ByteDance. Widely reported as aggressive on crawl rate and inconsistent about honoring robots.txt.
    • Google-Extended — A permission token, not a crawler. It fetches nothing; it controls whether content Googlebot already crawled may be used for Gemini training and grounding. Disallowing it has no effect on Google Search rankings or inclusion in the Search index.

    4. Mental Model

    The "Two Doors" Mental Model

    Crawling and indexing are two separate doors:

    ┌─────────────────────────────────────────────┐
│              THE TWO DOORS                   │
│                                              │
│  Door 1: robots.txt      → Can the crawler  │
│    (Crawl control)         ACCESS the page? │
│                                              │
│  Door 2: robots meta tag → Can the crawler  │
│    (Index control)         INDEX the page?  │
│                                              │
│  A page blocked at Door 1 can still be       │
│  indexed if linked externally — just without │
│  a snippet.                                   │
│                                              │
│  A page with noindex at Door 2 can be        │
│  crawled but will not be indexed.            │
└─────────────────────────────────────────────┘

    The most common mistake in robots management is confusing Disallow with noindex. A Disallowed URL can still appear in search results if it is linked from external sites — just without a snippet. To fully exclude a page from search, use a noindex meta tag or an HTTP 401/403 response.

    The "Training vs. Retrieval" Mental Model (AI Crawlers)

    The single most important distinction in 2026 AI crawler governance:

    ┌─────────────────────────────────────────────┐
│         TRAINING CRAWLERS                    │
│  Purpose: Collect content for training       │
│  future models.                              │
│                                              │
│  Blocking cost: LOW — no traffic today.     │
│  Examples: GPTBot, ClaudeBot, CCBot          │
├─────────────────────────────────────────────┤
│         RETRIEVAL CRAWLERS                   │
│  Purpose: Build search indexes for AI        │
│  answers and citations.                      │
│                                              │
│  Blocking cost: HIGH — you disappear from   │
│  the answers that send traffic.              │
│  Examples: OAI-SearchBot, PerplexityBot     │
├─────────────────────────────────────────────┤
│         USER-INITIATED FETCHERS              │
│  Purpose: Fetch a page on behalf of a        │
│  specific user asking a specific question.   │
│                                              │
│  Blocking cost: HIGHEST — a human is        │
│  waiting on the response.                    │
│  Examples: ChatGPT-User, Claude-User         │
└─────────────────────────────────────────────┘

    Blocking a training crawler such as GPTBot costs you nothing in traffic today. Blocking a retrieval crawler such as OAI-SearchBot removes you from the answers that produce the referrals you can actually measure. Same file, opposite consequences.

    The "Robots.txt Is Not a Security Tool" Mental Model

    robots.txt is a visibility control mechanism, not a security tool. Most major crawlers respect Disallow rules, but some scrapers, spoofed bots, and user-triggered AI tools may ignore them. Do not use robots.txt to hide sensitive paths — that advertises them. Use authentication, authorization, and noindex instead.

    The "Cache Window" Mental Model

    Google caches robots.txt for up to 24 hours. When you change your robots.txt file, Google may not see the change immediately. To refresh the cache faster, use the Request a Recrawl function in the Search Console robots.txt report. John Mueller strongly advises against dynamically modifying robots.txt multiple times per day — it is not effective because Google caches the file for approximately 24 hours.

    5. Core Concepts

    Concept 1: robots.txt — Crawling Control

    robots.txt is a plain text file at the root of the domain that tells crawlers which URLs they may access. It implements the Robots Exclusion Protocol (REP), standardized as RFC 9309 in 2022. It controls crawling, not indexing.

    Concept 2: The robots Meta Tag — Indexing Control

    The robots meta tag is placed in the <head> of an HTML page and controls whether the page is indexed and presented in search results. Google confirmed in March 2026 that it also processes robots meta tags in the <body> section.

    Concept 3: X-Robots-Tag — Indexing Control for Non-HTML Files

    The X-Robots-Tag HTTP response header is the equivalent of the robots meta tag for non-HTML resources — PDFs, images, video. It supports all the same directives as the meta tag.

    Concept 4: The Disallow vs. Noindex Distinction

    Directive Controls Where Effect
    Disallow Crawling robots.txt Prevents fetching; URL can still be indexed if linked externally
    noindex Indexing robots meta tag / X-Robots-Tag Prevents indexing; page can still be crawled

    To fully exclude a page from search, use noindex — not Disallow.

    Concept 5: The noindex in robots.txt Deprecation

    Google officially dropped support for the noindex directive in robots.txt on September 1, 2019. If you have rules like Noindex: in your robots.txt file, they no longer work. Use the robots meta tag or X-Robots-Tag instead.

    Concept 6: The Crawl-Delay Directive

    Crawl-delay is a non-standard extension to robots.txt that requests a delay between crawler requests. It is not part of RFC 9309. Google does not support it. Applebot typically ignores it. Some crawlers (including Anthropic) support it where appropriate. Best practice: avoid relying on crawl-delay; use Search Console's crawl rate settings or CDN rate limiting instead.

    Concept 7: Wildcards in robots.txt

    Google supports two wildcards:

    • * — matches any sequence of characters.
    • $ — marks the end of a URL.
    # Block any URL containing "?sort="
Disallow: /*?sort=

# Block all .xls files
Disallow: /*.xls$

# Block only /page, not /page1 or /page/subpage
Disallow: /page$

    Concept 8: The File Size Limit

    Crawlers must parse at least 500 KiB (512,000 bytes) of a robots.txt file per RFC 9309. Search engines may stop processing robots.txt midway through if the file is larger than 500 KiB, leading to incorrect crawling.

    Concept 9: The 24-Hour Cache

    Google caches robots.txt for up to 24 hours. Changes are not picked up immediately. Use the Request a Recrawl function in Search Console to refresh the cache faster.

    Concept 10: The Google-Extended Token

    Google-Extended is a permission token, not a crawler. It controls whether content that Googlebot already crawled may be used for Gemini training and grounding. Disallowing it has no effect on Google Search rankings or your inclusion in the Search index. This is the single most common misconception in AI crawler governance.

    Concept 11: Training Crawlers

    Training crawlers collect content for training future AI models:

    • GPTBot (OpenAI) — training data.
    • ClaudeBot (Anthropic) — training data.
    • CCBot (Common Crawl) — nonprofit archive feeding training at many organizations.
    • Bytespider (ByteDance) — widely reported as aggressive and inconsistent about honoring robots.txt.

    Blocking training crawlers is cheap — it costs nothing in traffic today.

    Concept 12: Retrieval Crawlers

    Retrieval crawlers build search indexes for AI answers and citations:

    • OAI-SearchBot (OpenAI) — builds the index behind ChatGPT search results.
    • PerplexityBot (Perplexity) — indexes pages for Perplexity answers.

    Blocking retrieval crawlers costs you traffic — you disappear from the answers that send referrals.

    Concept 13: User-Initiated Fetchers

    User-initiated fetchers fire when a person asks an AI assistant something that requires visiting a page right now:

    • ChatGPT-User (OpenAI).
    • Claude-User (Anthropic).

    These are the highest-intent requests — a human is waiting on the response. Blocking them means the model answers from stale memory or says it cannot read the page, in front of a person who was actively evaluating you.

    Concept 14: The "More Restrictive Directive Wins" Rule

    When multiple robots meta tags or directives conflict, the more restrictive directive wins. noindex always overrides index.

    Concept 15: The robots Meta Tag in the Body

    Google updated its documentation in March 2026 to clarify that it does not enforce placement of robots meta tags in the <head> — it will respect robots meta tags in the <body> section as well. This is not a specification change; it is a clarification of existing behavior. The recommended placement remains the <head>.

    Concept 16: The Sitemap Directive

    The Sitemap directive declares the location of an XML sitemap. It helps crawlers discover the sitemap faster. It should be placed at the end of the robots.txt file.

    Concept 17: The User-Agent Matching

    A crawler uses the group matching its token (case-insensitive) and falls back to the group addressed to the asterisk wildcard. If neither matches, nothing is restricted.

    Concept 18: The Allow Directive

    The Allow directive (introduced in 2012) gives site owners granular control. It can override Disallow for specific paths:

    User-agent: *
Disallow: /private/
Allow: /private/public-file.html

    This keeps certain files accessible while protecting others.

    Concept 19: The Request a Recrawl Function

    Search Console's robots.txt report includes a Request a Recrawl function that refreshes Google's cached version of robots.txt faster than the 24-hour automatic cycle.

    Concept 20: The "Not a Security Tool" Caveat

    robots.txt is a visibility control mechanism, not a security tool. It does not protect data. Do not list sensitive paths — that advertises them. Use authentication, authorization, and noindex instead.

    7. Internal Architecture / Under the Hood

    The Robots Exclusion Protocol (RFC 9309)

    RFC 9309 defines the syntax and semantics of robots.txt. Key requirements:

    • The file must be at the root of the domain (/robots.txt).
    • The file must be UTF-8 encoded (ASCII subset).
    • The file size must not exceed 500 KiB.
    • The User-agent, Disallow, and Allow directives are the core directives.
    • Sitemap is an extension (not part of the core REP but widely supported).
    • Crawl-delay is a non-standard extension, not part of RFC 9309.

    • The X-Robots-Tag header is the only way to control indexing of non-HTML files.

    Example 4: Blocking a Specific Image from Google Images

    User-agent: Googlebot-Image
Disallow: /images/dogs.jpg

    Code Breakdown:

    • Blocks a single image from Google Images.
    • Google cannot index images and videos without crawling them.

    Example 5: Blocking All .xls Files

    User-agent: Googlebot
Disallow: /*.xls$

    Code Breakdown:

    • * matches any sequence of characters.
    • $ marks the end of the URL.
    • Blocks all URLs ending in .xls.

    Example 6: Blocking Query Parameter Variants

    User-agent: *
Disallow: /*?sort=
Disallow: /*?sessionid=
Disallow: /*?utm_

    Code Breakdown:

    • Blocks URLs containing ?sort=, ?sessionid=, or ?utm_.
    • Prevents parameter-decorated duplicates from wasting crawl budget.

    11. Best Practices

    1. Use noindex — not Disallow — to exclude a page from search. Why: Disallow prevents crawling but the URL can still be indexed if linked externally; noindex prevents indexing.
    2. Place the robots meta tag in the <head>. Why: this is the recommended and most reliable placement, even though Google also processes it in the <body>.
    3. Use X-Robots-Tag for non-HTML files. Why: PDFs, images, and video cannot contain <meta> tags.
    4. Keep robots.txt simple and focused. Why: it's generally best to keep things simple.
    5. Do not use robots.txt to hide sensitive paths. Why: robots.txt is public; listing sensitive paths advertises them.
    6. Avoid using crawl-delay for major search engines. Why: it's not supported consistently across major crawlers and is not part of RFC 9309.
    7. Keep robots.txt under 500 KiB. Why: crawlers may stop processing larger files.
    8. Remember Google caches robots.txt for 24 hours. Why: changes are not immediate; use Request a Recrawl for priority changes.
    9. Allow CSS and JavaScript files to be crawled. Why: blocking them hurts rendering and prevents Google from understanding the page.
    10. Use Allow to override Disallow for specific paths. Why: gives granular control without blocking entire directories.
    11. Declare your sitemap in robots.txt. Why: helps crawlers discover it faster.
    12. Do not block OAI-SearchBot or PerplexityBot if you want AI search citations. Why: these are retrieval crawlers; blocking them costs you traffic.
    13. Blocking training crawlers (GPTBot, ClaudeBot, CCBot) is cheap. Why: it costs nothing in traffic today.
    14. Remember Google-Extended does not affect Search. Why: it controls Gemini training only; disallowing it has no effect on Google Search rankings or index inclusion.
    15. Do not rely on robots.txt as a security tool. Why: only cooperative bots follow it; scrapers and spoofed bots may ignore it.
    16. Validate robots.txt with Search Console. Why: catches syntax errors and unintended blocks.
    17. Monitor index coverage in Search Console. Why: ensures noindex pages are excluded and indexable pages are included.
    18. Use the URL Inspection tool to verify page-level directives. Why: shows Google-selected canonical, robots directives, and indexing status.
    19. Keep robots.txt directives case-consistent. Why: URLs in directives are case-sensitive.
    20. Document your AI crawler policy. Why: consistency across a team prevents accidental blocking of retrieval crawlers.
    21. Use the Sitemap directive at the end of robots.txt. Why: keeps the file organized and ensures crawlers find it.
    22. Test robots.txt changes in a staging environment. Why: one incorrect rule can block major sections of your site from search engines and AI bots.
    23. Audit robots.txt quarterly. Why: crawler landscape changes; AI crawlers emerge; business rules change.
    24. Do not block Googlebot-Image if you want images indexed. Why: Google cannot index images without crawling them.
    25. Use max-image-preview:large for rich thumbnails. Why: enables large image previews in SERPs.

    12. Common Mistakes

    ❌ Mistake: Using Disallow to Exclude a Page from Search

    User-agent: *
Disallow: /private-page/

    Why it's wrong: A Disallowed URL can still be indexed if linked externally — just without a snippet. The page is still in search results.

    ✅ Correct:

    <meta name="robots" content="noindex">

    ❌ Mistake: Using noindex in robots.txt

    User-agent: *
Noindex: /page/

    Why it's wrong: Google deprecated the noindex directive in robots.txt on September 1, 2019. It no longer works.

    ✅ Correct:

    <meta name="robots" content="noindex">

    ❌ Mistake: Blocking CSS and JavaScript

    User-agent: *
Disallow: /css/
Disallow: /js/

    Why it's wrong: Blocking CSS and JavaScript hurts rendering and prevents Google from understanding the page.

    ✅ Correct: Allow CSS and JavaScript to be crawled.

    ❌ Mistake: Blocking AI Retrieval Crawlers

    User-agent: OAI-SearchBot
Disallow: /

    Why it's wrong: OAI-SearchBot powers ChatGPT search citations. Blocking it removes you from AI answers that send traffic.

    ✅ Correct: Allow OAI-SearchBot if you want AI search visibility.

    ❌ Mistake: Thinking Google-Extended Affects Search

    User-agent: Google-Extended
Disallow: /

    Why it's wrong: Google-Extended is a permission token for Gemini training. It has no effect on Google Search rankings or index inclusion.

    ✅ Correct: Understand the difference; use Google-Extended for AI training control only.

    ❌ Mistake: Using crawl-delay for Google

    User-agent: Googlebot
Crawl-delay: 10

    Why it's wrong: Google does not support crawl-delay.

    ✅ Correct: Use Search Console's crawl rate settings or CDN rate limiting.

    ❌ Mistake: Robots.txt File Over 500 KiB

    # 600 KiB robots.txt file

    Why it's wrong: Crawlers may stop processing robots.txt midway through if the file is larger than 500 KiB.

    ✅ Correct: Keep robots.txt under 500 KiB.

    ❌ Mistake: Blocking the Entire Site on Production

    User-agent: *
Disallow: /

    Why it's wrong: Blocks all crawlers from the entire site — a catastrophic SEO failure if deployed to production.

    ✅ Correct: Only use Disallow: / on staging environments.

    ❌ Mistake: Listing Sensitive Paths in robots.txt

    User-agent: *
Disallow: /secret-admin-panel/

    Why it's wrong: robots.txt is public; listing sensitive paths advertises them.

    ✅ Correct: Use authentication and authorization to protect sensitive paths.

    ❌ Mistake: Conflicting Directives

    <meta name="robots" content="noindex">
<meta name="robots" content="index">

    Why it's wrong: The more restrictive directive wins — noindex overrides index. But conflicting directives cause confusion.

    ✅ Correct: Use one clear directive per page.

    13. Performance Considerations

    • robots.txt is fetched once per crawl session — negligible overhead.
    • robots.txt is cached for 24 hours — no repeated fetches.
    • The robots meta tag adds minimal bytes — a single line of HTML.
    • X-Robots-Tag adds a single HTTP header — negligible overhead.
    • Blocking CSS/JS hurts rendering performance — allow them to be crawled.
    • Blocking crawl-heavy paths improves crawl efficiency — saves crawl budget.

    Performance Tips

    1. Keep robots.txt small and focused.
    2. Block low-value paths to save crawl budget.
    3. Allow CSS and JavaScript for proper rendering.
    4. Use X-Robots-Tag for non-HTML files — no page size increase.

    14. Security Considerations

    robots.txt Is Not a Security Tool

    robots.txt is a visibility control mechanism, not a security tool. Most major crawlers respect Disallow rules, but some scrapers, spoofed bots, and user-triggered AI tools may ignore them. Do not use robots.txt to hide sensitive paths — that advertises them. Use authentication, authorization, and noindex instead.

    noindex Is Not a Security Tool

    noindex prevents pages from appearing in search results but does not protect data. A page with noindex is still accessible to anyone who knows the URL.

    AI Crawler Governance Is a Policy Decision

    Blocking AI training crawlers is a policy decision. Blocking retrieval crawlers costs you traffic. Understand the tradeoff before configuring your robots.txt.

    Do Not Block Security-Related Crawlers

    Some crawlers are used for security scanning (e.g., Google Safe Browsing). Blocking them may prevent security checks.

    Robots.txt and Data Leakage

    If your robots.txt file lists sensitive paths, it leaks information about your site structure. Use it as a crawl control mechanism, not a security mechanism.

    • curl -I https://example.com/page — check response headers for X-Robots-Tag.
    • view-source: — confirm the robots meta tag is in the static HTML.
    • Screaming Frog — crawls your site and reports robots.txt and meta robots issues.
    • Sitebulb — visualizes robots.txt and indexing directives across the site.
    • Test with the Rich Results Test — validates that the page is indexable.
    • Use the Request a Recrawl function — refreshes Google's cached robots.txt faster.

    16. When to Use

    • robots.txt — for crawl control: block low-value paths, declare sitemaps, govern AI crawlers.
    • robots meta tag — for index control: exclude pages from search, control snippets and previews.
    • X-Robots-Tag — for non-HTML files: PDFs, images, video.
    • noindex — for pages that should not appear in search results.
    • Disallow — for paths that should not be crawled.
    • Sitemap — to declare the sitemap location.
    • AI crawler directives — to govern AI training and retrieval access.

    17. When Not to Use

    • Do not use robots.txt to hide sensitive paths. Use authentication.
    • Do not use Disallow to exclude a page from search. Use noindex.
    • Do not use noindex in robots.txt. It is deprecated since 2019.
    • Do not block CSS or JavaScript. It hurts rendering.
    • Do not use crawl-delay for Google. It is not supported.
    • Do not block OAI-SearchBot or PerplexityBot if you want AI citations.
    • Do not use Disallow: / on production. Use it only on staging.
    • Do not rely on robots.txt for security. It is a visibility control mechanism.

    • Google deprecated the noindex directive in robots.txt on September 1, 2019.
    • Google caches robots.txt for up to 24 hours.
    • The crawl-delay directive is not part of RFC 9309 and is not supported by Google.
    • Crawlers must parse at least 500 KiB of a robots.txt file.
    • Google confirmed in March 2026 that it processes robots meta tags in the <body>.
    • Google-Extended is a permission token, not a crawler — it controls Gemini training but has no effect on Google Search.
    • Blocking a training crawler costs nothing in traffic today — blocking a retrieval crawler costs you citations and referrals.
    • OAI-SearchBot builds the index behind ChatGPT search results — blocking it removes you from AI citations.
    • ChatGPT-User is a user-initiated fetcher — a human is waiting on the response.
    • PerplexityBot has unusually high traffic-per-crawl value because Perplexity links aggressively.

    • Bytespider is widely reported as aggressive and inconsistent about honoring robots.txt.

    • The Allow directive was introduced in 2012 to give site owners granular control.

    20. Summary

    • Robots directives control crawling and indexing through three mechanisms: robots.txt, the robots meta tag, and the X-Robots-Tag.
    • robots.txt controls crawling — which URLs bots may access. It is a plain text file at the domain root, standardized as RFC 9309.
    • The robots meta tag controls indexing — whether a page is indexed and shown in search results. Place it in the <head>; Google also processes it in the <body>.
    • X-Robots-Tag controls indexing for non-HTML files — PDFs, images, video.
    • The most common mistake is confusing Disallow with noindex. A Disallowed URL can still be indexed if linked externally; a noindex page can be crawled but will not be indexed.
    • Google deprecated noindex in robots.txt on September 1, 2019. Use the meta tag or X-Robots-Tag instead.
    • crawl-delay is not part of RFC 9309 and is not supported by Google.
    • Keep robots.txt under 500 KiB. Crawlers may stop processing larger files.
    • Google caches robots.txt for up to 24 hours. Use Request a Recrawl for priority changes.
    • In 2026, robots.txt is the primary mechanism for AI crawler governance.
    • Training crawlers (GPTBot, ClaudeBot, CCBot) collect content for model training — blocking them is cheap.
    • Retrieval crawlers (OAI-SearchBot, PerplexityBot) build search indexes for AI answers — blocking them costs you traffic.
    • User-initiated fetchers (ChatGPT-User, Claude-User) fire when a human is waiting on a response — blocking them is the highest cost.
    • Google-Extended is a permission token, not a crawler — disallowing it has no effect on Google Search.
    • robots.txt is not a security tool. Use authentication and authorization to protect sensitive data.
    • Validate robots.txt with Search Console, monitor index coverage, and audit quarterly.
    • A 2026-ready robots.txt covers four jobs: hide sensitive paths, trim crawl waste, declare the sitemap, and govern AI crawler access.
